第8回 地理空間データの活用1（座標変換、バッファ、空間結合）¶

皆さん、こんにちは！プログラミング応用A（コンピューティング応用G）、第8回の講義です。担当の教員です。

前回の第7回では、GISの基本概念や、丸い地球を平らにする「座標系」の不思議、そして「GeoPandas」を使った最初の地図描画を学びました。 今回はその知識をさらに一歩進め、ビジネスや社会課題解決の現場で最もよく使う**「空間データの実践的な加工・操作技術」**を学びます！

「店舗から徒歩10分（800m圏内）に住む人口を集計したい」「このGPS位置情報のピンは、東京都の何区にあるのかを自動判定したい」といった課題は、今日の講義をマスターすれば、Pythonでわずか数行で自動化できるようになります。

「バッファ」「空間結合（Spatial Join）」など、一見難しそうな処理が登場しますが、大丈夫です！ 「店舗の縄張り（テリトリー）」や「ピンを区というバケツに投げ入れるゲーム」に例えながら、アスキーアートも豊富に使って解説します。 データ分析の仕事で「即戦力」となるGIS応用スキルを身につけていきましょう！

🎯 到達目標¶

この100分の授業が終わるころには、以下のことができるようになります。

  1. .to_crs() を使って、データフレームの座標参照系（経緯度 ➡ 平面直角座標系など）を正しく変換できる。

  2. バッファ（.buffer()） を用いて、特定の地点から「半径〇メートル」の商圏・影響エリアを自動生成できる。

  3. 位置情報を持った2つの表を重ね合わせる**「空間結合（Spatial Join: .sjoin()）」**の仕組みを理解し、実装できる。

  4. **代表点・重心（.centroid）や、2点間の距離計算（.distance()）**を使って、地理空間的な距離関係を算出できる。

8.1 座標参照系（CRS）の変換（なぜ .to_crs() が必要なのか？） (約20分)¶

経緯度（度）のままで距離を計るとどうなる？¶

前回、「スマホのGPSデータ（WGS84）は角度（緯度経度）で場所を記録している」とお話ししました。 もし、この「角度」のデータのままで、「店舗の半径500m圏内を計算して！」とプログラムに指示を出すとどうなるでしょうか？

プログラムは「半径500度」と勘違いして、地球を何周もする巨大な円を描いてしまいます。あるいは、「緯度1度って何メートルだっけ？」と迷い、日本と赤道直下で全く長さが異なる不正確な計算をしてしまいます。

【丸い地球にメジャーはあてられない】

  角度データ (WGS84) [度]              平面直角座標系 (JGD2011) [メートル]
        ╭━━━━━╮                              ┌───────────────┐
       ┃  (度) ┃  ── to_crs() で変換 ──▶     │  (メートル)   │
        ╰━━━━━╯                              └───────────────┘
  「半径0.01度って何m？」                「半径1000mを定規でピシッと計測！」

.to_crs() という強力な魔法¶

距離（メートル）や面積（平方メートル）を正確に計算したい時は、必ず .to_crs() メソッドを使って、データを**「メートル単位の平面座標系（投影座標系）」**に変換します。

  • 世界共通（メートル単位）：EPSG:3857（Webメルカトル。Google Maps等で使用）

  • 日本国内（メートル単位・超高精度）：平面直角座標系（JGD2011）。東京や武蔵野市周辺なら EPSG:6677（第9系） を使います。

8.2 バッファ（buffer）と重心（centroid） (約20分)¶

1. バッファ（buffer）処理：商圏やテリトリーの作成¶

バッファとは、**「ある点・線・面から、指定された距離（メートルなど）の範囲をぐるりと囲む面（ポリゴン）を作る処理」**です。

ビジネスでの「新規出店したカフェから、半径500m（徒歩圏内）のエリア」や、防災での「氾濫の危険がある河川の周囲100mの避難警戒エリア」は、すべてこのバッファ処理で作られます。

【バッファのイメージ図】

           [ 店舗（点：Point）]
                    │
                    ▼  buffer(500) ＝ 半径500メートルの円を作る！
             ╭  ━━━━  ╮
          /             \
         |       ●       | (この円の中にいる顧客や競合店を集計できる！)
          \             /
             ╰  ━━━━  ╯

2. 重心・代表点（centroid）：エリアの中心¶

ある市区町村や浸水エリアの「真ん中の点」を代表として計算したい時は、.centroid というプロパティを使います。 「店舗エリア（ポリゴン）の中心に、看板ピン（Point）を1本立てる」といった用途でよく使います。

8.3 空間結合（Spatial Join：緯度経度を行政区画に投げ入れる） (約20分)¶

通常のPandasでは、2つの表をくっつける時に pd.merge() を使い、「顧客ID」などの「共通の文字・数値（キー）」を仲立ちにして結合しましたね。 しかし、地図データには共通のキー（文字）がありません。あるのは「位置（座標）」だけです。

「この緯度経度のピンは、何区のポリゴンの内側にあるか？」のように、共通の文字キーがなくても、位置の重なり（包含関係）をキーにして自動で表同士をくっつける処理を**空間結合（Spatial Join：.sjoin()）**と呼びます。

【空間結合のイメージ（バケツ投げゲーム）】

  [ 表 A : 顧客の位置ピン (Point) ]        [ 表 B : 東京都の行政区画 (Polygon) ]
    ・顧客ID: 01                           ・区名: 杉並区 (ポリゴン)
    ・座標: (139.62, 35.70)                 ・区名: 武蔵野市 (ポリゴン)
              │                                      │
              ╰───────────── 空間結合 (sjoin) ────────╯
                                    │
                                    ▼ (ピンがどのエリアの内側にあるかを判定！)
  [ 結合された新しい表 ]
    ・顧客ID: 01, 座標: (139.62, 35.70), 判定された区名: 「杉並区」！

GeoPandasでは、gpd.sjoin(表A, 表B, how="inner", predicate="within") という1行のコードでこれが実現します。 predicate="within" は「内側に入っているものを結合してね」という指示です。

📚 第8回のまとめ¶

お疲れ様でした！GISの実務で最も強力な「データの座標変換・バッファ・空間結合」をマスターしましたね。

✨ 今日の重要ポイントまとめ¶

  • .to_crs(): 正確な距離や面積を計るために、角度（度）の座標系からメートル単位の平面座標系（EPSG:6677など）に変換する必須処理。

  • .buffer(): 特定の点から「半径〇メートル」のテリトリー（面データ）を自動生成する。

  • .distance(): 2つの位置データ間のメートル単位の直線距離を一瞬で計算する。

  • .sjoin() (空間結合): 共通の文字キーがなくても、「ピンがポリゴンの内側にある（within）」という空間的な重なりだけで表をくっつける最強テクニック。

❓ よくある質問と回答 (FAQ)¶

  • Q. gpd.sjoin() を実行したら UserWarning: CRS mismatch between the CRS of left gdf and right gdf. という警告（またはエラー）が出ました。

    • A. これもGIS実務で非常に多いトラブルです！ 「結合したい左側の表（WGS84：経緯度）」と「右側の表（平面直角座標系：メートル）」のように、2つのデータの座標系（CRS）が一致していないと空間結合は計算できません（リンゴとオレンジを比べるようなものです）。 空間結合を行う前には、必ず両方のデータの .crs を確認し、もし異なっていれば、どちらか一方を .to_crs() で変換して、完全に座標系を揃えてから sjoin を実行してくださいね。
