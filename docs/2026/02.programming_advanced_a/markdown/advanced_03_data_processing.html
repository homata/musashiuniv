皆さん、こんにちは！プログラミング応用A（コンピューティング応用G）、第3回の講義です。担当の教員です。 前回の第2回では「オープンデータ」をテーマに、Web上のデータを直接Pandasに読み込み、文字コードのエラー（Shift-JIS問題）を解決しながら、データ分析の最重要ステップである「データクレンジング」を学びました。皆さんの演習への取り組みが素晴らしく、すでにデータ分析エンジニアとしての基礎が固まりつつあります。

今日のテーマは、データ分析をさらに一段ステップアップさせる**「データの種類（尺度）と高度なデータ加工（Data Processing）」**です。

現実のデータは、1つのファイルに収まっていることはまずありません。「今月の売上ファイル」「店舗の場所ファイル」「スタッフのシフトファイル」のようにバラバラに存在します。これらをパズルのように連結（ガッチャンコ）したり、特定のルール（例えば『日付データから曜日を取り出す』）に沿って加工したりするスキルを身につけます。

「尺度」「空間結合」「ラムダ式のapply」「時系列オブジェクト」など、少し専門的な言葉も出てきますが、大丈夫です！ 「カフェのメニュー表の合体」や「曜日ごとの売上の波」など、身近な例に例えて丁寧に図解します。 それでは、じっくりとデータ加工のプロフェッショナルなスキルを身につけていきましょう！

3.1 データの「尺度（データ型）」を理解しよう (約15分)¶

データ分析を行う前に、「そのデータがどういう性質のものか」を見極める必要があります。これを統計学では**「4つの尺度」**と呼びます。

【4つの尺度のビジュアル図解】

  [ 📊 4つの尺度 ]
   ├── ① 名義尺度 (分類のみ)  ──▶ 「コーヒー」「紅茶」（足し引きできない）
   ├── ② 順序尺度 (順番に意味) ──▶ 「大・中・小」「顧客満足度：1〜5」（差は不均等）
   ├── ③ 間隔尺度 (ゼロに意味なし) ──▶ 「気温（℃）」（0度は『温度がない』ではない）
   └── ④ 比例尺度 (絶対的なゼロ) ──▶ 「価格（円）」「来客数」（0は『存在しない』。2倍が計算できる）

  1. 名義尺度（Nominal Scale）：単なる「名前」や「分類」です。計算はできません。

    • 例：商品カテゴリ（ドリンク、フード）、性別、店舗名。

  2. 順序尺度（Ordinal Scale）：順番（大小）には意味がありますが、「差」が均等ではありません。

    • 例：顧客満足度（5:大満足、4:満足...）、コーヒーのサイズ（S, M, L）。「SとMの差」と「MとLの差」は同じとは限りません。

  3. 間隔尺度（Interval Scale）：数値の「差」には意味がありますが、「比（〇倍）」には意味がありません。「0（ゼロ）」が絶対的な無を意味しないデータです。

    • 例：気温（℃）。「30℃は15℃の2倍暑い」とは言えません（0℃は熱が完全に無い絶対零度ではないため）。

  4. 比例尺度（Ratio Scale）：数値の「差」にも「比」にも意味があります。「0」は「何もない」ことを示します。データ分析で最も扱いやすい形です。

    • 例：価格、売上数、客数。「0円」はタダ（お金がない）ですし、「1000円は500円の2倍」と言えます。

Pandasでデータを加工するときは、この尺度が「文字列（object）」、「カテゴリ（category）」、「数値（int/float）」のどのデータ型に変換すべきかを意識します。

3.2 データの連結（concat）と結合（merge） (約20分)¶

実務のデータ分析では、複数のバラバラの表を1つに統合する作業が必ず発生します。

① 表を縦にガッチャンコ！「連結（pd.concat）」¶

例えば、「月曜日の売上表」と「火曜日の売上表」のように、**「同じ項目の表を、縦に単純に繋げたい」**ときは、pd.concat() を使います。

【連結（concat）のイメージ】

  [ 月曜の表 ]         [ 火曜の表 ]
  │ A店 │ 10万円 │     │ A店 │ 12万円 │
  │ B店 │  8万円 │     │ B店 │  9万円 │
          │                   │
          ╰─────── concat ────╯
                  │
                  ▼ (縦に繋がる！)
           │ A店 │ 10万円 │
           │ B店 │  8万円 │
           │ A店 │ 12万円 │
           │ B店 │  9万円 │


<!-- コードセル -->
import pandas as pd

# 月曜日の売上
df_monday = pd.DataFrame([
    ["A店", 100000],
    ["B店", 80000]
], columns=["店舗名", "売上"])

# 火曜日の売上
df_tuesday = pd.DataFrame([
    ["A店", 120000],
    ["B店", 90000]
], columns=["店舗名", "売上"])

# 縦に連結（リストに入れて渡します。ignore_index=True をつけると、インデックス番号が0,1,2,3と綺麗に振り直されます）
df_all = pd.concat([df_monday, df_tuesday], ignore_index=True)

print("▼ 縦に連結した売上データ")
display(df_all)

② 共通のキーで合体！「結合（pd.merge）」¶

例えば、「売上データ」に「各店舗の住所や店長名」が載っている「店舗マスタ」を合体させたいとき、共通するキーワード（この場合は「店舗名」）を軸にして横に合体させるのが pd.merge() です。これはエクセルでいう VLOOKUP関数 の動きをします！

【結合（merge）のイメージ】

  [ 売上表 ]                       [ 店舗マスタ ]
  │ 店舗名 │ 売上   │               │ 店舗名 │ エリア  │ 店長名 │
  │ A店    │ 10万円 │               │ A店    │ 杉並区  │ 山田   │
  │ B店    │  8万円 │               │ B店    │ 武蔵野市│ 佐藤   │
       │                               │
       ╰──────────── merge (on="店舗名") ╯
                       │
                       ▼ (横に拡張される！)
  │ 店舗名 │ 売上   │ エリア  │ 店長名 │
  │ A店    │ 10万円 │ 杉並区  │ 山田   │
  │ B店    │  8万円 │ 武蔵野市│ 佐藤   │


<!-- コードセル -->
# 店舗別の売上データ
df_sales = pd.DataFrame([
    ["A店", 100000],
    ["B店", 80000],
    ["C店", 150000]
], columns=["店舗名", "売上"])

# 店舗マスタ（住所と店長情報）
df_master = pd.DataFrame([
    ["A店", "東京都杉並区", "山田店長"],
    ["B店", "東京都武蔵野市", "佐藤店長"],
    ["C店", "東京都練馬区", "鈴木店長"]
], columns=["店舗名", "所在地", "責任者"])

# 「店舗名」を基準キーにして、横にスマートに合体！
df_merged = pd.merge(df_sales, df_master, on="店舗名")

print("▼ 横に結合した店舗詳細売上データ")
display(df_merged)

3.3 apply() とラムダ式（lambda）による高度なカスタム変換 (約15分)¶

エクセルで「10万円以上の売上には『目標達成』、未満には『未達成』と隣の列に書く」という処理をする場合、IF関数（=IF(B2>=100000, "目標達成", "未達成")）を使いますよね。

Pandasでこのような**「全データ（各行・各列）に対して、自分だけのオリジナルルール（関数）を適用したい」ときに使う最強のコンビが、apply() メソッド** と lambda（ラムダ式） です。

  • apply(関数)：列のデータすべてに、指定した関数を「適用（apply）」する。

  • lambda（ラムダ式）：第11回で学んだ「名前のない1行限りの使い捨て関数」。

【apply と lambda のイメージ】

  [ データの列 ] ──▶ [ フィルター (apply + lambda) ] ──▶ [ 新しい列 ]
    150,000 円           「x >= 100000 なら 達成！」       目標達成
     80,000 円           「そうでなければ 未達成！」       未達成


<!-- コードセル -->
# 売上データ
df_eval = pd.DataFrame([
    ["東京本店", 120000],
    ["大阪支店", 95000],
    ["名古屋店", 80000],
    ["福岡支店", 150000]
], columns=["店舗名", "売上"])

# applyとlambdaを使って、「売上(x)が 100000 以上なら『達成』、未満なら『未達成』」という評価列を1行で作ります！
df_eval["売上評価"] = df_eval["売上"].apply(lambda x: "目標達成" if x >= 100000 else "未達成")

print("▼ apply()とラムダ式を使って評価を追加したデータフレーム")
display(df_eval)

3.4 時系列データ（datetime型）の扱いと曜日抽出 (約15分)¶

オープンデータや店舗のレジデータには、必ず「日付（2026-08-27）」が含まれています。 しかし、読み込んだ直後はただの「文字列（テキストデータ）」として扱われているため、Pythonは「これが木曜日なのか、何月なのか、何時なのか」を理解できません。

そこで、文字列を 時系列データ（datetimeオブジェクト） に変換します。

  • 変換：pd.to_datetime(df["日付列"])

  • 曜日の取り出し：df["日付列"].dt.day_name() (英語表記) または .dt.weekday (0=月曜〜6=日曜の数値)


<!-- コードセル -->
# 日付が「文字列」の売上データ
df_daily_sales = pd.DataFrame([
    ["2026-08-01", 120000],
    ["2026-08-02", 150000],
    ["2026-08-03", 85000],
    ["2026-08-04", 90000]
], columns=["売上日", "売上金額"])

print("--- 変換前のデータ型 ---")
print(df_daily_sales.dtypes) # 「売上日」が「object（文字列）」になっている

# ① 日付文字列を「datetime型（時系列オブジェクト）」に変換！
df_daily_sales["売上日"] = pd.to_datetime(df_daily_sales["売上日"])

print("\n--- 変換後のデータ型 ---")
print(df_daily_sales.dtypes) # 「datetime64[ns]（時系列型）」に変わりました！

# ② datetime型になると、日付から「曜日」を一瞬で抽出できます（.dtプロパティを使います）
# 英語の曜日名を取得
df_daily_sales["曜日（英語）"] = df_daily_sales["売上日"].dt.day_name()

# 日本語の曜日に変換する簡単な辞書
weekday_jp = {0: "月", 1: "火", 2: "水", 3: "木", 4: "金", 5: "土", 6: "日"}
# .dt.weekday は 0から6の数字を返すので、mapで日本語に置き換えます
df_daily_sales["曜日"] = df_daily_sales["売上日"].dt.weekday.map(weekday_jp)

print("\n▼ 曜日情報を追加した売上データ")
display(df_daily_sales)

✨ 今日の重要ポイントまとめ¶

  • データの4つの尺度: 名義（分類）、順序（大小）、間隔（差）、比例（ゼロに意味あり）。データがどの尺度に属しているかで、適切な加工・計算のアプローチが変わる。

  • 連結 (pd.concat): 同じ列名を持つ複数の表を、縦に単純に合体する。

  • 結合 (pd.merge): エクセルのVLOOKUPのように、共通の「キー列」を使って、2つの異なる表を横に合体・拡張する。

  • apply() と ラムダ式: axis=1 を指定することで、各行に対して「もし店内飲食なら10%、テイクアウトなら8%」といった複雑なオリジナル計算を一瞬で適用できる。

  • 時系列データ(datetime): 文字列を時系列データに変換することで、曜日(.dt.weekday)や月（.dt.month）などを自在に取り出せるようになる。

❓ よくある質問と回答 (FAQ)¶

  • Q. pd.merge() で結合したら、データ件数が減ってしまいました。なぜですか？

    • A. とても良い疑問です！ pd.merge の標準設定（デフォルト）は 「インナー・ジョイン（Inner Join：内部結合）」 になっています。これは、「両方の表に共通して存在するキー」だけを合体させるため、どちらか一方にしか存在しないデータは切り捨てられます。もし「左側の売上データを1件も消さずに結合したい」という場合は、pd.merge(..., how="left") のように how="left"（左外部結合）を指定してください。

  • Q. axis=1 を書き忘れるとどうなりますか？

    • A. これも初心者が100%と言っていいほど直面するエラーです！ axis=1（列方向・横向き）を忘れると、Pandasは縦（行方向）に処理をしようとして「そんな列名は見つからない」という KeyError や TypeError を吐き出します。「行（横）をまたいだ計算を apply でやるときは必ず最後にカンマ axis=1！」とお守りのように覚えておきましょう。

# 来店したお客様の会員IDと注文データ
df_shop_orders = pd.DataFrame([
    ["ID01", "コーヒー"],
    ["ID99", "紅茶"], # ID99 は、会員マスタに登録されていない！？
    ["ID02", "ケーキ"]
], columns=["会員ID", "注文"])

# 会員マスタ
df_member_master = pd.DataFrame([
    ["ID01", "山田さん"],
    ["ID02", "佐藤さん"]
], columns=["会員ID", "名前"])

df_left_merged = pd.merge(df_shop_orders, df_member_master, on="会員ID", how="left")

# 名前が NaN（欠損値）になっている行だけを抽出する（マスタ未登録者の特定！）
unregistered_customers = df_left_merged[df_left_merged["名前"].isna()]
print("\n▼ 会員マスタに登録がない注文データ（エラー・不正の早期発見！）")
