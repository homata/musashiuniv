9.1 動的地図の革命：その仕組みとライブラリ比較 (約40分)¶

9.1.1 地図に「命（インタラクティブ）」を吹き込むとは？¶

これまで私たちが描画していたのは、MatplotlibやSeabornによる地図でした。これは「画像ファイル（PNGやJPEG）」です。 論文に印刷して載せるのには最適ですが、Webサイトで一般のユーザーが操作するには不向きです。

現代のWeb地図に求められるのは、以下のような**「対話（インタラクティブ）性」**です。

  1. 直感的なスクロールとズーム（見たいところへ飛び、拡大する）。

  2. 動的なトッピング（レイヤー）のオン・オフ（ハザードマップを重ねたり消したりする）。

  3. クリック時のイベント（ピンをクリックすると、そこに登録された詳細情報が表示される）。

実は、このような動的地図は、裏側では 「JavaScript（ジャバスクリプト）」 という、Webブラウザを動かすための全く別のプログラミング言語で書かれています。代表的なオープンソースライブラリが 「Leaflet.js（リーフレット・ジェイエス）」 です。

通常、Webで動く地図を開発するには、HTMLを書き、CSSでデザインを整え、何十行ものJavaScriptで地図の初期化やピンの設置を書く必要があり、文系の学生さんにとっては極めて高いハードルでした。

9.2.1 経緯度指定の「鉄則」と、全人類が一度はやる大バグの復習¶

前回の授業でも学びましたが、大事なことなのでもう一度おさらいします。 日常の会話では「緯度（Latitude）・経度（Longitude）」という順番で口にしますが、プログラミングやGIS（幾何空間）の世界のグラフを思い出してください。

  • 横軸（X軸） ＝ 経度（東経140度など、左右の動き）

  • 縦軸（Y軸） ＝ 緯度（北緯35度など、上下の動き）

座標を (X, Y) で表す基本ルールがあるため、GeoPandasやShapelyのPointオブジェクトでは Point(経度, 緯度) の順（経度が先、緯度が後）で指定するのが鉄則でした。

しかし、folium の location 引数では、歴史的な背景から [緯度, 経度] の順（緯度が先、経度が後）でリストを渡すお約束になっています！

  【 幾何・GISデータ（GeoPandas等） 】
   geometry = Point( 経度 , 緯度 )  <-- 横(X), 縦(Y) の数学の基本順

  【 Web可視化（folium / Google Maps API 等） 】
   location = [ 緯度 , 経度 ]      <-- 日常生活の「緯度経度」の口頭順

  • デバッグのアドバイス：「地図を動かしたら画面が真っ白になった、あるいはピンが南極の近くや宇宙空間に消えてしまった！」という時の原因の9割は、この**「経度と緯度の指定順が逆になっていること」**です。エラーは出ないのにピンが表示されないため、最も注意して確認すべきポイントです。

9.2.2 ループ処理（iterrows()）による全自動マッピング¶

手動で folium.Marker を何個も書くのはスマートではありません。 私たちの手元には、Pandasのデータフレームという強力な表データがあります。 これまでに学んだ、データフレームを1行ずつ上から順番に読み出す for idx, row in df.iterrows(): のループ処理と合体させることで、1万件のデータであっても一瞬で全自動マッピングできます。

# 1. Pandasデータフレームで3つの店舗データを用意（実務を想定したダミーデータ）
import pandas as pd
import folium

shop_df = pd.DataFrame({
    "店舗名": ["江古田コーヒー", "桜台ベーカリー", "練馬スイーツ"],
    "緯度": [35.7368, 35.7382, 35.7351],
    "経度": [139.6705, 139.6631, 139.6542],
    "今日のおすすめ": ["コロンビア浅煎り", "焼きたてクロワッサン", "とろけるプリン"],
    "評価スコア": [4.5, 3.8, 4.8]
})

# 2. 地図の土台を生成
m_shops = folium.Map(location=[35.736, 139.663], zoom_start=14)

# 3. 黄金のループ：iterrows() で1行ずつ位置を取り出してピンを立てる
for idx, row in shop_df.iterrows():
    # 各行の経緯度、店舗名、おすすめ商品を取り出す
    lat = row["緯度"]
    lng = row["経度"]
    name = row["店舗名"]
    recommend = row["今日のおすすめ"]
    
    # マーカーを作成して地図に追加
    folium.Marker(
        location=[lat, lng], # foliumは [緯度, 経度] の順！
        popup=f"{name} (おすすめ: {recommend})", # クリックした時のテキスト
        tooltip=name # マウスを乗せた時（ホバー）に出る簡易テキスト
    ).add_to(m_shops)

9.2.3 HTMLポップアップでデザインされたリッチなUIを作る¶

popup 引数の中に渡す文字は、ただのテキストだけではありません。 実は、HTMLのソースコードをそのまま文字列として流し込むことができます！

9.3 階級区分図（Choropleth Map）のデータ構築パイプライン (約40分)¶

9.3.1 「形（境界ポリゴン）」と「数字（Pandas）」を合体させる理論¶

ビジネスのマーケティングや自治体の地域分析で、「どのエリアで売上が高いか」「どこで高齢化が進んでいるか」を一目で把握するために、地域を色の濃淡で塗り分ける手法を**階級区分図（コーロプレス図：Choropleth Map）**と呼びます。

これを作成するには、絶対に2つの別々のデータが必要です。

  1. 境界ポリゴン（地図の形データ：GeoJSON形式など）

    • 「〇〇区の境界線は、この緯度経度の点々を繋いだ多角形（Polygon）です」という、ただの「形」の情報。

  2. 統計データ（属性情報：PandasのDataFrameなど）

    • 「〇〇区の今年の売上高は500万円です」「高齢化率は28%です」という、ただの「数字」の表。

この2つを、共通のキーワード（例えば「区名」や「市区町村コード」）を接着剤（キー）にして合体させることで、初めて色分けされた地図が完成します。

     name: "杉並区"                               店舗: "杉並区"
     geometry: POLYGON((139.6 35.7...))            売上額: 1,200,000 円
   feature 2:                                    行 2:
     name: "練馬区"                               店舗: "練馬区"

9.3.2 folium.Choropleth クラスのパラメータ徹底解読¶

foliumでこれを行うためのコードは、非常に設定項目（引数）が多く、初心者が最もエラーを起こしやすい難所です。 1行ずつのパラメータの意味を、ここで完全にマスターしましょう。

# （概念コード：授業内で解説します）
# folium.Choropleth(

#     data=pandas_df,                     # 2. 塗り分ける「数字」データ（PandasのDataFrame）

【超重要】最大の難関 key_on の書き方¶

なぜ key_on="feature.properties.name" のように、ドット（.）で繋がれた長い文字列を指定するのでしょうか？ それは、GeoJSONという地図ファイルの内部構造（ネストされた辞書型）から、接着剤となる「地域名」を取り出すための**住所（パス）**を指定しているからです。

GeoJSONのファイルの中身は、以下のような構造をしています。

{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "properties": {
        "name": "杉並区",
        "code": "13115"
      },
      "geometry": { "type": "Polygon", "coordinates": [...] }
    }
  ]
}

この中から、接着剤として使いたい "杉並区"（"name"）を取り出すためには、

  1. まず全員に共通する親要素である feature から出発し、

  2. その中にある properties（属性グループ）の中に入り、

  3. 目的の name という引き出しを開ける、

というルートを伝える必要があります。これをドットで繋いで feature.properties.name と書くのが、foliumにおける絶対のルールです。

  • 指導のアドバイス：「Choroplethを実行したら、地図は出るのに全部黒（またはグレー）に塗りつぶされて、グラデーションにならない！」というエラーの100%は、この key_on の指定パスが、GeoJSONファイルの中身とズレていることが原因です。GeoJSONを一度Pandasで読むなどして、propertiesの中にどんなキー名（"name" なのか、"name_local" なのか、"N03_004" なのか）が入っているかを事前に確認する習慣を身につけさせます。

9.3.3 色のグラデーション（Color Brewer 2.0 規格）の選び方¶

fill_color に指定する文字列は、何でも良いわけではありません。 統計地図の世界標準カラー規格である 「ColorBrewer 2.0」 に定められたカラーコード（3文字の略称を繋いだもの）を指定します。

  • YlOrRd：Yellow (黄) ➡ Orange (橙) ➡ Red (赤)。売上高や危険度など、「数字が大きいほど警戒・活発」なデータの可視化に最適。

  • YlGnBu：Yellow (黄) ➡ Green (緑) ➡ Blue (青)。雨量や水分量、森林率など、自然・環境データの可視化に最適。

  • BuPu：Blue (青) ➡ Purple (紫)。高級感や、少し落ち着いた分布を示すのに最適。

  • RdYlGn：Red (赤：悪い/多い) ➡ Yellow (中間) ➡ Green (緑：良い/少ない)。「安全度」や「顧客満足度」など、両極端な評価を表すのに適したカラー。

練習問題 1: 緯度・経度の「指定順序」の罠¶

GeoPandasで店舗の位置（Pointオブジェクト）を新しく手動で作成する場合と、foliumの地図上に folium.Marker でピンを立てる場合では、引数に指定する「緯度」と「経度」の順番のルールが異なります。 それぞれの正しい指定順序の組み合わせを答えてください。

  1. GeoPandas (ShapelyのPoint) ➡ Point( [ A ] , [ B ] )

  2. folium (Map や Marker の location) ➡ location = [ [ C ] , [ D ] ]

👉 練習問題 1 の解答と解説を見る

  • 正解:

    • [ A ] = 経度 (Longitude / X軸), [ B ] = 緯度 (Latitude / Y軸)

    • [ C ] = 緯度 (Latitude), [ D ] = 経度 (Longitude)

  • 解説:

    • 数学のグラフやGeoDataFrameのように「幾何学データ」として空間演算を行うGeoPandasでは、横軸（X軸）である 経度、縦軸（Y軸）である 緯度 の順で指定します。

    • 一方で、Google Mapsやfoliumなどの「Web可視化サービス」のAPIでは、日常の口頭順である 「緯度、経度」 の順でリストを渡すお約束になっています。

    • この2つのズレは、プロのエンジニアでも最も頻繁に間違える罠ですので、コードを書く時は頭の中で「今、自分はデータの加工（GeoPandas）をしているのか、画面の描画（folium）をしているのか」を強く意識しましょう！

練習問題 2: 地図上のポップアップ内での改行¶

👉 練習問題 2 の解答と解説を見る

  • 正解: <br> タグ

  • 解説:

    • foliumのポップアップの中身は、ブラウザが「HTMLソースコード」として解釈して描画します。

練習問題 3: 階級区分図（Choropleth）がグレーにバグる原因¶

folium.Choropleth を使って、各市区町村の人口統計を色の濃淡で塗り分けようとプログラムを実行しました。 エラーメッセージは何も出ず、実行自体は成功して地図は描画されましたが、どの市区町村もグラデーションの色がつかず、すべて一律の「グレー（灰色）」に塗りつぶされてしまいました。 このとき、疑うべき「Choroplethの引数設定」および「データの中身」の原因は何でしょうか？

👉 練習問題 3 の解答と解説を見る

  • 正解:

    • 原因: key_on 引数で指定した「GeoJSON側の地域名が入っているキーのパス」が間違っている（ズレている）ため、Pandasの統計データと位置データが接着剤として噛み合わなかったから。

  • 解説:

    • foliumのChoroplethは、GeoJSONファイルとPandasのデータフレームを、指定されたキー（例：区名）でマッチングさせて色を塗ります。

    • もし、key_on="feature.properties.name" と指定したのに対し、実際のGeoJSONファイルの中に "name" というキーが存在せず、代わりに "city_name" という名前で登録されていた場合、接着剤が完全に空振りしてしまいます。

    • foliumは「マッチする数値データが見つからなかった地域」を、データ未登録エリアとして標準色である「グレー」で安全に塗りつぶします。エラーを出してくれないため、接着キーの名前が完全に大文字小文字・アンダースコアまで一致しているか確認しましょう。

練習問題 4: 「メートル座標系」での空間結合（sjoin）と距離計算（復習）¶

第8回で、商圏バッファ（.buffer()）や距離計算（.distance()）を行う前には、GeoDataFrameを世界測地系 EPSG:4326（経緯度）から、平面直角座標系 EPSG:6677（メートル）などの投影座標系に変換するステップが絶対に必要だと学びました。 では、本日学んだ folium や leafmap を使って、「動的地図の上にピンを配置したり、階級区分図を描画する」直前のデータは、投影変換した EPSG:6677 のままで渡してよいでしょうか？ それとも、元の EPSG:4326 に戻す（あるいは最初から変換しない）必要があるでしょうか？

👉 練習問題 4 の解答と解説を見る

  • 正解: 元の世界測地系 EPSG:4326（経緯度・角度単位）に戻す（あるいは経緯度データのままで渡す）必要がある。

  • 解説:

    • ここが、GeoPandas（加工）とfolium（描画）を組み合わせる際の、最大の頭の整理ポイントです！

    • folium や leafmap のWeb地図は、世界基準のGPS座標である 「緯度と経度（角度：WGS84 / EPSG:4326）」でピンの位置や境界線を認識・表示する仕組み になっています。

    • そのため、もしメートル平面座標系（EPSG:6677）のままで folium.Marker(location=[X座標(メートル), Y座標(メートル)]) のように巨大な数値（例: -35000, -12000 など）を渡してしまうと、システムは「そんな緯度経度は地球上に存在しない！」とパニックを起こしてエラーになります。

これまでに学んだ、境界区画（GeoJSONポリゴン：形）と、統計データ（Pandas：数字）をマッチングさせて美しく塗り分ける、実務データ分析の王道パイプラインです。

  1. 以下のコード内に用意された「東京城西地区の簡易行政区画 GeoJSON（形データ）」と「各地区の避難所混雑率 Pandas DataFrame（数字データ）」を使用します。

  2. 接着剤となる共通のキーワード列は、GeoJSON側が properties.name（properties辞書の中の name キー）、Pandas側が 地区名 列です。

  3. folium.Choropleth を使い、混雑率（数字）が高い地区ほど 「赤（OrRd：オレンジから赤へのグラデーション）」 で自動的に濃く塗り分けられる階級区分図を完成させてください。
