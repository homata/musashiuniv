第12回 Pythonとバイブコーディング（Vibe Coding）¶

🎯 到達目標¶

  1. バイブコーディング（Vibe Coding） の定義と、開発における明確な役割分担（「指示・設計・検証者」としての人間、「高速実装者」としてのAI）を論理的に説明できる。

  2. 生成AIから一発で動く完璧なコードを引き出すための 「4大プロンプト構成要素」 を使いこなし、NGプロンプトをプロ級に改善できる。

  3. AIが記述したプログラムにエラーが発生した際、パニックにならずに エラーメッセージをAIに正しくフィードバックして数秒で自己解決（デバッグ） できる。

  4. これまでに習得した全ての技術（Pandas, ML, GIS, Streamlit）をAIに指示してガッチャンコさせ、実用的な「AI予測付き経営分析ダッシュボード」を15分で構築できる。

  5. 「AIが書いたコードの論理的な誤りや脆弱性を見破るレビュー能力」 の重要性を理解し、AIネイティブ時代の正しい倫理的プログラミング力を説明できる。

バイブコーディングとは何か？（プログラミングのパラダイムシフト）¶

プログラミングの「地殻変動」が始まった¶

これまでのプログラミング学習は、非常に過酷なものでした。 「変数、ループ、リストの文法を丸暗記し、コロン（:）やインデント（空白4マス）の位置を1ミリも間違えないように、スペルミス（タイポ）をしないように目を皿のようにしてキーボードを叩く……」 これが、数十年続いてきたプログラミング学習の当たり前の姿であり、同時に、多くの文系学生が「エラーばかりで心が折れた」と挫折する最大の原因でした。

しかし、2022年末のChatGPTの登場を皮切りに、世界最高峰の言語モデル（LLM）がプログラミング能力を爆発的に高めました。今や、自然言語（日本語）で「こういうことをするプログラムを書いて」と頼めば、AIがミリ秒単位で、スペルミスもインデントエラーも一切ない、極めて美しいコードを出力してくれます。

この技術革新が生んだ新しい開発パラダイムが、「バイブコーディング（Vibe Coding）」です。

【従来の開発とバイブコーディングの比較】

▼ 従来型の開発（実装が「労働」だった時代）
  [ 人間 ] ──( 🧠 考える＆設計 )──▶ [ 人間 ] ──( ⌨️ 手書きで200行書く：数日かかる )──▶ [ 実行 ]
  ※タイポや文法エラーに何時間も苦しみ、実装だけでエネルギーの90%を消費してしまう。

▼ バイブコーディング（実装が「一瞬」の現代）
  [ 人間 ] ──( 🧠 考える＆設計・Vibe )──( 🗣️ 指示・日本語 )──▶ [ AI ] ──( 💻 0.5秒で手ブレなしのコード生成 )
                                                                 │
  [ 🎉 わずか15分で完成！ ] ◀── [ 🛠️ AIが即座に修正 ] ◀──( 🐛 エラーを貼る )──╯
  ※人間は「アイデア」「設計」「正しさの検証（レビュー）」という、最も楽しいクリエイティブな活動に100%集中できる！

人間とAIの正しい役割分担¶

バイブコーディングにおいて、人間とAIの関係は「映画の監督（ディレクター）」と「非常に優秀だが自分からはアイデアを出せない新人アシスタント（プログラマー）」の関係に似ています。

  • AI（プログラマー・実装者）： 指定されたコードを、一瞬で正確に書く。バグの修正も得意。ただし、「何を作れば人間が喜ぶか」「地域のどんな課題を解決するか（シビックテックの精神）」は自分では一切思いつけない。

  • 人間（設計者・ディレクター）： 🌟あなたの役割！ 「どんな画面にしたいか」「何のオープンデータを読み込ませたいか」「どういう人がこのアプリを使うか」という、全体の雰囲気（Vibe）と設計図を考え、AIを正しく指揮する。

AI時代だからこそ「プログラミング基礎」が10倍重要になる理由¶

「AIが全部コードを書いてくれるなら、私たちはもう変数とかPandasとか、データ解析の勉強なんてしなくていいんじゃないですか？」 これは、非常に多くの人が陥る最大の誤解です。

プログラミングの基礎知識を持たない人がAIを使って作ったアプリは、高確率で「致命的な欠陥」を抱える可能性が高いです。

なぜでしょうか？ AIは、非常にそれっぽくて動くコードを出力してくれますが、時々「嘘（ハルシネーション）」や「論理的な計算バグ」を混ぜて出力します。 例えば、前々回に学んだ機械学習の評価で、AIが「予測モデルの決定係数（(R^2)）を計算するコード」を書いたとします。もしAIが「学習用データ」をそのままテストに使い回す致命的なミス（データリーケージ：カンニング）を犯していた場合、プログラム自体はエラーを吐かずに「100%完璧に動きます」。

プログラミングの基礎知識（過学習やデータ分割の意味）を知らない人は、AIが書いたコードのミスに気づけず、「このAIモデルの決定係数は1.0（完璧）です！」と間違った成果を役員会や社会に報告してしまうことになります。これはビジネスや研究において、取り返しのつかない大事故になります。

AIにコードを書かせることはできても、「そのコードが本当に正しい処理をしているかを読み解き、検証（レビュー）し、正しさを保証すること」は、プログラミング知識を持つ人間にしかできません。 「手書きする労力（タイピング・暗記）」は不要になりましたが、「コードを読んで論理をチェックする力（コードリーディング）」は、これからのAI時代にこそ、最も強力で価値のある武器になるのです。

AIから完璧なコードを引き出す「プロンプトの極意」¶

AIを最高の部下として完璧に動かすためには、「プロンプト（指示文）」の書き方に明確な型（フォーマット）が必要です。 ただ単に「売上予測アプリのコードを書いて」とだけ頼むのは、新人に「いい感じに仕事しといて」と丸投げするのと同じで、使えないコードが返ってくる原因になります。

【実例】NGプロンプト vs プロ級プロンプト（改善ビフォーアフター）¶

プロンプトの失敗例と、それを一発で成功させるプロの書き方を見比べてみましょう。

❌ NGプロンプト（これでは動かないコードが返ってきます）¶

「Streamlitで売上を予測するアプリのコードを書いてください。グラフも出したいです。よろしく。」

  • 何がダメか：

    • AIは「どのようなデータ（CSVなど）を使うべきか」が分かりません。

    • どのような「予測アルゴリズム」を使うべきか指定されていません。

    • Google Colab特有の「ファイル書き出し（%%writefile app.py）」や「localtunnel」を考慮していないため、Colab上で実行できないコード（ローカルのターミナル用コードなど）が出力されてしまいます。

⭕ プロ級プロンプト（一発で100点満点のコードが返ってきます）¶

【役割】 あなたは優しく教えるのが得意な、世界一流のPythonデータサイエンス講師です。

【開発環境】 Google Colab上で開発を行い、Streamlitとlocaltunnelを使ってWebアプリを起動します。

【前提データ（インプット）】

  1. コードの内部で、50日分のカフェ模擬データフレーム（df）を作成してください。

    • 列名：「客数」（50〜300人の間のランダムな整数）

    • 列名：「売上高」（客数 × 350円 ＋ 多少のランダムなノイズを入れた実数）

  2. Pandasのデータフレームの「客数」を説明変数(X)、「売上高」を目的変数(y)に設定してください。

【具体的要件（処理とアウトプット）】

  1. アプリ起動時に、scikit-learnの LinearRegression モデルに上記の df を学習（.fit）させてください。

  2. 画面の左側のサイドバー（st.sidebar）に、「明日の客数（人）」を調整できるスライダー（最小10人、最大400人、デフォルト150人）を設置してください。

  3. スライダーで選ばれた客数から、学習済みの線形回帰モデルを使って「予測売上高（円）」を計算し、メイン画面に st.metric を使ってデカデカと表示してください（金額はカンマ区切りの整数にキャストしてください）。

  4. メイン画面の st.metric の下に、過去の df の点々（青色）と、AIが引いた「予測直線（赤色の点線）」を Matplotlib で描画して表示してください。

  5. グラフの上には、現在スライダーで選択されている「予測ポイント」を、目立つ「黄色い星マーク（★）」で重ね合わせてプロットしてください。

【出力形式】 コピペするだけで100%一撃で動く、1つの app.py ファイルとして完結する美しいPythonコードのみを出力してください。余計な前置きテキストは不要です。

このように、「自分の頭の中にある『完成イメージ（Vibe）』を、箇条書きで漏れなく、論理的な手順書に変換してAIに手渡す」ことこそが、バイブコーディングの神髄です。

【ハンズオン1】AIを活用した「Pandasデータ処理」の自動化¶

それでは、実際に生成AIの力を借りて、複雑なデータクレンジングを一瞬で実装するハンズオンを行います

実務で非常によくある「表記揺れが激しく、不要な文字や空白が混ざった汚いCSVデータを、一瞬できれいに掃除（クレンジング）するプログラム」をAIに作らせてみます。

汚れたデータの準備¶

まずは、以下の「お掃除前の汚れたデータ」を作成してください。

<!-- コードセル -->
import pandas as pd
import numpy as np

# わざと激しく汚した「カフェの売上データ」のデータフレームを作成
raw_dirty_df = pd.DataFrame({
    "注文日": ["2026/08/28", "2026-08-29", " 2026/08/30 ", "2026.08.31"], # 日付のフォーマットがバラバラ、空白もある
    "店舗名": [" 江古田本店 ", "白山店", "江古田本店", "  白山店  "],       # 前後に大量の余計なスペースがある
    "本日売上": ["52,000円", "48000", "データなし", "60,000 円"],           # カンマ、円、空白、日本語が混ざった最悪の文字列
    "無料WiFi": ["あり", np.nan, "あり", "あり"]                           # 欠損値（NaN）が含まれている
})

print("🧼 【お掃除前の汚れたデータ】")
display(raw_dirty_df)
print("\nデータ型を確認してみましょう:")
print(raw_dirty_df.dtypes) # すべてが「object（文字列）」として認識され、計算不可能な状態です

AIへのプロンプト指示（バイブコーディング）¶

今、あなたの目の前には汚いデータがあります。 これをお掃除するためのPandasコードをAIに書いてもらうため、以下のプロンプト（Vibe）を生成AIに送信したと想定します。

【AIへの指示プロンプト】 以下のPandasデータフレーム「raw_dirty_df」をデータクレンジングして、美しいデータフレーム「clean_df」を完成させるコードを書いてください。 【クレンジング要件】

  1. 「注文日」列： 日付に変換できない余計な前後の空白を削除した上で、すべて「YYYY-MM-DD」の日付型（datetime64）に統一して変換してください。

  2. 「店舗名」列： 文字の前後に含まれる余計な空白スペース（半角・全角）を完全に除去してください。

  3. 「本日売上」列：

    • カンマ（,）や「円」という日本語、不要な空白を除去してください。

    • 「データなし」という文字は、数値の 0 に置換してください。

    • 最終的に、計算ができるように「整数型（int）」に変換してください。

  4. 「無料WiFi」列： 欠損値（NaN）を「なし」という文字で補完してください。

実行すると、お掃除完了後の clean_df と、データ型（.dtypes）、および本日売上高の合計値を出力する、Pythonコードのみを出力してください。

AIが生成したお掃除コードの実行¶

以下は、上記のプロンプトによってAIが一撃で出力した完璧なお掃除プログラムです。実行してみましょう！

# 🌟 AIが自動生成したデータクレンジングプログラム

# 1. 元の汚いデータをコピーしてクレンジングを開始
clean_df = raw_dirty_df.copy()

# 要件1: 注文日列のクレンジング（空白削除 ➡ datetime変換）
clean_df["注文日"] = clean_df["注文日"].str.strip()
clean_df["注文日"] = pd.to_datetime(clean_df["注文日"].str.replace("/", "-").str.replace(".", "-"))

# 要件2: 店舗名列のクレンジング（前後の空白除去）
clean_df["店舗名"] = clean_df["店舗名"].str.strip()

# 要件3: 本日売上列のクレンジング（カンマ・円・空白削除 ➡ 0置換 ➡ intキャスト）
clean_df["本日売上"] = clean_df["本日売上"].str.replace(",", "").str.replace("円", "").str.replace(" ", "")
clean_df["本日売上"] = clean_df["本日売上"].replace("データなし", "0")
clean_df["本日売上"] = clean_df["本日売上"].astype(int)

# 要件4: 無料WiFi列のクレンジング（欠損値を「なし」で埋める）
clean_df["無料WiFi"] = clean_df["無料WiFi"].fillna("なし")

# 結果の確認表示
print("✨ 【AIによるお掃除（クレンジング）完了後のデータ】")
display(clean_df)
print("\nデータ型:")
print(clean_df.dtypes) # 本日売上が「int64」、注文日が「datetime64」になりました！

# 売上の合計を計算してみる
total_sales = clean_df["本日売上"].sum()
print(f"\n期間内の総売上高: {total_sales:,} 円") # 160,000円 と正しく計算できれば大成功！

一文字も手書きでお掃除コードを書くことなく、Pandasの難解な正規表現や置換、型変換が一瞬で終わってしまいました。 これが、バイブコーディングがもたらす圧倒的な効率化です。

【ハンズオン】AI売上予測Webダッシュボードの構築¶

これまでに学んだ「Pandasによるデータ読み込み」「scikit-learnによる線形回帰AI学習」「Matplotlibによるグラフプロット」「Streamlitのカラム分割UIとスライダー操作」、そして「localtunnelによる公開」のすべてを合体させた、「AI予測機能付き売上ダッシュボードアプリ」 をAIで作らせてみましょう。

エラーをAIに直させる「自己修復デバッグ」¶

バイブコーディングでアプリを作っていると、1回で完璧に動くことは稀で、高確率で赤いエラー画面に直面します。 そんな時、初心者は「もうダメだ、プログラミングなんて嫌いだ」と諦めてしまいがちです。 しかし「エラーが出た時こそ、AIにバグを直してもらう絶好のチャンス」なのです。

これを 自己修復デバッグ（Self-Healing Debugging） と呼びます。

【エラー修復のイメージ図】

  [ 💻 エラー発生！ ] ──▶ [ 📋 エラーメッセージをコピー ]
                                 │
                                 ▼ (プロンプトに貼り付け)
  [ 🧠 人間からの指示 ]
    「このエラーが出ました。原因を分析して、修正したコードだけを再出力してください。」
                                 │
                                 ▼ (一瞬で分析・書き換え)
  [ 🤖 AIから修正コードの提案 ] ➡ [ 🎉 コピペして実行 ➡ 1秒でバグ解消！ ]

AIにバグを直させる「エラーフィードバックの3ヶ条」¶

AIにデバッグを依頼する時は、以下の3点をプロンプトに盛り込んでチャットで送るのが鉄則です。

  1. エラーメッセージを「丸ごと（コピペで）」貼る： 「エラーが出ました。直して」だけではAIもエスパーではないので直せません。赤い画面に表示された NameError: name 'plt' is not defined のようなテキストをそのまま貼り付けます。

  2. エラーが起きた「直前のソースコード」を貼る： AIはチャット履歴を忘れることがあるため、「このコードを実行したらエラーが出ました」と、対象のコードを一緒に貼ってあげると、修復の精度が100%に跳ね上がります。

  3. 「修正したコードだけを丸ごと再出力して」と頼む： 「〇行目をこう書き換えてください」と小出しに指示されると、初心者はどこを書き換えればいいか迷子になります。丸ごと再出力させることで、コピペするだけで一瞬で直せるようになります。

「動きはするが、計算が間違っている」論理バグの修正方法¶

一番厄介なのは、プログラムは動いていて赤いエラー画面も出ないのに、「計算結果が明らかに不自然（バグ）」というケースです。 例えば、「客数を増やしているのに、売上予測金額がどんどんマイナス（減っていく）になる」というバグが起きたとします。

これは、プログラムの文法エラー（タイポなど）ではなく、AIモデルの学習方法やデータの渡し方がおかしい「論理エラー（Logical Error）」です。 これを見抜くために、先ほど説明した「人間のプログラミング基礎知識（レビュー力）」が必要になります。

❌ AIへの間違った指示（これでは直りません）¶

「売上予測がマイナスになります。バグを直して。」

  • ダメな理由：AIは「なぜマイナスになっているのか」の仮説が立てられず、適当にコードを書き直して余計にバグを深くしてしまいます。

⭕ AIへの論理的な修正指示（これで一撃で直ります）¶

「プログラム自体はエラーなく動いていますが、客数スライダーを増やすと予測売上が減少してマイナスになる論理バグが発生しています。 調べたところ、過去データ df の客数(X)と売上高(y)の相関が逆（負の相関）になって学習されている、もしくは model.predict() に渡す引数の形状（2次元配列）が間違っている可能性があります。 過去データが正しく『客数が増えれば売上も増える正の相関』になるよう模擬データを修正し、予測値が正の整数で出力されるようにコードを修正してください。」

このように、「バグの仮説を人間が立てて、修正方針をAIに指示する」。これができるようになった時、あなたはAIに仕事を奪われる側ではなく、AIを支配して生産性を何十倍にも高める「真のデータ活用人材」になるのです。

練習問題 3：Rerun（再実行）システムの仕様（理論）¶

Streamlitの動作システム「Rerun（再実行）」の仕様に関する説明として、正しい記述を選んでください。

  1. Streamlitは、ユーザーが画面上のスライダーやボタンを操作するたびに、「プログラムの該当する1行だけ」をピンポイントで書き換えて実行する。

  2. Streamlitは、ユーザーが何か操作をするたびに、「プログラムを一番上から一番下まで、すべて最初から実行し直す」。

  3. Streamlitは、一度起動したら画面は完全に固定され、Pythonプログラムが裏で再実行されることはない。

👉 練習問題 3 の解答を見る

  • 正解: 2

  • 解説:

    • これがStreamlitの最も重要で画期的な仕様です。スライダーを1ミリ動かすだけで、Pythonは「ファイルの一番上から一番下まで、もう一度丸ごと実行し直して」画面を更新します。

    • この仕様を理解していないと、次の練習問題4のような「ボタンの罠」にハメられて頭を抱えることになります。

練習問題 4： st.button が抱える「一瞬の罠」（理論）¶

Streamlitで以下のプログラムを作成しました。

# 1. 割引率を入力するスライダー
discount = st.slider("割引率", 0, 50)
# 2. 「計算する」ボタン
if st.button("計算する"):
    st.write(f"割引後の金額は {500 * (1 - discount/100)} 円です")

このアプリを起動して、 「① 割引率を20%に合わせる」➡「② 『計算する』ボタンを押す（画面に400円と出る）」➡「③ 割引率をさらに30%に動かす」 という操作を行いました。③の操作をした瞬間、画面の表示はどうなるでしょうか？

  1. 割引率が30%に変わり、画面の表示も即座に「350円です」に書き換わる。

  2. 画面には「400円です」という文字がそのまま残り続ける。

  3. 「計算する」ボタンを押した中の処理が消え去り、「割引後の金額は...」という文字自体が画面から完全に消滅する。

👉 練習問題 4 の解答を見る

  • 正解: 3（計算結果が画面から消えてしまう！）

  • 解説:

    • st.button は、「押されたその一瞬（Rerunの1回分）だけ True になり、次のアクションが起きた瞬間に自動的に False に戻る」という仕様を持っています。

    • ③でスライダーを動かした瞬間、Streamlitはプログラムを「上から下まで最初から再実行」します。このとき、ボタンは「今この瞬間は押されていない」ため False に戻ってしまい、if文の中の st.write 処理がスキップされ、結果が画面から一瞬で消えてしまいます。

    • これを防ぐには、チェックボックス（st.checkbox）を使って状態を持たせるか、セッション状態（st.session_state）に値を保存するという、PandasやPythonの高度な状態管理の知識が必要になります。

AIにコードを作らせて実行したところ、以下の赤いエラーメッセージ（ZeroDivisionError）が発生して処理が止まってしまいました。

  2. このエラーを未然に防ぎ、エラーの代わりに「本日の来客数は0人です」と画面に優しく表示させるようにコードを修正してもらうため、AIにチャットで送る「修正依頼プロンプト（指示文）」を記述してください。

👉 演習 2 の解答を見る

  1. エラーの原因:

    • 割り算の分母である total_customers（本日の来客数）の数値が 「0（ゼロ）」 になっていたため、数学・プログラミング上の禁忌である「0での割り算（ゼロ除算）」が発生し、プログラムがパニックを起こして強制終了した。

    • これは、雨の日などで本当にお客様が一人も来なかった日、あるいはデータの読み込み・フィルタリングの条件設定を間違えてデータ件数が0件で抽出されてしまった場合に発生する。

  2. AIへのデバッグ指示プロンプト:

    提供されたコードを実行したところ、以下のエラーが発生しました。

    ZeroDivisionError: division by zero

    該当箇所は average_spend = total_sales / total_customers です。本日の来客数（total_customers）が0人の場合に、ゼロ除算エラーが発生してプログラムが強制終了してしまいます。

    【修正要件】

    1. if-else 条件分岐を使い、total_customers が 0 よりも大きい（1人以上いる）場合のみ、上記の割り算を実行して平均客単価を算出するようにしてください。

    2. もし total_customers が 0 の場合は、割り算を実行せず、average_spend = 0 と設定し、画面に「⚠️ 本日の来客数は0人のため、平均客単価は算出できません。」と警告メッセージを出力するようにコードを修正してください。

import streamlit as st

st.set_page_config(page_title="学園祭POSアプリ", layout="centered")

st.title("🎪 学園祭 POSレジシステム チュロス＆タピオカ")
st.write("深夜割増・クーポン割引自動計算POSです。")

# 1. サイドバー（設定メニュー）
st.sidebar.header("⚙️ レジ基本設定")
selected_shop = st.sidebar.selectbox("販売店舗を選択してください", ["江古田店", "白山店"])
is_late_night = st.sidebar.checkbox("🌙 深夜営業モード (+50円/個)")

# 2. メイン画面の入力フォーム
st.subheader("🛍️ 注文入力")
item = st.selectbox("商品を選択してください", ["チュロス (350円)", "タピオカ (400円)"])
quantity = st.slider("数量を選択してください", min_value=1, max_value=10, value=1)
use_coupon = st.checkbox("🎟️ 10%割引クーポンを使用する")

# 3. 計算ロジック
# 基本単価の設定
base_price = 350 if "チュロス" in item else 400

# 深夜増し料金の加算
if is_late_night:
    base_price += 50

# 小計
subtotal = base_price * quantity

# 割引の適用
if use_coupon:
    final_total = int(subtotal * 0.9) # 10%引き（整数にキャスト）
else:
    final_total = subtotal

# 4. 主要指標(KPI)の出力
st.write("---")
col1, col2 = st.columns(2)
with col1:
    st.metric(label="🏪 担当店舗", value=selected_shop)
with col2:
    # 割引が適用された場合、矢印(delta)で割引額を表示する粋な演出
    discount_diff = subtotal - final_total
    delta_text = f"-{discount_diff}円引き適用" if discount_diff > 0 else None
    st.metric(label="💰 お会計合計金額", value=f"{final_total:,} 円", delta=delta_text)

# おまけのレシート風表示
with st.expander("🧾 簡易レシート内訳"):
    st.text(f"店舗：{selected_shop}")
    st.text(f"商品：{item} ✕ {quantity}個")
    if is_late_night:
        st.text("※深夜割増料金(+50円/個)が適用されています。")
    st.text(f"小計：{subtotal:,}円")
    if use_coupon:
        st.text(f"クーポン割引：-{discount_diff:,}円")
    st.text(f"合計支払金額：{final_total:,}円")
