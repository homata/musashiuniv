第5回 Webサービスの活用1：StreamlitによるWebアプリ開発の基礎（200分集中講義版）¶

皆さん、こんにちは！プログラミング応用A（コンピューティング応用G）、第5回の講義です。担当の教員です。 前回（第4回）は、Pandasを使って「平均値の罠」を見破り、データのばらつき（標準偏差）や関係性の強さ（相関係数）を可視化する「データ解析」の基本を学びました。

今回からは、データ分析をさらに一歩進めて、**「Webサービスの活用」**という新しい領域に突入します！ 具体的には、Pythonだけで本格的なWebアプリケーションを構築できる魔法のライブラリ Streamlit（ストリームリット） を使って、あなた専用の「データダッシュボード」を作っていきます。

この講義は**「200分（2コマ連続、または集中講義）」**のスケールで、基礎から実務レベルまでを一本の線で繋ぎます。 「HTMLやCSS、JavaScriptは難しそう…」「Webサーバーって何？」と思うかもしれませんが、大丈夫です！ Streamlitを使えば、そうした難しいデザインのコードは一切書く必要がありません。Pythonのコードを数行書くだけで、オシャレなボタンやスライダー、グラフが画面に自動的に配置されます。

前半の100分では、Google Colab上でWebアプリを安全に起動するための特別な「トンネリング技術」の仕組みと構築を。 後半の100分では、オシャレなボタンやスライダーを配置し、ユーザーの操作に応じて画面が自動で書き換わる「対話型（インタラクティブ）」なプログラムの作り方と、Streamlit特有の動作ルールを深く学んでいきます。

自分で作ったプログラムがWebブラウザ上で「動くアプリ」として生命を吹き込まれる感動を、ぜひこの200分間で体験してください！

🎯 本日の到達目標¶

この200分の集中講義が終わるころには、以下のことができるようになります。

5.1 なぜデータを「アプリ」にするのか？（ダッシュボード化の意義） (約15分)¶

データ分析を「社会や現場に届ける」最後の壁¶

これまでの授業で、私たちはデータを収集し、Pandasで集計し、Matplotlibでグラフを描くことができるようになりました。 しかし、その分析結果を「プログラミングを全く知らない会社の上司、店舗マネージャー、あるいは一般のお客様」に見せたいとき、どう共有すればいいでしょうか？

  • 「Pythonのコードと、グラフの画像ファイルをメールで送る」

    • 😱 問題点：相手はPythonを実行できません。また、画像は「静止画」なので、相手が「特定の店舗だけ」「特定の年代だけ」に絞り込んだデータを見たいと思っても、拡大したり、条件を変えて計算し直したりすることができません。

  • 「Excelファイルを共有する」

    • 😱 問題点：共有された相手が誤って関数や数式を壊して（消して）しまったり、スマートフォンからだと画面が崩れて操作しづらかったりします。

一番良い解決策は、**「誰でもスマホやパソコンのブラウザからアクセスして、ボタン一つでデータを絞り込める『Webアプリ』にして渡すこと」です。このように、データと操作盤が合体した画面を「データダッシュボード」**と呼びます。

【ダッシュボード開発の今と昔（イメージ図）】

▼ 昔の開発方法（学習コスト：極大 😱）
  Python(分析) ＋ HTML/CSS(画面デザイン) ＋ JavaScript(動き) ＋ サーバー構築
  ➡ 覚えることが多すぎて、文系学生やデータ分析者は画面を作る前に挫折してしまいます。

▼ Streamlitを使った開発（学習コスト：極小 😍）
  [ 🐍 Pythonコード数行 ] ──▶  [ 🎨 Streamlitが自動変換 ] ──▶ [ 💻 プロ級のWebアプリ ]
  ➡ HTMLもサーバーの知識も不要！いつものPythonコードがそのまま美しいアプリに生まれ変わります。

5.2 Google ColabにおけるWebアプリ開発の壁とトンネリング技術 (約40分)¶

通常、Streamlitはお手元のパソコン（ローカル環境）のターミナル（黒い画面）で起動します。 しかし、本コースでは誰もがすぐに同じ環境で学習を始められるよう、インストールの手間がない Google Colab を利用しています。

ここで1つ、ネットワーク上の重大な問題が発生します。 Google Colabは、**「Googleが管理する、インターネットの向こう側（クラウド）にある仮想パソコン」**です。 Colabの中で「Webアプリ（Streamlit）」を起動しても、そのアプリはクラウドの奥深くに隠れているため、手元にあるあなたのパソコンのブラウザ（Google Chromeなど）から、直接住所（URL）を入力して覗きに行くことができません。

【Colabと手元のブラウザの距離（イメージ図）】

  [ 💻 あなたのパソコン ]                      [ 🏛️ Google Colab（クラウド） ]
  ┌───────────────────┐                      ┌────────────────────────────┐
  │  Chromeブラウザ    │  ──(見に行けない)──▶ │   Streamlit起動！          │
  │  (手元)           │  ⚠️ 壁（ファイアウォール）│   (ポート: 8501)           │
  └───────────────────┘                      └────────────────────────────┘

この「壁」を突破し、一時的に外からアプリを覗き見するための安全な通路（トンネル）を作ってくれるツールが、localtunnel（ローカルトンネル） です。

  1. Colabの中でStreamlitアプリを起動します（内部ポート 8501 番という窓口で待機します）。

  2. localtunnelが、8501番の窓口と、世界中からアクセスできる一時的なWebアドレス（https://xxxx.loca.lt）を直結します。

  3. あなたがその一時的アドレスにアクセスすると、トンネルを通って、Colabの中のStreamlitアプリの画面が手元のブラウザに映し出されます。

  [ 手元のブラウザ ] ──▶ [ https://xxxx.loca.lt (トンネルURL) ] ──▶ [ Colabの8501番窓口 ] ──▶ [ アプリ画面 ]

セキュリティの鍵「IPアドレス」¶

トンネルを開通してアクセスする際、不審なハッカーの侵入を防ぐため、localtunnelから「接続先Colabのセキュリティキー（パスワード）」を入力するよう求められます。 このキーとして使用するのが、あなたのColab環境に割り当てられた 「IPアドレス（4つの数字の羅列）」 です。これは後ほど、手順の中で実際に取得します。

5.3 実践ハンズオン：Hello Worldアプリの起動（手順A, B, C） (約40分)¶

それでは、実際に手を動かして、あなた専用の最初のWebアプリをインターネット上に誕生させてみましょう！ 以下の「黄金の3ステップ」を順番に実行していきます。

ステップ 1: 必要なライブラリのインストール¶

まずは、Colabのセルに以下のコマンドを入力して実行し、Streamlitと、トンネリングツール（localtunnel）をColabの仮想パソコンにインストールします。 ※コマンドの先頭についている「!」は、PythonではなくColabのシステムに命令を下すおまじないです。

# 必要なパッケージをインストールします（1回実行すればOKです）
!pip install -q streamlit
!npm install -g localtunnel

🚀 手順A: アプリのソースコードを書き出す（%%writefile）¶

Colabは通常、セル単位でプログラムを実行しますが、Webアプリを起動するためには、プログラムを「1つの独立したファイル（app.py）」として保存する必要があります。

セルの1行目に %%writefile app.py と書くと、そのセルに記述されたコードが、Colabのフォルダ内に app.py という名前のファイルとして自動で書き出され、保存されます。

以下のコードを新しいセルにコピペして、実行してみましょう！

%%writefile app.py
# -------------------------------------------------------------
# ここに書いたコードが、そのまま「app.py」というファイルに書き出されます
# -------------------------------------------------------------
import streamlit as st

# アプリのタイトルを表示
st.title("Musashi Cafe アプリ ☕")

# メッセージを表示
st.write("プログラミング応用Aの授業で作成した、私の最初のWebアプリです！")
st.write("スライダーやボタンを追加して、これからPOSレジやダッシュボードに進化させていきます。")

実行後、Colabの画面左側にある「フォルダ（ファイル）」アイコンをクリックすると、app.py というファイルが生成されていることを確認してください。

🔑 手順B: トンネルの鍵（あなたのIPアドレス）を確認する¶

次に、トンネルを開くためのセキュリティパスワード（Colabの外部IPアドレス）を取得します。 以下のコマンドを実行すると、数字の羅列（例：34.125.12.34）が表示されます。この数字をコピーしてメモ帳などに貼り付けておいてください。

# あなたのColab環境のIPアドレス（パスワード）を表示します
!wget -qO- ipv4.icanhazip.com

🌐 手順C: アプリをバックグラウンドで起動し、トンネルを開通する！¶

いよいよアプリを裏側で起動させ、世界に公開します。 以下のコマンドを実行してください。

# 1. Streamlitをバックグラウンド（裏側）で実行し、ログファイルを保存します
!streamlit run app.py &>/dev/null &

# 2. ポート8501番（Streamlitの標準ポート）を外部に公開するトンネルを開通します
!npx localtunnel --port 8501

【接続のやり方（超重要）】

  1. 上記のセルを実行すると、数秒後に画面下に your url is: https://xxxx.loca.lt という青いリンクが表示されます。このリンクをクリックしてください。

  2. 画面が切り替わり、「Friendly Reminder」という英文のセキュリティ画面（または「Tunnel Password」入力画面）が開きます。

  3. 画面中央の 「Tunnel Password」 という入力欄に、先ほどの 【手順Bで確認したIPアドレス（数字の羅列）】 をそのまま貼り付け（ペースト）してください。

  4. その下にある 「Click to Submit」（またはSubmit）ボタンをクリックします。

  5. 画面が読み込まれ、あなたが作った 「Musashi Cafe アプリ ☕」 の真っ白で美しいWeb画面が目の前に起動します！

5.4 Streamlitの表示系コマンドと入力部品ウィジェット (約30分)¶

最初のアプリが起動したことに感動したら、今度はアプリの中身を豪華に、そしてインタラクティブにしていきましょう！ アプリのファイルを書き換えるときは、常に 「手順A（%%writefile app.py）のセルを書き換えて実行」➡「開いているWebアプリ画面の右上にある『Always rerun（またはRerun）』ボタンを押す」 という開発サイクルを回します。

1. 情報を伝える表示系コマンド¶

Streamlitには、文字を綺麗にデザインして表示するためのコマンドがたくさん用意されています。

st.title("大きなタイトル") # ページの一番上に置く大見出し
st.header("中見出し")      # セクションの区切りに使う見出し
st.subheader("小見出し")   # さらに細かい段落の見出し
st.write("通常のテキスト。Pandasの表やグラフもこれ1つで綺麗に表示できます。")
st.markdown("**太字** や *斜体*、[リンク](https://...) などを自由に書くためのマークダウン。")

2. ユーザーの入力を受け取るウィジェット（入力部品）¶

ここからがStreamlitの真骨頂です。エクセルや通常のWebサイトにあるような操作部品を、たった1行で設置できます。 ユーザーが操作した結果（選択した文字や数値）は、そのまま左辺の変数にリアルタイムに代入されます。

① ドロップダウンメニュー（st.selectbox）¶

# st.selectbox("ラベル名", [選択肢のリスト])
selected_item = st.selectbox(
    "ご注文の商品を選んでください:",
    ["ブレンドコーヒー (450円)", "ダージリン紅茶 (400円)", "チョコケーキ (550円)"]
)
# ユーザーが「チョコケーキ (550円)」を選ぶと、変数 selected_item にその文字列が代入されます。

② 数値調整スライダー（st.slider）¶

# st.slider("ラベル名", 最小値, 最大値, 初期値)
quantity = st.slider("数量を選択してください:", 1, 10, 1)
# ユーザーがスライダーを「3」に合わせると、変数 quantity に 3 という数値が代入されます。

5.6 最重要：Streamlitの動作メカニズム「Rerunシステム」と「st.buttonの罠」 (約30分)¶

Streamlitは非常に簡単にアプリが作れますが、他のプログラミング言語とは全く異なる**「特有の動作ルール（動作システム）」**を持っています。 これを知らないと、今後「なぜかアプリが思い通りに動かない！」という深刻な泥沼（バグ）にはまることになります。200分集中講義の後半の主役として、この仕組みを完璧に脳に叩き込みましょう！

1. 「Rerun（再実行）」システムの真実¶

通常のPythonスクリプトは、上から下まで実行したら、そこでプログラムは「終了」して消えてしまいます。 しかし、Streamlitは違います。

🌟 Streamlitの鉄則： ユーザーが画面上の何か（スライダー、セレクトボックス、チェックボックスなど）を**「1ミリでも動かした瞬間」、Streamlitは裏側で、記述されたPythonプログラム（app.py）を「1行目から最後（一番下）まで、毎回すべて丸ごと再実行（Rerun）」**します。

【Rerun（再実行）の流れ】

  1. スライダーを「2」から「3」に動かす。

  2. Pythonが「よっしゃ、もう一度1行目からやり直すぞ！」と立ち上がる。

  3. quantity = st.slider(...) の行に来たとき、画面のスライダーが「3」であることを読み取って、変数 quantity に 3 を代入する。

  4. 下の行の total_price = ... を計算し直し、画面全体の数値を書き換える。

  5. プログラムの最後まで到達したら、一時停止して次の操作をじっと待つ。

この「毎回、最初からすべてをやり直す」というシンプルな豪快さがあるからこそ、私たちは面倒な「画面の書き換え処理」を一切書かなくても、常に最新の計算結果を画面に表示できるのです。

2. 初心者が100%はまる「st.button の消える罠」¶

この「毎回最初からやり直す（Rerun）」という仕組みが原因で、ボタン（st.button）を扱う際に、初心者が100%パニックを起こす「罠」が発生します。

例えば、以下のようなアプリを思い浮かべてください。

  • 「送信」ボタンを押すと、画面に「お見積もりを送信しました！」とメッセージが出る。

  • その下には、数量を調整するスライダーがある。

実際にこのコード（バグのある例）を実行したと仮定して、何が起きるか見てみましょう。

# ⚠️ バグのあるプログラムのイメージ
import streamlit as st

st.title("お見積もり送信アプリ")
quantity = st.slider("数量を選んでください", 1, 10, 1)

# ボタンの設置
# ボタンがクリックされた「その瞬間だけ」、st.button は「True（真）」になります
if st.button("お見積もりを確定して送信"):
    # ユーザーがクリックした瞬間だけ、この中身が実行されます
    st.success("🎉 メールを送信しました！")

【バグの発生プロセス（なぜ消えるのか？）】

  1. 初期画面：

    • ユーザーが画面を開く。プログラムが上から下まで走り、ボタンは押されていないので st.button は False。画面にはスライダーとボタンだけがある。

  2. 確定ボタンをクリックする：

    • クリックした瞬間、Rerun（再実行）が発生！

    • 1行目から再実行され、st.button の判定部分に来る。

    • 「今、クリックされた瞬間」なので、st.button は True を返す。

    • if の中に入り、画面に 「🎉 メールを送信しました！」 という緑のボックスが表示される。（ここまでは大成功）

  3. スライダーを動かして個数を変更する：

    • 個数を変更した瞬間、またRerun（再実行）が発生！

    • 1行目から再びプログラムが走り始める。

    • st.button の判定部分に来る。

    • しかし、今回のRerunのきっかけは「スライダーの移動」であり、「ボタンのクリック」ではありません。

    • したがって、st.button は False（押されていない）に戻ってしまいます！

    • if の中の処理はスキップされ、画面から「🎉 メールを送信しました！」というメッセージが、煙のように綺麗に消え去ってしまいます。

【st.buttonの消える罠（イメージ図）】

  【ボタンを押した瞬間】                    【スライダーを動かした瞬間】
  1. Rerun発生（ボタン押された）             1. Rerun発生（スライダー動いた）
  2. st.button が True になる                2. st.button が False に戻る
  3. [🎉 送信完了！] ──▶ 表示される！       3. [🎉 送信完了！] ──▶ 画面から消滅する！😱

どうやって対策するのか？¶

ボタンを押した「状態」を維持するためには、画面が再起動（Rerun）してもデータが消えない特別な保管庫である 「セッション状態（st.session_state）」 という高度な仕組みを使う必要があります。 今回の基礎クラス（第5回）では、「ボタンは、押したその瞬間の一時的なアクション（おまじないを実行するなど）にのみ使い、計算結果の表示などの状態キープにはスライダーやチェックボックスを主役に使う！」というルールを覚えておきましょう。

  • Rerun（再実行）システム: ユーザーが操作を行うたびに、Pythonのコードが1行目から最後まで毎回すべて最初から実行され直す、Streamlitの最も重要なお約束ルール。

  • st.buttonの罠: ボタンは「押された瞬間だけTrueになり、他の操作をするとFalseに戻る」という、Rerunが原因で起きる初心者定番の仕様。

  • st.metric / st.columns: 画面を並列に並べ、KPIメーターを表示する、ダッシュボード制作のレイアウト手法。

❓ よくあるエラーと対処法（FAQ）¶

  • Q. localtunnel のURLを踏むと、真っ白な画面のまま「504 Gateway Timeout」と表示されてアプリが開きません。

    • A. Colab上でStreamlitの起動セルが一時停止してしまっているか、途中でエラー停止している可能性があります。Colabに戻り、アプリ起動セル（手順C）をもう一度停止ボタンを押してから再起動し、新しく発行されたURLを踏み直してみてください。

  • Q. app.pyを書き換えても、画面が前の状態のまま変わりません。

    • A. 手順A（%%writefile app.py）のセルを再実行し忘れているか、Web画面の右上にある「Rerun（再読み込み）」をクリックし忘れています。コードを書き換えたら、必ず「Colabでセル実行」➡「Web画面でRerun」の2アクションを行う癖をつけましょう！

  • Q. スライダーを動かそうとすると、画面全体が「TypeError: ...」や「NameError: ...」という赤いエラーで埋め尽くされます。

    • A. 鋭いバグですね！それはスライダーが動いたことによる「Rerun（再実行）」の際、コードのどこかで定義し忘れた変数や、データ型の不整合（文字列に数値を掛け算しようとするなど）が発生し、Pythonがパニックを起こしたためです。エラーメッセージに表示されている「何行目でエラーが起きているか」をじっくり読み、お掃除しましょう。分からなければ、そのエラーを丸ごと生成AIに投げるのも賢い解決策です！
