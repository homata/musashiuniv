分類モデルとクラスタリング

教師あり学習「分類」モデルの真髄¶

分類（Classification）とは何か？（回帰との違い）¶

前回学んだ「回帰（Regression）」は、アイスコーヒーの売上杯数（28杯、45杯、52杯...）といった「途切れなく連続する数値（連続値）」を当てるのが目的でした。

それに対し、本日学ぶ「分類（Classification）」は、「このメールは迷惑メール（1）か、普通メール（0）か」「このお客様はリピーターになってくれる（1）か、もう来ない（0）か」という、「あらかじめ決められたカテゴリ（離散値）」のどれに当てはまるかを予測します。

▼ 回帰（Regression）の目的：
  [ 気温 32度 ]  ──▶  【 AIモデル 】  ──▶  「今日の売上は 235,000円 です！」（具体的な数値をピンポイントで予測）

▼ 分類（Classification）の目的：
  [ 年齢: 21歳, 来店3回 ] ──▶  【 AIモデル 】  ──▶  「リピーターになる確率 85% ＝ 【リピーター(1)】に分類！」

決定木（Decision Tree）の直感的イメージ¶

分類を行うアルゴリズムにはたくさんの種類がありますが、その中で強力なのが「決定木（Decision Tree）」です。

決定木は、データの中に隠れているパターンを分析し、コンピュータが自動的に「最もきれいにデータを仕分けられるYes/Noの質問リスト」を作ってくれるアルゴリズムです。その形が、木が枝分かれしているように見えるため「決定木（意思決定の木）」と呼ばれます。

例えば、あるカフェの顧客データから「リピーターになる人（1）」と「1回きりの人（0）」を見分ける決定木をAIが作ると、以下のようなフローチャートが自動生成されます。

【決定木の枝分かれ（イメージ図）】

                  [ 🌳 ルートノード（出発点） ]
                   お客様はリピーターになるか？
                               │
                 ❓ 質問1: 来店回数は 3回以上？
                     /                       \
               (Yes) /                       \ (No)
                    /                         \
      ❓ 質問2: ケーキを注文した？          【 1回きりの顧客(0) 】
            /               \               (※来店回数が少ないため)
      (Yes) /               \ (No)
           /                 \
  【 超VIP(1) 】        【 リピーター(1) 】
  (高確率で再来店)      (普通のリピーター)

AIは、過去のデータをすべて見比べながら、「どういう順番で、どのような質問をすれば、最もすっきりと1と0を仕分けることができるか」を自動的に学習（.fit()）してくれるのです。

実践：決定木の構築と過学習（木の深さ）のコントロール¶

それでは、実際に決定木モデルを構築してみましょう！ 今回は、カフェの「年齢」と「1回あたりの購入金額」という2つの情報から、そのお客様が「リピーター（1）」になるか「1回きりのライト顧客（0）」になるかを予測する決定木モデルを作成します。

まずは、おなじみの「ダミーデータ自動生成」を行い、データを学習用とテスト用に分割します。

# 1. 模擬データの作成とデータ分割
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split

np.random.seed(12)
n_customers = 100

# 100人分のお客様の「年齢」と「平均支払金額（円）」
age = np.random.randint(18, 65, n_customers)
spend = np.random.randint(300, 2500, n_customers)

# 年齢が若くて支払金額が高い人、または年齢が高くて支払金額がそこそこの人が
# リピーター（1）になりやすいというルール（パターンのベース）を定義
repeater = []
for a, s in zip(age, spend):
    if a < 35 and s > 1200:
        repeater.append(1)
    elif a >= 35 and s > 800:
        repeater.append(1)
    else:
        # 多少のノイズ（ランダムさ）を加えて現実らしくする
        repeater.append(1 if np.random.rand() > 0.85 else 0)

# データフレーム化
df_customer = pd.DataFrame({
    "年齢": age,
    "支払金額": spend,
    "リピーター": repeater
})

print("--- カフェの顧客データ（先頭5名分） ---")
display(df_customer.head())

# 説明変数 X（年齢、支払金額）と目的変数 y（リピーター：1か0か）に分ける
X = df_customer[["年齢", "支払金額"]]
y = df_customer["リピーター"]

# データを「学習用（75%）」と「テスト用（25%）」に分割
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=42)
print(f"データ分割完了：学習用 {len(X_train)}名分, テスト用 {len(X_test)}名分")

決定木モデルの学習と「木の深さ」の制限¶

決定木を作る際、最も注意しなければならないパラメータが「木の最大深さ（max_depth）」です。

もし、この制限をかけずにAIに学習させると、AIは「100%完全に1と0を仕分けられるまで、無限に細かく複雑な質問」を作り続けてしまいます。 これは、過去のデータの細かいノイズ（たまたまその日だけ機嫌が悪かったお客様、など）まで丸暗記してしまい、新しいデータ（テストデータ）が来たときに全く予測が当たらなくなる過学習（オーバーフィッティング）を引き起こします。

そのため、実務では max_depth（質問を繰り返す回数の上限）を 3回や4回程度に制限する のが鉄則です。

# 2. 決定木モデルの定義・学習・予測
from sklearn.tree import DecisionTreeClassifier # 決定木分類器

# max_depth=3（質問は最大3階層まで）に制限して過学習を防ぎます
clf_tree = DecisionTreeClassifier(max_depth=3, random_state=42)

# 【超重要】学習用データを使って、AIに「最適な質問リスト」を考えさせます
clf_tree.fit(X_train, y_train)

# 勉強した成果を使い、一度も見たことがないテスト用の客層に対して予測を実行
y_pred = clf_tree.predict(X_test)

print("AIによるリピーター予測（最初の5名分）：", y_pred[:5])
print("実際のテスト用データの正解（最初の5名分）：", y_test[:5].values)

決定木の最大のメリット：「なぜ？」が説明できる（可視化）¶

決定木の素晴らしいところは、他のAIモデル（複雑なニューラルネットワークなど）と違い、「なぜその予測をしたのか」という思考のプロセスを、人間が完全に見て納得できるという点にあります。これを目で見える図（ツリー構造）として書き出してみましょう。

# 3. 決定木の構造を綺麗にビジュアル表示する
from sklearn.tree import plot_tree
import matplotlib.pyplot as plt
import japanize_matplotlib

fig, ax = plt.subplots(figsize=(14, 8))
plot_tree(
    clf_tree,
    feature_names=["年齢", "支払金額"], # 質問に使った説明変数名
    class_names=["リピートなし", "リピートあり"], # 分類結果のグループ名
    filled=True, # 確率が高い方に色を塗って分かりやすくする
    rounded=True, # 角を丸くする
    ax=ax
)
plt.title("AIが自動構築した『リピーター判定』決定木フローチャート", fontsize=16)
plt.show()

描画された図の一番上のボックス（根っこ）を見てみましょう。 AIが「データを最もきれいに2分割できる最高の最初の質問」として、例えば「支払金額 <= 973.5円」といった具体的な数値を自動で弾き出し、そこから見事に枝分かれ（ツリー）を構築している様子が視覚的に確認できたはずです！

分類モデルの成績表：「評価指標」の正しい読み解き方¶

予測モデルが完成したら、そのモデルの「実力テスト（評価）」を行います。 しかし、分類モデルの評価は、前回の回帰（MAEや\(R^2\)）とは異なる、非常に重要なビジネス上のトラップが潜んでいます。

① 単純な「正解率（Accuracy）」だけを信じてはいけない罠（不均衡データ）¶

多くの人は、AIの評価として「正解率（Accuracy）＝全体の何％の予測が当たったか」だけを見てしまいがちです。 しかし、これは実務において最悪の意思決定を招く原因になります。

例えば、100人中1人だけが感染している「超難病（確率1%）」を発見する診断AIを作るとします。 このAIのプログラムを極めてシンプルにし、「中身を一切見ず、誰が来ても全員に『あなたは健康（陰性）です』と答えるだけの怠け者AI」にしたとします。

この怠け者AIの正解率はどうなるでしょうか？ 100人中99人は本当に健康なので、なんと「正解率 99.0%」の超優秀に見えるAIが誕生してしまいます。しかし、一番見つけなければならない「1名の難病患者」を完全に見落としているため、医療現場では使い物にならないどころか、人命に関わる欠陥品です。

このように、データの比率に偏りがある（不均衡データ）場合、正解率（Accuracy）は使い物になりません。そこで、実務では以下の「混同行列（Confusion Matrix）」を頭に叩き込む必要があります。

② 混同行列（Confusion Matrix）の直感的4分類¶

混同行列とは、実際の正解（1か0か）と、AIの予測（1か0か）の組み合わせを2✕2の表にまとめたものです。

                  【 AIの予測結果 】
                 予測＝1           予測＝0
            ┌─────────────────┬─────────────────┐
  本物＝1   │  ① 真陽性 (TP)  │  ② 偽陰性 (FN)  │
            │  （大アタリ！） │ （見落とし！）  │
実際の正解  ├─────────────────┼─────────────────┤
  本物＝0   │  ③ 偽陽性 (FP)  │  ④ 真陰性 (TN)  │
            │ （オオカミ少年）│  （安全クリア） │
            └─────────────────┴─────────────────┘

  • ① 真陽性 (TP: True Positive)：本物が「1」で、AIも「1」と予測。文句なしの大アタリ！

  • ② 偽陰性 (FN: False Negative)：本物は「1」なのに、AIは「0」と予測。病気や解約をスルーしてしまった最も危険な「見落とし（見逃し）」。

  • ③ 偽陽性 (FP: False Positive)：本物は「0」なのに、AIは「1」と予測。何もないのに「狼が来たぞ！」と騒いでしまった「空振り（オオカミ少年・誤検知）」。

  • ④ 真陰性 (TN: True Negative)：本物が「0」で、AIも「0」と予測。何もないことを正しく見破った「安全クリア」。

③ 適合率（Precision）と再現率（Recall）のビジネス・トレードオフ¶

この混同行列をもとに、不均衡データでも騙されないための「2大指標」が定義されます。この2つは天秤（トレードオフ）の関係にあり、ビジネスの目的によってどちらを重視するかを私たちが選ぶ必要があります。

1. 適合率 (Precision) ＝ 「空振りを減らしたい！」¶

  • 意味：AIが「1（リピーターになる）」と予測した人たちの中で、「本当に1だった本物の割合」。

  • 式： \(\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}}\)

  • 重視すべきビジネス場面：

    • 「無駄なコストを極限まで減らしたいとき」。

    • 例：予算が限られているため、リピート確率が極めて高い人だけに限定して「2000円割引の超高額クーポン」をDM郵送したい。もしAIの予測が空振り（偽陽性：リピートしない人に送ってしまう）すると、郵送費とクーポン代が丸ごと赤字になってしまいます。このような時は、空振りを減らすために「適合率」を最重視します。

2. 再現率 (Recall) ＝ 「見落としを減らしたい！」¶

  • 意味：本当に「1（リピーターになるはず）」だった人たちの中で、AIがどれだけ「見落とさずに1だと見破れたかの割合」（検出率とも呼ばれます）。

  • 式： \(\text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}}\)

  • 重視すべきビジネス場面：

    • 「見落とした時のリスクやダメージが、取り返しのつかないほど巨大なとき」。

    • 例①：がんの早期発見AI。空振り（健康なのに『再検査です』と脅してしまう）は後で検査すれば誤解が解けますが、見落とし（がんがあるのに『健康です』とスルーする）は患者の命に関わります。

    • 例②：クレジットカードの不正利用検知や、顧客の解約予兆検知。「怪しい行動」を少しでも多くあぶり出し、多少の空振りがあっても、本物の不正や解約を1件残らず食い止めたいときは、「再現率」を限界まで高める必要があります。

それでは、先ほど作ったカフェの決定木モデルの成績表を、scikit-learnを使って一瞬で計算してみましょう。

# 4. 評価指標を一括計算する
from sklearn.metrics import accuracy_score, precision_score, recall_score, confusion_matrix

print("--- AIモデルの成績表（実力テスト結果） ---")
# 1. 正解率（Accuracy）
acc = accuracy_score(y_test, y_pred)
print(f"① 正解率 (Accuracy) : {acc:.3f}  (全体のうち当たった割合)")

# 2. 適合率（Precision：空振りを防ぐ力）
prec = precision_score(y_test, y_pred)
print(f"② 適合率 (Precision): {prec:.3f}  (AIが『1』と予言した中の本物率)")

# 3. 再現率（Recall：見落としを防ぐ力）
rec = recall_score(y_test, y_pred)
print(f"③ 再現率 (Recall)   : {rec:.3f}  (本物の『1』をどれだけ検知できたか)")

# 4. 混同行列（表の形式で出力）
cm = confusion_matrix(y_test, y_pred)
print("\n▼ 混同行列（Confusion Matrix）の実数内訳:")
cm_df = pd.DataFrame(cm, index=["実際の0（非リピ）", "実際の1（リピ）"], columns=["予測の0", "予測の1"])
display(cm_df)

テスト結果の適合率や再現率の数値を見ながら、「このAIは、クーポンの誤送付を防ぐのに向いているか？ それとも優良顧客の流出を食い止めるのに向いているか？」を考えることが大切です。

分類問題における正解・不正解のパターン¶

分類問題における実測値と予測値の関係性は以下のマトリクスで表現できます。

正（実測） 負（実測）
正（予測） TP FP
負（予測） FN TN

モデルが正しく予測したパターン → 頭にT(True)がつく

  • TP(True Positive)：実測値と予測値の両方が正であったもの

  • TN(Ture Negative)：実測値と予測値の両方が負であったもの

モデルが間違って予測したパターン → 頭にF(False)がつく

  • FP(False Positive)：実測値が負なのに、誤って正と予測値したもの（誤検知、偽陽性）

  • FN(False Negative)：実測値が正なのに、誤って負と予測値したもの（偽陰性）

どの数値を用いるかが評価指標を見るときのポイントになります。

Accuracy(正解率)
読んで字のごとく、全体のうちどれだけ正解があるかだ。 「予測がどれだけ正しかったか」を見る指標

(TP + TN) / (TP + TN + FP + FN)
=>  予測が正しかった数 / 予測したデータ数

Precision(適合率）
無駄打ちをなくすのが目標
Precisionは「正と予測したものが、どれだけ正しかったか」を見る指標

英語でPreciseは精密な、という意味があることからも精度のように厳密に予測の性能を図ることができる。
再現率とはトレードオフの関係にある。

TP / (TP + FP)
=>  正と予測した中で実際に正であったものの数 / 正と予測したものの数

Recall(再現率) 機会損失をなくすのが目標
Recallは「実際に正であったもののうち、どれだけ正と予測できたか」を見る指標

TP / (TP + FN)
=> 実際に正であったものの中で正と予測できた数 / 実際に正であったものの数

F値(F-measure/F1スコア) F値はPrecisionとRecallの調和平均
Recall(再現率)とPrecision(適合率)はトレードオフの関係にあることから、これらの調和平均をとって性能指標とすることが多い。 これをF値(F-measure/F1スコア)と呼ぶ。

F1score = (2 x (適合率 x 再現率)) / (適合率 + 再現率)

教師なし学習「クラスタリング」の衝撃¶

教師なし学習（Unsupervised Learning）の役割¶

これまでの学習は、データの中に必ず「売上杯数」や「リピーターフラグ（1/0）」といった「正解ラベル（答え）」がセットされていました。 しかし、現実社会にあるデータの9割以上には、そのような都合の良い正解ラベルは付いていません。

例えば、あなたは新しくカフェの店長に就任し、手元に「過去1万人分の購入データ（来店回数と支払金額）」という大きなエクセルシートがあるとします。 正解ラベルはありませんが、ここから「うちのカフェには、どのようなタイプのお客さんたちが集まっているのか？」という顧客のプロファイリング（顧客セグメンテーション）を行いたいとします。

ここで活躍するのが、教師なし学習（Unsupervised Learning）です。 教師なし学習のAIは、正解を与えられなくても、自らデータの点々の「距離感（特徴）」をじっくり観察し、「似た性質を持つ者同士のグループ」を自動的にあぶり出して分類してくれます。

【教師あり（分類）と教師なし（クラスタリング）の違い】

▼ 教師あり学習（分類）：あらかじめ「正解の境界線」を教わって分ける
  [ 🔴と🔵が混ざった過去データ ]  ──(学習)──▶  「ここが赤と青の境目（境界線）だ！」

▼ 教師なし学習（クラスタリング）：正解はない。なんとなく「集まっている塊」を見つけて分ける
  [ ⚫と⚫が混ざった過去データ ]  ──(学習)──▶  「なんとなく、左上に1つの塊、右下に1つの塊があるな！」

K-Means（K平均法）の直感的なステップ¶

教師なし学習の中で、最も有名で強力なグループ分けアルゴリズムが K-Means（K平均法 / ケー・ミーンズ） です。 K-Meansの「K」とは、「データを何個のグループに分けたいか」というグループの数を表します（私たちが事前に設定します）。

K-Meansは、まるで学校の席替えでリーダーがクラスメイトを自分のグループに引き寄せるように、以下の4つのステップを高速で繰り返すことで、完璧なグループ分けを自動的に完成させます。

K-Meansがグループを決める「4つのステップ」¶

ステップ 1：リーダー（重心）をランダムに配置する¶

あなたが「3つのグループに分けたい（K=3）」と命令すると、AIは真っ白なデータ空間の上に、3つの「リーダーのピン（重心：Centroid）」をランダムにグサッと立てます。

  [ データの点々 ]
     *    *              * 
        *     ▲(赤)        * *
                ▲(青)
     * *   ▲(緑)

ステップ 2：一番近いリーダーのグループに所属する（割り当て）¶

すべてのデータの点々は、自分から一番距離が近いリーダーを見つけ、「私は赤グループに入ります」「僕は緑グループ！」と、自動的に所属を決めます。

     🔴   🔴             🔵 
        🔴               🔵 🔵
             
     🟢 🟢

ステップ 3：グループの中心地にリーダーが引っ越す（重心の再計算）¶

所属が決まったら、リーダーは「よし、みんなの真ん中の位置（平均値）を計算して、そこに私が引っ越そう！」と、メンバーの中心地へと移動します。これにより、リーダーの位置がブラッシュアップされます。

       *   *(新赤リーダー)   * 
        *                *(新青リーダー)*
             
     * *(新緑リーダー)

ステップ 4：リーダーが動かなくなるまで「2」と「3」を繰り返す！¶

リーダーが動いたので、もう一度ステップ2に戻り、データの点々は「あ、リーダーの位置が変わったから、私は今度は青グループの方が近いな」と所属を決め直します。 このステップ2と3を何度も何度も繰り返すと、やがてリーダーが全く動かなくなります。ここで「クラスタリング完了」となります。

K-Meansの実践ハンズオンと「エルボー法」¶

それでは、K-Meansを使って、カフェの顧客100名を自動的にグループ分けしてみましょう！ データは「来店回数」と「平均支払金額（客単価）」の2つの特徴だけを持つ、ラベルのない散布図データです。

# 1. データの作成（来店回数と客単価）
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

np.random.seed(42)

# カフェに集まる、性質の異なる3つのグループの顧客層を模擬的に生成します
# グループA: 来店は少ないが、1回の支払額が非常に高い「たまの贅沢・ご褒美層」
g_a_freq = np.random.normal(3, 1, 30)
g_a_spend = np.random.normal(1800, 200, 30)

# グループB: 毎日のように来るが、支払額は安い「お仕事・ノマド常連層」
g_b_freq = np.random.normal(15, 2, 40)
g_b_spend = np.random.normal(450, 80, 40)

# グループC: 来店も支払額もそこそこの「標準的なライト層」
g_c_freq = np.random.normal(8, 1.5, 30)
g_c_spend = np.random.normal(1000, 150, 30)

# 合体して1つの顧客データフレームにします
df_customer_raw = pd.DataFrame({
    "来店回数": np.concatenate([g_a_freq, g_b_freq, g_c_freq]),
    "平均支払金額": np.concatenate([g_a_spend, g_b_spend, g_c_spend])
})

# データの可視化（最初は誰がどのグループか分からない真っ黒な点々です）
plt.scatter(df_customer_raw["来店回数"], df_customer_raw["平均支払金額"], color="gray")
plt.title("カフェ顧客データ（初期状態：正解ラベルなし）")
plt.xlabel("来店回数 (回)")
plt.ylabel("平均支払金額 (円)")
plt.grid(True)
plt.show()

K-Meansを動かす前の「標準化（スケーリング）」のルール¶

クラスタリングを動かす前に、前回の重回帰の最後でも紹介した「標準化（データのスケールを整える）」を実行しなければなりません。

なぜなら、K-Meansは点と点の「物理的な距離」を測ってグループ分けするからです。 今回のデータを見ると、横軸の「来店回数」は高々 1〜20 程度の狭い範囲ですが、縦軸の「支払金額」は 300〜2500 という巨大な桁数の範囲を動きます。 このままの状態で距離を計算すると、AIは「縦軸の支払金額のちょっとのズレ（例えば100円の差）」をもの凄く遠い距離だと勘違いし、横軸の来店回数の違いをほぼ無視して、縦方向の細長いスライスだけでグループ分けをしてしまいます。

これを防ぐために、両方の列を「平均が0、標準偏差（ばらつき）が1」の平等なスケールに変換（標準化）してから、K-Meansに入力します。

# 2. データの標準化と K-Means の実行
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans

# ① データを平等なスケールに標準化します
scaler = StandardScaler()
X_scaled = scaler.fit_transform(df_customer_raw)

# ② K-Meansモデルの定義（3つのグループに分けたいので n_clusters=3）
kmeans = KMeans(n_clusters=3, random_state=42, n_init=10)

# ③ 学習とグループ割り当ての実行
# 教師なし学習なので、引数に y (正解) は渡さず、X_scaled（ヒント）だけを渡します！
# .fit_predict() を使うと、学習と同時に各データのグループ番号（0, 1, 2）を返してくれます。
customer_clusters = kmeans.fit_predict(X_scaled)

# 元のデータフレームに「AIが自動で決めたグループ番号」を追加
df_customer_raw["グループ番号"] = customer_clusters

print("--- AIが自動でグループ分けした結果（先頭5名分） ---")
display(df_customer_raw.head())

AIが自動的に導き出したグループ番号ごとに、色を変えて散布図を再描画してみましょう。

# 3. クラスタリング結果のプロット
plt.figure(figsize=(8, 6))
# グループ番号（0, 1, 2）ごとに色を変えてプロット
for i in range(3):

plt.title("K-Meansによる顧客自動セグメンテーション（3グループ）")

人間が「この人はVIP、この人はライト」と教えることすらしていないのに、コンピュータが距離感から見事に「来店は少ないが高額なグループ」「常連だけど安価なグループ」「平均的なグループ」の3つの塊を自動で看破し、色分けしたのが確認できたでしょうか？ これが教師なし学習の絶大なパワーです。

グループ数はいくつに設定すればいいの？「エルボー法（Elbow Method）」¶

K-Meansを使うとき、誰もが「グループ数（K）は本当に3個でいいのか？2個や4個の方がいいのでは？」と悩みます。正解のラベルがないため、客観的に評価するのが難しいためです。

この疑問を解決するアプローチが、エルボー法（Elbow Method）です。

K-Meansモデルには、学習が終わると inertia_（インナーシャ：グループ内の歪み・データのバラツキの合計値） という数値が自動で保存されます。 グループ数を「1個、2個、3個……」と増やしていくと、当然グループが細分化されるため、グループ内のバラツキ（inertia_）はどんどん小さくなっていきます。

この「グループ数」と「バラツキの数値」をグラフにプロットした時、「これ以上グループを増やしても、大してバラツキが減らなくなる境界線（グラフがガクッと折れ曲がり、まるで人間の『肘（Elbow）』のように見える部分）」があります。この折れ曲がりポイントを最適なグループ数（K）と判断するのがエルボー法です。

# 4. エルボー法による最適なグループ数の探索
inertia_list = []
k_range = range(1, 8) # グループ数Kを 1から7まで試してみる

for k in k_range:
    # 各Kでモデルを作り、学習させます
    km_test = KMeans(n_clusters=k, random_state=42, n_init=10)
    km_test.fit(X_scaled)
    # 歪み（inertia_）をリストに格納
    inertia_list.append(km_test.inertia_)

# エルボー図を描画
plt.plot(k_range, inertia_list, marker="o", color="purple")
plt.title("最適なグループ数を見極める『エルボー図』")
plt.xlabel("設定したグループ数 (K)")
plt.ylabel("グループ内のデータのバラツキ合計 (Inertia)")
plt.grid(True)
plt.show()

グラフを見てください。 Kが「3」の部分を境目にして、それ以降（4, 5, 6）は傾きが緩やかになり、バラツキがあまり減らなくなっている（肘のように曲がっている）のが見つかったでしょうか？ エルボー法により、「このカフェの顧客データは、科学的に『3つ』に分類するのが最も美しいグループ数である」という客観的な根拠を、説得力を持って上司やクライアントにプレゼンすることができます！

練習問題 1: 「回帰」と「分類」の仕分け（理論）¶

  2. カフェの「来週の土曜日の売上金額（円）」を予測する。

  3. アップロードされた写真が「ショートケーキ」「モンブラン」「プリン」のどれであるかを予測する。

  4. カフェに滞在する「お客様の平均時間（分）」を予測する。

👉 練習問題 1 の解答を見る

  • 正解: 1 と 3

  • 解説:

    • 1 は「注文する／しない」という2カテゴリの予測、3 は3種類のケーキというカテゴリの予測なので、これらはすべて分類（Classification）の問題です。

    • 2 は「売上金額（円）」という連続する数値を当てるため、4 は「滞在時間（分）」という連続する数値を当てるため、これらは回帰（Regression）の問題に該当します。

練習問題 2: 正解率（Accuracy）の甘い罠（理論）¶

あなたはカフェの会員登録アプリで「退会しそうな人を事前に発見して引き止めるAI」を構築しました。 このカフェの会員の退会率は非常に低く、年間でわずか「0.5%（200人に1人）」しか退会しません。

あなたが作った予測モデルの精度を測定したところ、「正解率（Accuracy）が 99.5%」という驚異的な数値が出ました。 しかし、実際に中身を詳しく見ると、このAIは「退会しそうな人を1人も発見できていない」ことが分かりました。なぜこのような現象が起きてしまったのか、理由を説明してください。

👉 練習問題 2 の解答を見る

  • 解答例:

    • このデータは退会する人が0.5%、退会しない人が99.5%という極端に偏った「不均衡データ」である。

    • AIが全員に対して単に「この人は退会しません（0）」と、何一つ考えずにただ同じ予測を繰り返す（怠け者モデル）だけで、全体の99.5%の予測が当たってしまい、見かけ上の正解率（Accuracy）が99.5%になってしまった。

    • 実際のビジネスで本当に見つけなければならない「退会しそうなわずか0.5%の人（見落とし）」を一切捉えられていないため、このAIは実務的には価値がまったくない。

  • 解説:

    • 不均衡データに対して正解率（Accuracy）だけを評価に使うと、こうした見かけの数値に騙される「不均衡データの罠」に陥ります。こうした場合は、後述する適合率や再現率、混同行列を必ずセットで評価する必要があります。

練習問題 3: 適合率と再現率、どっちを優先？（データリテラシー）¶

あなたが開発した「カフェのクレジットカードの不正利用を自動的に検知・ブロックするAIモデル」があるとします。 この不正検知システムを実務で運用するにあたり、以下の2つのリスクを考えました。

  • リスクA（空振りのリスク）：普通の健全なお客様の決済を、AIが「不正利用かもしれない！」と誤検知（空振り）してしまい、一時的に決済をロックして不快な思いをさせてしまう。

  • リスクB（見落としのリスク）：本物の泥棒がクレジットカードを不正に大金を使ってしまっているのに、AIが「普通のお客様の決済です」とスルー（見落とし）してしまい、店とカード会社に数百万の損害が出る。

  1. 今回のクレジットカード不正検知ビジネスにおいて、極限まで減らさなければならないのはリスクAとリスクBのどちらでしょうか？

  2. そのリスクを避けるために、私たちが最大まで引き上げるべきAIモデルの評価指標は、「適合率（Precision）」と「再現率（Recall）」のどちらでしょうか？

👉 練習問題 3 の解答を見る

  • 正解:

    1. 極限まで減らすべきリスク：リスクB（本物の不正利用の見落とし）

    2. 最大まで高めるべきAIの評価指標：「再現率（Recall）」

  • 解説:

    • カードの不正利用は、1件見落とすだけで数百万の壊滅的な実害が発生します。多少の空振り（健全なお客様を疑って確認の手間を取らせてしまう：リスクA）をしてでも、本物の泥棒を「絶対に1件も見落とさない」ようにモデルを設定する必要があります。

    • したがって、見落としを限界までゼロに近づける指標である 「再現率（Recall、検出率）」 を最優先で引き上げるチューニングを行うのが、実務における正しいデータリテラシーです。

データサイエンスのプロジェクトを進める上で、「教師あり学習」と「教師なし学習（クラスタリング）」の最も決定的なデータの持ち方の違い（何が存在し、何が存在しないか）を説明してください。

👉 練習問題 4 の解答を見る

  • 正解: データのなかに「正解ラベル（ターゲット・答えとなるy）」が含まれているか、含まれていないかの違い。

  • 解説:

    • 教師あり学習：データの中に「売上高」や「リピーター判定（1/0）」といった明確な正解の列（y）があらかじめ用意されており、それをヒントから当てるルールを学びます。

練習問題 5: K-Meansにおける「標準化」の必要性（理論）¶

K-Means（K平均法）を動かす前に、データの各列のスケールを揃える「標準化（平均0、標準偏差1にする変換）」を行う必要があるのはなぜですか？ 「距離」というキーワードを必ず含めて説明してください。

👉 練習問題 5 の解答を見る

  • 解答例:

    • K-Meansは、データ同士の「距離（空間的な直線距離）」を測ることによってグループ分けを計算するアルゴリズムだから。

    • 標準化をせずに「単位や桁数が著しく異なるデータ（例：1〜20の来店回数と、300〜2500の支払金額）」をそのまま計算に入れると、桁数の大きい支払金額のわずかな差だけで「距離がとても遠い」とAIが過剰に判定してしまい、来店回数の違いをほとんど無視した歪んだグループ分けになってしまうため、データのばらつきのスケールを均等に揃える必要がある。
