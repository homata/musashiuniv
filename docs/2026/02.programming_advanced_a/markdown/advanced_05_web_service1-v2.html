第5回 Webサービスの活用1：StreamlitによるWebアプリ開発の基礎（100分授業用）¶

皆さん、こんにちは！プログラミング応用A（コンピューティング応用G）、第5回の講義です。担当の教員です。 前回（第4回）は、Pandasを使って「平均値の罠」を見破り、データのばらつき（標準偏差）や変数間の関係性の強さ（相関係数）を可視化する「データ解析」の基本を学びました。皆さんのデータリテラシーは確実にプロのレベルへと近づいています。

今回からはいよいよ、データ分析をさらに一歩進めて、**「Webサービスの活用（Webアプリケーション開発）」**というエキサイティングな領域に突入します！ 具体的には、Pythonだけで本格的かつモダンなWebアプリケーションを構築できる魔法のライブラリ Streamlit（ストリームリット） を使い、あなた専用の「データダッシュボード」を作っていきます。

「HTMLやCSSは難しそう…」「Webサーバーって何？」と思うかもしれませんが、大丈夫です！ Streamlitを使えば、そうした難しいデザインのコードは一切書く必要がありません。Pythonのコードを数行書くだけで、オシャレなボタンやスライダー、グラフが画面に自動的に配置されます。

今日は、Google Colab上でWebアプリを起動するための特別な手順（トンネリング）から、基本的なボタンや入力欄（ウィジェット）の配置方法まで、100分間かけて丁寧に学んでいきます。自分で作ったプログラムがWebブラウザ上で「アプリ」として動く感動を、ぜひ味わってください！

🎯 本日の到達目標 (約5分)¶

この100分の授業が終わるころには、以下のことができるようになります。

  1. Webアプリ化（ダッシュボード化）の目的と意義（なぜデータをアプリとして公開するのか、誰が使うのか）を説明できる。

  2. Google Colab上でStreamlitを安全に起動し、ローカルトンネル（localtunnel）を使ってスマホやブラウザからアクセスできる。

  3. Streamlitの基本コマンド（タイトル、テキスト出力、マークダウン、インジケーター表示）を使い分けてWeb画面を構成できる。

  4. 入力用ウィジェット（ボタン、スライダー、テキスト入力、セレクトボックス、ラジオボタン）を配置し、ユーザーの操作に応じて画面が変わるインタラクティブ（対話型）なアプリが作れる。

  5. Streamlit特有の「上から下へ毎度再実行される（Rerun）」仕組みを理解し、ボタンを押した時の挙動の罠をデバッグ・回避できる。

5.1 なぜデータを「アプリ」にするのか？ (約20分)¶

5.1.1 データ分析を「社会に届ける」ための課題¶

これまでの授業で、私たちはデータを収集し、Pandasで集計し、Matplotlibでグラフを描くことができるようになりました。 しかし、その素晴らしい分析結果を「プログラミングを全く知らない会社の上司、クライアント、あるいは一般のお客様」に見せたいとき、どのように共有すればいいでしょうか？

  • 「Pythonのコード（Colabのノートブック）をそのまま送る」

    • ❌ 相手はPythonのコードを読めませんし、Colabの実行方法も知りません。余計なコードが並んでいるだけで「難しそうだ」と敬遠されてしまいます。

  • 「グラフを画像（PNG）にして、メールやスライドで送る」

    • ❌ 画像は「静止画」です。「客数を150人から200人に増やしたときの売上はどうなるの？」とか「江古田店だけの売上グラフを見たい」といった、相手の「もしも（シミュレーション）」にその場で応えることができません。

  • 「Excelファイルを共有する」

    • ❌ 相手が数式や関数をうっかり書き換えて壊してしまう危険があります。また、スマートフォンやタブレットからだと画面が崩れて操作しづらいという難点があります。

一番良い解決策は、**「誰でもスマホやパソコンのブラウザからアクセスして、ボタン一つでデータを絞り込んだり、スライダーで数値を動かして未来を予測できる『Webアプリ』にして渡すこと」です。これを「データダッシュボード」**と呼びます。

【データ共有の進化ステップ】

  [ 段階 1: 生データ ] ──▶ [ 段階 2: 静止画グラフ ] ──▶ [ 段階 3: Webアプリ（ダッシュボード）]
   エクセルの数字の羅列        報告用スライドの画像         スライダーを動かすとグラフが
   (見ても意味がわからない)    (自分で条件を変えられない)   リアルタイムに自動変形する！(双方向)

5.1.2 Streamlitとは何か？¶

通常、Webアプリケーション（YouTubeやTwitter、企業のダッシュボードなど）をゼロから作成するためには、非常に多くのプログラミング言語を習得しなければなりません。

  1. HTML（画面の骨組みを作る）

  2. CSS（画面の色やデザイン、レイアウトを整える）

  3. JavaScript（ボタンを押した時の「動き」をつける）

  4. Webサーバーの構築（バックエンド：PythonやNode.js、Rubyなど）

これらをすべて一人で習得するには、何百時間もの学習コストが必要です。データ分析者や文系学生が「ちょっとデータをオシャレに見せたい」だけなのに、これらを学ぶのは現実的ではありません。

そこで登場したのが、Pythonライブラリ Streamlit（ストリームリット） です！

【伝統的な開発方法 vs Streamlit】

▼ 従来のWeb開発（挫折率：極大 😱）
  Python（分析） ＋ HTML/CSS（デザイン） ＋ JavaScript（挙動） ＋ サーバー構築 ＝ 複雑すぎる！

▼ Streamlitを使った開発（効率性：極大 😍）
  [ 🐍 Pythonコードを数行書くだけ ] ──▶ [ 🎨 Streamlitが自動変換 ] ──▶ [ 💻 プロ級のオシャレWebアプリ ]

5.1.3 Streamlitの画期的な3大特徴¶

  • HTML/CSS/JavaScriptが一切不要

    • Pythonのコードを書くだけで、Streamlitが裏側で自動的に美しいWebデザイン（マテリアルデザイン）に変換してブラウザに表示してくれます。スマホ画面の自動対応（レスポンシブデザイン）も最初から完備されています。

  • 直感的なUI（ユーザーインターフェース）コンポーネント

    • st.slider() と1行書くだけでオシャレなスライダーが配置され、st.selectbox() と書くだけで綺麗なドロップダウンメニューが生成されます。

  • リアクティブ（即時反応）な実行システム

    • スライダーを「10」から「11」に動かした瞬間、プログラムが自動で瞬時に再計算を行い、画面のグラフや文字を滑らかに更新します。JavaScriptの「お固い同期処理」を書く必要は全くありません。

5.2 Google Colab上でStreamlitを動かす魔法（環境構築） (約30分)¶

通常、Streamlitは自分のパソコン（ローカル環境）のコマンドプロンプトやターミナルで起動します。 しかし、この授業では誰もがインストールなしで同じ環境で学べるよう Google Colab を使っています。

Colabは「Googleのクラウド上にある仮想のパソコン」なので、そこで動かしたWebアプリはそのままでは私たちのパソコンの画面には表示されません。 そこで、クラウド上のColabと、皆さんの手元のブラウザを繋ぐ**「一時的な通り道（トンネル）」**を作ってあげる必要があります。

このトンネリングツールとして localtunnel（ローカルトンネル） という無料のサービスを使います。

【localtunnelによる通信のイメージ図】

  [ ☁️ Google Colab ]                           [ 🌐 localtunnel サーバー ]                 [ 💻 あなたのブラウザ ]
    ・Streamlitが起動中                           一時的な公開URLを発行する                  Colabの画面を
    ・ポート: 8501番   ──(トンネル開通)──▶     (https://xxxx.loca.lt)   ──(アクセス)──▶  手元のPC/スマホで
    ・IPアドレス(鍵)                                                                         直接操作できる！

まずは、Colabのセルに以下の「おまじない」を貼り付けて、環境構築の準備をしましょう。

# ------------------------------------------------------------------
# ステップ 1: 必要なライブラリのインストール（Colabのセルで実行してください）
# ------------------------------------------------------------------
# Streamlitと、トンネリング用のツールをインストールします。
!pip install -q streamlit
!npm install -g localtunnel

⚠️ 【最重要】ColabでStreamlitを起動する「3つの手順（黄金の儀式）」¶

Colab上でアプリを起動し、表示させるためには、これから紹介する**3つのセルを順番に実行する「儀式」**が必ず必要になります。1つでも手順を抜かすと繋がりませんので、丁寧に確認していきましょう。

手順①：アプリのソースコードを書き出す（%%writefile）¶

Colabのセルの1行目に %%writefile app.py と記述すると、そのセルの中身がそのまま app.py という名前のPythonファイルとしてColabの中に保存されます。

  • ※以下のコードセルを実行してください。

%%writefile app.py
# これがあなたの最初のWebアプリのプログラムになります！
import streamlit as st

st.title("武蔵大学データ分析アプリ ☕")
st.subheader("プログラミング応用A（第5回実習）")
st.write("こんにちは！私が自分で作って起動した、最初のStreamlitアプリへようこそ！")
st.markdown("---")
st.success("おめでとうございます！アプリのソースコードが正常に作成されました。")

手順②：トンネルの鍵（あなたのIPアドレス）を確認する¶

localtunnelを使って外部からアプリにアクセスする際、いたずら防止（セキュリティ確認）のために「Colabの仮想パソコンのIPアドレス（4つの数字の組み合わせ）」を求められます。 以下のコマンドを実行して、出力されたIPアドレスをコピーして手元にメモしておきましょう。

  • ※以下のコードセルを実行してください。

# あなたのColab環境のIPアドレスを表示します（トンネルを開くためのパスワードになります）
!wget -qO- ipv4.icanhazip.com

出力例：34.125.12.34（※実行するたびに毎回異なる数字が出ます）

手順③：アプリをバックグラウンドで起動し、トンネルを開通する！¶

以下のコマンドを実行すると、StreamlitがColabの裏側（バックグラウンド）でひっそりと動き続け、localtunnelが手元のブラウザからアクセスするための一時的なURLリンクを発行してくれます。

  • ※以下のコードセルを実行してください。

# 1. StreamlitをColabの裏側で静かに起動（ポート8501番を使用）
!streamlit run app.py &>/dev/null &

# 2. ポート8501番を localtunnel を使って外部に公開します
!npx localtunnel --port 8501

  • ブラウザでの開き方（接続の完了まで）:

    1. 手順③を実行すると、画面に url: https://xxxx.loca.lt という青いリンクが表示されます。このリンクをクリックしてください。

    2. 以下のような英語の画面（セキュリティ警告）が表示されます。

      Friendly Reminder
Submit your IP address to access this localtunnel:
[                  ] (ここにIPアドレスを入れる入力欄)

    3. 入力欄に、先ほど**手順②で確認したIPアドレス（例：34.125.x.x）をそのまま貼り付け、「Submit」**ボタンを押してください。

    4. 画面がパッと切り替わり、あなたが手順①で作った「武蔵大学データ分析アプリ ☕」が表示されれば大成功です！🎉

5.3 基本ウィジェットと挙動の理解 (約25分)¶

無事にアプリが起動したら、今度はアプリの中身を豪華にしていきましょう！

5.3.1 最重要：Streamlit特有の「Rerun（再実行）」システム¶

Streamlitでコードを書く際、従来のプログラミングと大きく異なる「お約束」があります。 それは、**「ユーザーがボタンを押したりスライダーを動かしたりするたびに、StreamlitはPythonのコードを上から下まで、毎回超高速で丸ごと再実行（Rerun）する」**という仕組みです。

【Streamlitの処理サイクル】

  [ 💻 画面でユーザーが操作 ] （例：スライダーを 150 に動かす）
             │
             ▼ （Streamlitが検知！）
  [ 🔄 Pythonコードを上から下まで全部再実行 ] （app.pyの1行目から読み直し）
             │
             ▼ （現在のスライダーの値を読み込み、売上高を再計算）
  [ 🎨 画面を滑らかに更新 ]

このお約束を理解していないと、次の「ボタンの罠」に引っかかってしまいます。

⚠️ 【初心者が100%はまる】ボタンの罠（st.button）¶

以下のようなコードを書いたとします。

if st.button("秘密のメッセージを見る"):
    st.write("秘密のメッセージ：いつも授業を頑張ってくれてありがとう！")

ボタンを押した瞬間はメッセージが表示されます。しかし、その後、別の場所にあるスライダーなどを動かすと、せっかく表示されたメッセージが一瞬で消えてしまいます。

なぜでしょうか？ スライダーが動かされた瞬間、Streamlitはコードを上から下まで再実行します。その再実行の際、「今、まさにこの瞬間ボタンがカチッとクリックされたか？」と判定されますが、クリックされた瞬間ではない（スライダーが動いただけ）ため、st.button の結果は False（押されていない）と判定され、if文の中のメッセージ表示処理がスキップされてしまうのです。

この「ボタンは押された瞬間だけ True になり、次のアクションでは False に戻る」という性質は、Streamlitの最も重要なルールです。覚えておきましょう！

5.3.2 画面を構成する代表的なコマンド¶

ソースコードを上書きして保存し、ブラウザの画面を「リロード（F5）」することで、瞬時にアプリが更新されます。

%%writefile app.py
import streamlit as st

# ==========================================
# 1. 画面表示系（テキストや装飾）
# ==========================================
st.title("カフェ自動レジアプリ ☕") # タイトル（最大サイズ）
st.header("お会計シミュレーター") # ヘッダー（中サイズ）
st.write("商品の選択と数量を入力すると、自動でお会計を計算します。") # 標準テキスト

# ==========================================
# 2. 入力系ウィジェット（ユーザーからデータを受け取る部品）
# ==========================================
# (1) セレクトボックス（ドロップダウンメニュー）
# ユーザーが選んだ値が、変数 selected_item に代入されます！
selected_item = st.selectbox(
    "ご注文の商品を選んでください:",
    ["コーヒー (450円)", "紅茶 (400円)", "チョコレートケーキ (550円)"]
)

# (2) スライダー（数値の範囲入力）
# st.slider("ラベル名", 最小値, 最大値, 初期値)
amount = st.slider("数量（個数）を選んでください:", 1, 10, 1)

# ==========================================
# 3. 連動した計算処理（Pythonのロジック）
# ==========================================
# 商品名から価格を取り出す
if "コーヒー" in selected_item:
    price = 450
elif "紅茶" in selected_item:
    price = 400
else:

練習問題 3: Rerun（再実行）システムの罠¶

Streamlitのアプリ画面で、ユーザーがスライダーのつまみを動かしたとき、裏側で動いているPythonのプログラム（app.py）はどのような挙動をしますでしょうか？ 「実行される範囲」に注目して答えてください。

👉 練習問題 3 の解答と解説を見る

  • 解答: プログラムの1行目（最初）から最後の行まで、すべてのコードが丸ごと超高速で再実行（Rerun）される。

  • 解説: これがStreamlitの最も重要で特徴的な仕組みです。ユーザーが何か操作するたびに、すべてのコードが上から下に再実行され、その時点でのウィジェットの値を読み取って画面全体を再描画します。

練習問題 4: ボタン（st.button）の挙動の真実¶

以下のコードを実行し、ブラウザでボタンを押した瞬間は「お祝い」と表示されましたが、その直後、別のスライダーを動かした瞬間、画面から「お祝い」の文字が消えてしまいました。この現象が起きる原因を説明してください。

if st.button("合格発表を見る"):
    st.write("🎉 おめでとうございます！合格です！")
👉 練習 representation 4 の解答と解説を見る

  • 解答: st.button は「ボタンがクリックされた瞬間（再実行）だけ True を返し、その後に別のウィジェット（スライダー等）が動いて再実行されたときには、クリックされた瞬間ではないため False（押されていない状態）に戻ってしまう」から。

  • 解説: ボタンの判定は「一瞬の打ち上げ花火」のようなものです。次の瞬間（再実行）にはリセットされて False に戻るため、if文の中の処理は消えてしまいます。この消したくないデータを保存する高度な技術（st.session_state）は、今後の授業で学びます！

練習問題 5: インジケーター st.metric の役割¶

Streamlitで用意されている st.metric() というコマンドは、どのようなデータを画面に表示するのに適していますか？ 具体的な例を2つ挙げてみてください。

👉 練習問題 5 の解答と解説を見る

  • 解答: 売上高、客数、気温、進捗率など、**「ダッシュボードの最上部に、パッと一目でわかるように大きな太字でアピールしたい『重要な数値指標（KPI）』」**を表示するのに適している。

  • 解説:

    • 例：「本日総売上：150,000円」「前日比：+15%」

    • 普通のテキスト（st.write）に比べて、文字が非常に大きく、枠線やカラー表示もオシャレに整理されるため、ビジネスダッシュボードの「主役」として多用されます。
