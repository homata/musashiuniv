13.2 授業内練習問題（理論確認用：5問）¶

まずはウォーミングアップです。以下の5つの理論問題に挑戦しましょう。頭の中で答えを決めてから、クリックして解答・解説を確認してください。

練習問題 1: データの尺度と統計指標¶

「コーヒー(100円), 紅茶(120円), ジュース(150円)」という商品別の「価格」は ( A ) 尺度であり、その代表値として平均値を計算することに意味があります。一方、「1:非常に満足, 2:満足, 3:普通, 4:不満」というアンケートの評価値は ( B ) 尺度であり、代表値としては「中央値」や「最頻値」が適しています。 空欄(A)と(B)に入る尺度の名称の組み合わせを答えてください。

👉 練習問題 1 の解答と解説を見る

  • 正解: ( A ) = 比例（比率）尺度、( B ) = 順序尺度

  • 解説:

    • 価格は、0円が「無（お金が存在しない）」を意味し、100円の2倍は200円という「掛け算・割り算（比率）」に意味があるため比例尺度です。平均値を計算できます。

    • 満足度アンケートは、1から4の数字に「順序（大小関係）」はありますが、「満足(2)と満足(1)の差が、不満(4)と普通(3)の差と全く等しい」とは言えず、割り算もできないため順序尺度です。アンケート結果を単純に「平均2.3」と出すのは厳密には不適切で、中央値（真ん中の人）や最頻値（最も多い回答）で見るのが基本です。

練習問題 2: Pandasの結合（merge）とデータ消失¶

Pandasで売上履歴データフレーム df_sales（1万行）と、商品マスタデータフレーム df_products（50件）を、共通の「商品ID」を使って pd.merge() で結合しようとしています。 しかし、結合オプションを何も指定せずにマージしたところ、売上履歴が8000行に減ってしまいました。この原因として最も適切なものはどれでしょうか？

  1. 結合方式が標準で「外部結合(outer)」になっており、商品マスタに存在しない商品IDの売上が消去されたから。

  2. 結合方式が標準で「内部結合(inner)」になっており、商品マスタに登録されていない商品IDの売上が、合致しないため消去されたから。

  3. 売上履歴に「重複」があったため、結合時にPandasが自動的に重複をクレンジング（削除）したから。

👉 練習問題 2 の解答と解説を見る

  • 正解: 2

  • 解説: pd.merge() のデフォルト（標準）の結合方式は how="inner"（内部結合） です。これは「両方のデータフレームに共通して存在するキー（商品ID）のみを残す」というお約束です。そのため、売上履歴の中に「まだ商品マスタに登録されていない、お試し新商品のID」などが混ざっていると、合致するものがマスタ側にないため、売上データ自体が丸ごと消去されてしまいます。売上を1行も消したくない場合は、**how="left"（左結合＝売上履歴をすべて残し、マスタにない部分はNaNにする）**を指定する必要があります。

練習問題 3: GISの座標系と単位の罠¶

GeoPandasで、ある店舗から「半径500m」の商圏ポリゴンを .buffer(500) で作成しようとしています。 しかし、店舗データのGeoDataFrameの座標系（CRS）が「EPSG:4326（世界測地系・経緯度）」のままで .buffer(500) を実行してしまいました。このとき発生する不具合として正しいものはどれでしょうか？

  1. エラーが発生して、プログラムがその場で強制終了する。

  2. エラーは出ないが、単位が「メートル」ではなく「度」として処理されるため、日本（地球）のサイズを遥かに超える巨大な（半径500度の）ポリゴンが生成されてしまう。

  3. プログラムが自動でメートルに変換して処理してくれるため、何の問題もなく正しい500mの円が作られる。

👉 練習問題 3 の解答と解説を見る

  • 正解: 2

  • 解説: これもGIS分析で初心者が最も犯しやすい恐ろしい罠です。GeoPandasの空間演算（.buffer() や距離計算など）は、**「そのデータフレームが今持っている座標系の単位」**をそのまま使います。

    • EPSG:4326 の単位は 「度（Degree）」 です。

    • そのため、この状態のまま .buffer(500) を実行すると、システムは「半径500度（地球は1周360度なので、地球を何周も包む巨大な円）」を作ろうとしてしまい、地図上が真っ青（巨大ポリゴンで埋まる）になります。

    • 空間演算を行う前には、必ず .to_crs(epsg=6677)（平面直角座標系などのメートル単位の平面座標系）に変換するステップが絶対必要です！

練習問題 4: 機械学習の「過学習（Overfitting）」¶

機械学習において、用意したデータすべてをAIの学習用（.fit）に使ってモデルを構築し、同じデータを使ってモデルの精度（決定係数など）を測定したところ、100%（完璧）の精度が出ました。 しかし、このAIモデルを実務に導入して「新しくやってきた明日のお客様の売上」を予測させたところ、全く当たらないひどい予測になってしまいました。この現象を何と呼ぶでしょうか？また、これを防ぐための機械学習の黄金のルールは何でしょうか？

👉 練習問題 4 の解答と解説を見る

  • 正解:

    • 現象名：過学習（オーバーフィッティング）

    • 黄金のルール：学習データ（訓練データ）と、テストデータ（評価データ）の分割（ホールドアウト法）

  • 解説:

    • 過去のデータを丸暗記（過学習）したAIは、過去の「たまたま起きたノイズ（その日だけ天気が大荒れだったなど）」まで完璧なルールとして記憶してしまいます。そのため、まだ見ぬ未来（未知のデータ）に対する予測力が極端に低下します（学校のテスト問題と答えを丸暗記したため、応用問題が解けない生徒と同じ状態です）。

    • これを防ぐため、データをあらかじめ 「学習用（7割〜8割）」 と 「テスト用（2割〜3割）」 に分割し（train_test_split）、学習にはテストデータを見せず、評価の時にだけ「実力テスト」として解かせることで、本当の予測実力を測定します。

練習問題 5: Vibe Codingにおけるプロンプト設計¶

ChatGPTやClaudeなどのLLM（生成AI）を使って、1回で不具合（バグ）の少ない完璧なStreamlitダッシュボードのコードを出力させるための「プロンプトの4大構成要素」を答えてください。

👉 練習問題 5 の解答と解説を見る

  • 正解: ①役割の定義（Persona）, ②前提条件と開発環境（Context/Environment）, ③具体的な機能要件（Requirements）, ④出力フォーマットの指定（Format）

  • 解説: 「〜のアプリを作って」とだけ書くのは、プロのエンジニアに「なんか面白いシステム作って」と丸投げするのと同じで、必ず失敗します。

    1. 役割:「あなたはPythonとStreamlitのシニアエンジニアです」

    2. 前提:「実行環境はGoogle Colab、Python3.12、Pandas、Matplotlibがインストール済みです。Web上のCSVを読み込んで処理します」

    3. 要件:「サイドバーで店舗を切り替え、Pandasでフィルターし、売上合計をKPI表示し、日次売上の棒グラフを描画する」

    4. フォーマット:「余計な解説は省き、Google Colabのセルにそのままコピペして動く1つのPythonコードブロックのみを出力してください」 この4要素を揃えることで、AIは劇的に美しく、一発で動作するプログラムを出力してくれます。

課題 1: Pandasによる複数データの結合（第3回テーマ）¶

カフェの「売上履歴（sales_df）」と「商品マスタ（product_df）」が別々のデータフレームにあります。 売上履歴には価格や商品名が載っていないため、共通キーである「商品コード（Item_Code）」を使って結合し、売上データに「商品名」と「価格」を合体させてください。なお、売上履歴にあるデータは1行も消去したくないため、**左結合（left）**を指定してください。

import pandas as pd

# 売上履歴データフレーム（ダミー）
sales_df = pd.DataFrame({
    "Sale_ID": [1001, 1002, 1003, 1004],
    "Item_Code": ["C01", "T01", "C01", "K01"], # C01=コーヒー, T01=紅茶, K01=マスタ未登録の裏メニュー
    "Amount": [2, 1, 3, 1]
})

# 商品マスタデータフレーム（ダミー）
product_df = pd.DataFrame({
    "Item_Code": ["C01", "T01", "C02"],
    "Item_Name": ["コーヒー", "紅茶", "カフェラテ"],
    "Price": [400, 450, 500]
})

# TODO: sales_df をベースに、product_df を "Item_Code" をキーにして左結合(how="left")してください。
merged_df = pd.merge(sales_df, product_df, on="Item_Code", how="left")

print("--- 結合後のデータフレーム ---")
display(merged_df)

課題 2: applyとラムダ式による条件付き計算（第3回テーマ）¶

カフェの営業時間において、**「22時以降（22:00〜）の売上には深夜割増料金として10%（1.1倍）のサービス料を価格に上乗せする」**というルールを自動計算する列を追加したいです。 apply() と lambda、そして if-else 文を組み合わせて、新しい列「深夜対応価格」を作成してください。 ※ヒント：行全体に処理を適用するため、必ず axis=1 を指定してください。

import pandas as pd

sales_history = pd.DataFrame({
    "商品名": ["コーヒー", "夜カフェラテ", "深夜パフェ", "紅茶"],
    "注文時": [15, 18, 23, 21], # 24時間表記の「時」
    "基本価格": [400, 500, 800, 450]
})

# TODO: apply と lambda を使い、注文時が 22 以上の場合は 基本価格*1.1、そうでない場合は 基本価格 を適用する
# ※ lambda row: row["基本価格"] * 1.1 if row["注文時"] >= 22 else row["基本価格"] の形を使います。
sales_history["深夜対応価格"] = sales_history.apply(
    lambda row: row["基本価格"] * 1.1 if row["注文時"] >= 22 else row["基本価格"],
    axis=1
)

print("--- 深夜料金適用後の売上履歴 ---")
display(sales_history)

課題 3: 時系列データからの月・曜日抽出とグループ集計（第3回テーマ）¶

売上の「日付」を表す列がありますが、現在はただの「文字列」になっています。

課題 6: GeoDataFrameの作成と座標系(CRS)変換（第7〜8回テーマ）¶

課題 7: 空間結合（Spatial Join）による位置判定（第8回テーマ）¶

空間結合（gpd.sjoin）を使うと、「店舗のGPSピン（Point）」が「どの市区町村の境界線（Polygon）」の中に物理的に含まれているかを、プログラムが全自動で交差判定して合体してくれます。 池袋店などの「店舗GeoDataFrame」と、豊島区や文京区の境界線を表す「行政区画GeoDataFrame」を空間結合し、各店舗が何区にあるかを自動判定させてください。

import geopandas as gpd
from shapely.geometry import Point, Polygon

# 1. 簡易的な「行政区（区画）」のポリゴンデータを作成します（ダミー）
# 本来は国土数値情報などのShapefileを読み込みますが、ここではコードだけで完結するダミーです。
poly_toshima = Polygon([(139.70, 35.72), (139.73, 35.72), (139.73, 35.74), (139.70, 35.74)]) # 豊島区簡易エリア
poly_bunkyo  = Polygon([(139.73, 35.71), (139.76, 35.71), (139.76, 35.73), (139.73, 35.73)]) # 文京区簡易エリア

gdf_districts = gpd.GeoDataFrame({
    "区名": ["豊島区", "文京区"]
}, geometry=[poly_toshima, poly_bunkyo], crs="EPSG:4326")

# 2. 店舗Pointデータ
shop_points = [Point(139.7111, 35.7292), Point(139.7523, 35.7215)] # 池袋店（豊島区）、白山店（文京区）
gdf_shops = gpd.GeoDataFrame({
    "店舗名": ["池袋店", "白山店"]
}, geometry=shop_points, crs="EPSG:4326")

print("--- 区画（Polygon）データ ---")
display(gdf_districts)
print("--- 店舗（Point）データ ---")
display(gdf_shops)

# TODO: gpd.sjoin を使って、店舗データ(gdf_shops)に区画データ(gdf_districts)を空間結合してください。
# 引数: left_df=gdf_shops, right_df=gdf_districts, how="left", predicate="within" (あるいはintersects)
joined_result = gpd.sjoin(gdf_shops, gdf_districts, how="left", predicate="intersects")

print("\n--- 空間結合（自動位置判定）の結果 ---")
# 各店舗名に、自動的に正しい「区名」がマージされているのを確認してください！
display(joined_result[["店舗名", "区名", "geometry"]])

課題 8: scikit-learnによる売上予測（線形回帰AI）（第10回テーマ）¶

過去のカフェの「客数（説明変数X）」と「売上高（目的変数Y）」のデータがあります。

  1. データを学習用（75%）とテスト用（25%）に分割してください。

  2. scikit-learn の LinearRegression を定義し、学習用データを使ってAIに学習（.fit）させてください。

  3. テストデータを用いて予測（.predict）を行い、モデルの賢さを表す「決定係数 \(R^2\)」を算出してください。

import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LinearRegression
from sklearn.metrics import r2_score

# 過去の客数と売上データ（ダミー）
np.random.seed(42)
X = np.random.randint(50, 200, (100, 1)) # 客数（説明変数：2次元配列にする必要があります）
y = X * 2500 + np.random.normal(0, 30000, 100) # 売上（目的変数：単価約2500円＋ノイズ）

# TODO: 1. データを学習用（train）とテスト用（test）に 75:25 で分割する
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=42)

# TODO: 2. 線形回帰モデルを定義し、学習用データで学習させる
model = LinearRegression()
model.fit(X_train, y_train)

# TODO: 3. テストデータを使って予測値を計算し、決定係数(R2)を算出する
y_pred = model.predict(X_test)
r2 = r2_score(y_test, y_pred)

print(f"モデルの学習が完了しました。")
print(f"客数に対する売上予測式: 売上 ＝ {model.coef_[0]:.1f} × 客数 ＋ {model.intercept_:.1f}")
print(f"テストデータに対する決定係数(R2): {r2:.4f} (1.0に近づくほど超優秀！)")

カフェの常連さん100人について、「年間購入額（X軸）」と「年間来店回数（Y軸）」のデータが記録されています。 scikit-learn の KMeans を使用して、この顧客たちを特徴に応じて自動的に**「3つのグループ」**にクラスタリング（分類）し、AIが決定した各グループの中心点（重心：セントロイド）の座標を表示してください。

fig, ax = plt.subplots(figsize=(8, 5))

# AIの回帰直線（予測ライン）

ax.plot(X_line, y_line, color="red", linestyle="--", label="AI売上予測ライン")

# 明日のシミュレーション位置（★）
ax.scatter(next_visitors, pred_sales, color="darkorange", marker="*", s=250, zorder=5, label="明日のシミュレーション")

# グラフ装飾

ax.legend()
ax.grid(True, linestyle=":")
