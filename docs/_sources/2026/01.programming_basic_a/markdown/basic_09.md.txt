## 関数を極める（引数とスコープ）

第3回で、`def` を使って関数（自動計算機）を作る方法を学びました。今日はその機能をさらに拡張します。

### 関数の復習（関数定義、引数、返値、複数の引数）
関数には、材料である「引数（ひきすう）」を複数渡して、完成品である「返値（戻り値：return）」を受け取ることができましたね。

### 引数の初期値とキーワード引数
引数には、「もし何も指定されなかったら、これを基本（デフォルト）にするよ」という**初期値**を設定できます。
また、引数を渡すときに「サイズはLね！」と名前を指定して渡す方法を**キーワード引数**と呼びます。

```
# 引数の初期値（sizeの初期値を"M"にします）
def order_coffee(amount, size="M"):
    print(size, "サイズのコーヒーを", amount, "杯ご注文ですね。")

# 引数を1つしか渡さないと、sizeは自動的に初期値の"M"になります！
order_coffee(2)

# キーワード引数（引数の名前を指定して渡すので、順番が逆でもOKです！）
order_coffee(size="L", amount=3)
```

### 可変長引数（*args）と辞書型の可変長引数（**kwargs）
「トッピングをいくつ頼むか分からない！」という時に、引数の前に `*` (アスタリスク) をつけると、**好きな数だけ引数を受け取れる（可変長引数）**ようになります。受け取ったデータはタプルにまとまります。
`**` を2つつけると、キーワード付きのデータを辞書として無限に受け取れます。

### 引数の順番のルール
引数を混ぜて使うときは、**①通常の引数 ➡ ②初期値付き引数 ➡ ③`*`可変長引数 ➡ ④`**`辞書型可変長引数** の順番で書くルールがあります。

```
# 可変長引数（*toppings で、いくつでもトッピングを受け取れます！）
def order_pancake(base_menu, *toppings):
    print("ベース:", base_menu)
    print("トッピング:", toppings) # タプルとしてまとまります

# トッピングを3つ渡してみます
order_pancake("プレーンパンケーキ", "チョコ", "バナナ", "ホイップ")
```

### 変数のスコープ（ローカル / グローバル）
変数が「どこからどこまで有効か」という縄張りのことを**スコープ**と呼びます。

*   **ローカル変数**: 関数の中（インデントの中）で作られた変数。関数の外からは見えません。
*   **グローバル変数**: 関数の外で作られた変数。プログラムのどこからでも見えます。

```
# スコープの確認
shop_name = "ムサシ・カフェ" # これはグローバル変数

def print_receipt():
    tax_rate = 0.1 # これは関数の中だけのローカル変数
    print(shop_name, "のレシートです。") # グローバル変数は読める！

print_receipt()
# print(tax_rate) # ←関数の外でローカル変数を呼ぼうとすると NameError になります！
```

### 変数としての関数
Pythonでは、関数そのもの（`def`で作ったもの）を、変数（箱）に入れることができます。「関数の別名」を作るようなイメージです。

```
def say_hello():
    return "こんにちは！"

# 関数本体（カッコなし）を別の変数に代入します
greeting_func = say_hello

# 別名で呼び出せます！
print(greeting_func())
```

## クラスとオブジェクト指向の基礎 

Pythonの世界では、数値や文字列、リストなどすべてが「オブジェクト（モノ）」として作られています。
このオブジェクトを作るための「設計図」が**クラス (class)** です。

**【クラスとインスタンスのイメージ図】**
```text
  [ 📝 設計図 (クラス: Cafe) ]
     ・お店の名前 (属性)
     ・開店する機能 (メソッド)
             │
             ▼ (設計図をもとにお店を建てる！)
             │
  [ 🏠 実店舗 (インスタンス: tokyo_cafe) ]
     「私は東京店です。開店します！」
```

*   **クラス**: 設計図です。`class` というキーワードで作ります。
*   **インスタンス**: 設計図から作られた「実体（オブジェクト）」です。
*   **属性（データ）**: そのオブジェクトが持っているデータ（名前や売上など）です。
*   **メソッド（振る舞い）**: そのオブジェクトができること（関数）です。

※ クラスの中で作られるメソッドには、必ず最初の引数に `self`（自分自身）を書くというお約束があります。

```
# カフェの設計図（クラス）を作ります
class Cafe:
    
    # __init__ は、お店を建てる時（初期化）に最初に呼ばれる特別なメソッドです。
    def __init__(self, name):
        # 自分自身(self)の name属性 に、渡された名前を記録します
        self.name = name 
        self.sales = 0
        
    # お店ができること（メソッド）を定義します
    def open_shop(self):
        print(self.name, "がオープンしました！いらっしゃいませ！")

# ----------------------------------------------------
# 設計図(Cafeクラス)を使って、実際の店舗（インスタンス）を作ります！
tokyo_cafe = Cafe("東京本店")
osaka_cafe = Cafe("大阪支店")

# 属性（データ）にアクセスする
print("店舗名:", tokyo_cafe.name)

# メソッド（機能）を呼び出す
tokyo_cafe.open_shop()
osaka_cafe.open_shop()
```

データ分析では、自分でクラスを作ることは最初は少ないかもしれませんが、「pandas」などの強力なツールを使うとき、実は裏側でこの「クラスとインスタンス」の仕組みがバリバリ動いています。この概念を知っておくと、ツールの使い方がとてもスムーズに理解できますよ。

## 例外処理：エラーで止まらないプログラム

データ分析で数万件のデータを処理している時、たった1つのデータがおかしくてエラーになり、プログラムが途中で止まってしまったら悲しいですよね。

そこで使うのが **例外処理（`try` / `except` / `else` / `finally`）** です。

*   **`try`**: まず、エラーが起きるかもしれない処理をここで「試して」みます。
*   **`except`**: もし特定のエラーが起きたら、止まらずにここを実行します（安全装置）。
*   **`else`**: エラーが起きず、無事に成功した時だけ実行します。
*   **`finally`**: エラーが起きても起きなくても、絶対に最後に実行します（お片付け用）。

```
# 例外処理の基本
def divide_sales(sales, people):
    try:
        # まずは普通に割り算を試します
        result = sales / people
        
    except ZeroDivisionError:
        # もし people が 0 で 0割りエラーが起きたら、止まらずにここに来ます！
        print("【エラー】人数が0人です！計算できません。")
        result = 0
        
    else:
        # エラーなく無事に計算できた時だけ呼ばれます
        print("無事に計算完了しました。")
        
    finally:
        # エラーが起きても起きなくても、絶対に最後に呼ばれます
        print("--- 処理終了 ---")
        
    return result

# 正常なデータ
print("1人あたり:", divide_sales(1000, 2), "円\n")

# 異常なデータ（人数が0人！ 普通ならプログラムがクラッシュします）
print("1人あたり:", divide_sales(1000, 0), "円")
```

### raise（意図的にエラーを起こす）
データがおかしい時に、「そのまま進むと危険だ！」と判断して、自分で意図的にエラーを発生させる（警告ブザーを鳴らす）こともできます。それが `raise` です。

```
# raise文 の例
def check_age(age):
    if age < 0:
        # 年齢がマイナスなら、意図的に ValueError を発生させます！
        raise ValueError("年齢がマイナスです。データが間違っています！")
    print(age, "歳ですね。確認しました。")

# check_age(-5) # ←コメントを外して実行すると、自分で設定したエラーが発生します。
```

## 📚 第9回のまとめ

プログラミングの世界を大きく広げる、とても重要な概念を学びました。
少し難しく感じたかもしれませんが、これができるようになるとプログラミングの自由度が格段に上がります！

### ✨ 今日の重要ポイントまとめ

*   **関数の応用**: 引数には初期値を持たせたり、`*args` でいくつでも受け取ったりすることができる。
*   **スコープ**: 関数の中で作った変数（ローカル）は、外からは見えない。
*   **クラスとインスタンス**: クラスは「設計図」、インスタンスはそれをもとに作られた「実体（オブジェクト）」。
*   **例外処理 (try-except)**: エラーが起きてもプログラムを強制終了させず、安全に別の処理（スキップなど）を行わせる必須テクニック。

### ❓ よくある質問と回答 (FAQ)
*   **Q. クラスと関数って何が違うんですか？**
    *   **A.** とても良い質問です！「関数」は単なる「動き（処理）」です。一方「クラス」は、データ（属性）と動き（メソッド）を「セットにして持ち運べるようにしたもの」です。カフェの例で言えば、関数は「コーヒーを淹れる」というマニュアルの1ページ。クラスは「カフェというお店そのもの（コーヒーも淹れるし、売上データも持っている）」というイメージです。
*   **Q. 例外処理の except にエラー名（ValueErrorなど）を書かないとどうなりますか？**
    *   **A.** `except:` とだけ書くと、構文エラーなどを除く「すべてのエラー」をキャッチしてしまいます。一見便利そうですが、本当にやばいバグ（変数名のタイポなど）も隠してしまい、後で原因不明のトラブルになるため、プロの世界では「予想されるエラー名（ZeroDivisionErrorなど）」をきちんと指定するのがマナーとされています。

### 🌟 Colabで試すおすすめコード

例外処理（try-except）と繰り返し（while）を組み合わせた、データ入力待ちのシミュレーションです。データ分析の下準備として、正しいデータが来るまで待機するような処理です。

```
# 正しい数値リストが完成するまで、エラーを無視して処理を続けるコード
data_list = [10, "A", 20, "B", 30]
valid_numbers = []

for item in data_list:
    try:
        # 数値への変換を試みる
        num = int(item)
        valid_numbers.append(num)
        print("追加成功:", num)
    except ValueError:
        # 文字が来てエラーになったら、警告だけ出して処理は止めない！
        print("【警告】数値ではないデータをスキップしました:", item)
        
print("最終的な正しいデータ:", valid_numbers)
```
