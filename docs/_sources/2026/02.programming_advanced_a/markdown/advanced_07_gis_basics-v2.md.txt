## 7.1 GIS（地理空間情報システム）とは？（地図の「レイヤー構造」） (約25分)

### 7.1.1 地図は「パンケーキの重ね合わせ」である
GISとは、**「地球上にあるあらゆるモノや出来事の位置情報を、コンピュータ上で重ね合わせて分析・視覚化するシステム」**です。
GISを理解する上で、最も重要な概念が**「レイヤー（層）」**です。

現実世界の複雑な地図を、性質ごとに切り分けた透明なフィルム（レイヤー）に分解して管理します。
これを身近な**「パンケーキのトッピング」**に例えてみましょう！

*   一番下のパンケーキ：**「地形・河川・ベースマップ（土台）」**
*   その上のホイップクリーム：**「道路や鉄道路線のネットワーク（線）」**
*   その上のイチゴ：**「避難所や店舗の場所（点）」**
*   その上のシロップ：**「ハザードマップの浸水想定エリアや、夜間の人口分布（面）」**

これらをコンピュータ上で綺麗に重ね合わせる（ガッチャンコする）ことで、「川（レイヤー1）から200m以内のエリアで、浸水想定（レイヤー2）に入っており、かつ高齢者数の多い地域（レイヤー3）にある、避難所（レイヤー4）はどこか？」といった、複雑な災害シミュレーションやエリアマーケティングが、手計算なしで一瞬でできるようになります。

**【GISのレイヤー構造（ビジュアルイメージ）】**
```text
  [ レイヤー 4 ]   📍 避難所・店舗（点データ：Point）
         │
  [ レイヤー 3 ]   🛣️ 道路や鉄道路線（線データ：LineString）
         │
  [ レイヤー 2 ]   🟩 行政区画・浸水エリア（面データ：Polygon）
         │
  [ レイヤー 1 ]   🗺️ 背景の衛星画像・白地図（ベースマップ）
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  【ガッチャンコ！】 ＝ 1枚の便利な「防災マップ」や「カフェ出店計画分析マップ」の完成！
```

### 7.1.2 GISを構成するデータの2大種類：ベクタとラスタ
GISで扱うデータは、大きく分けて**「ベクタデータ」**と**「ラスタデータ」**の2つがあります。この違いを理解することは、GIS分析の第一歩です。

```text
       【 ベクタデータ 】                      【 ラスタデータ 】
  （数式と座標で描くくっきり地図）           （ピクセルの格子で描くモザイク地図）
  
        Point   Line   Polygon
          📍     ───     ┌─┐                 ┌──┬──┬──┬──┐
                         └─┘                 │  │██│  │  │
                                             ├──┼──┼──┼──┤
                                             │██│██│  │  │
                                             └──┴──┴──┴──┘
```

1.  **ベクタデータ（Vector Data）**：【点・線・面】
    幾何学的な「座標（X, Y）」の組み合わせで位置を表現するデータです。どれだけ拡大しても境界線がぼやけず、くっきりと表示されます。データ量が軽く、統計計算に適しています。
    *   **点（Point）**：経度と緯度の一組で表される点。例：店舗、避難所、バス停。
    *   **線（LineString）**：複数の点を繋いだ折れ線。例：道路、河川、鉄道路線。
    *   **面（Polygon）**：始点と終点が一致して閉じられた多角形。例：市区町村の境界、浸水想定エリア、公園の敷地。
2.  **ラスタデータ（Raster Data）**：【ピクセル・格子】
    画面を細かなマス目（ピクセル・グリッド）に分割し、それぞれのマス目に「数値」を入れて表現するデータです。
    *   *例*：人工衛星から撮った写真（写真データ）、標高データ（各マス目の標高が入っている）、雨雲レーダーの強度。
    *   拡大すると、デジタル写真のように「ギザギザ（モザイク）」になります。

## 7.2 地球をどうやって平らにする？（座標系と投影法の罠） (約25分)

ここが、地理空間データを扱う上で文系学生が最も「うっ…」となる理論パートです。
しかし、**数式は一切使いません！** イメージで理解しましょう。

### 7.2.1 地理座標系（丸い地球を角度で表す：経緯度）
地球は丸い（楕円体）です。この丸い地球の上の「住所」を、角度（度・分・秒）で表現したものを**地理座標系（Geographic Coordinate System）**と呼びます。
*   **緯度（Latitude）**：赤道を0度とし、南北にそれぞれ90度まで測る（北緯・南緯）。
*   **経度（Longitude）**：イギリスの旧グリニッジ天文台を通る本初子午線を0度とし、東西にそれぞれ180度まで測る（東経・西経）。

世界共通で最も使われているのが **「WGS84」** という世界測地系です。皆さんのスマートフォンに内蔵されているGPSや、Google Mapsの裏側もすべてこのWGS84（経緯度）で動いています。

### 7.2.2 投影座標系（丸い地球を無理やり平らにする：平面）
しかし、角度（度）のデータのままでは重大な問題が発生します。
*   「この店舗から『半径500メートル』の商圏を計算したい」
*   「この避難所とあの避難所は何メートル離れている？」

角度の単位は「度（Degree）」です。日本付近では「緯度1度」と「経度1度」の長さ（メートル換算）は異なりますし、北極に近づくほど経度1度あたりの距離はゼロに近づきます（スイカの縞模様がてっぺんで1点に集まるのをイメージしてください）。
つまり、**経緯度の数値（度）のままで、足し算や引き算をしてメートル単位の距離や面積を求めることは絶対にできません。**

そこで、丸い地球を**「無理やり引っ張って平らな紙に投影（印刷）」**し、単位を「メートル」に直したものを**投影座標系（Projected Coordinate System）**と呼びます。

### 🍊 みかんの皮の比喩（なぜ地図は歪むのか）
丸いみかんを想像してください。
丸いみかんの皮を、破かずに机の上に「完全な平らな四角形」として広げることはできますか？
絶対にできませんよね。どうしてもどこかが伸びたり、引きちぎれたりします。

**【投影のイメージ（みかんの皮）】**
```text
      丸いみかん（地球）             平面に広げた皮（世界地図）
         ╭━━━━━╮                     ┌───────────────┐
        ┃   ●   ┃   ──投影(flatten)─▶ │   ●   (歪み)   │
         ╰━━━━━╯                     └───────────────┘
      「角度は正確！」                「距離や面積が引き伸ばされる！」
```

このように、3次元の球体を2次元の平面に投影するときには、必ず**「面積」「距離」「角度」のどれかが犠牲（歪む）**になります。
*   世界地図でおなじみの「メルカトル図法」は、角度は正しいですが、北極や南極に近いグリーンランドが異常に巨大に描かれる（面積が極端に歪む）ことで有名です。
*   日本国内の狭い範囲をメートル単位で正確に測定（距離・面積計算）したい時は、日本全国を19の地域に細かく分割し、それぞれの地域での歪みを最小限に抑えた**「平面直角座標系（JGD2011）」**という国土地理院が定めた特別な平面投影座標系を使います。関東地域であれば、**「平面直角座標第9系（EPSG:6677）」**というコードを割り当てて計算します。

## 7.3 地理空間データの代表的なファイル形式とGeoPandasの構造 (約20分)

### 7.3.1 地図データはどうやって保存されている？
地図データは、通常のExcelファイル（.xlsx）や単なるCSVファイルとは異なり、形状データを保存するための特別な形式が使われます。

1.  **Shapefile（シェープファイル：.shp）**：
    *   GIS界の「超定番（長老）」であり、国際規格。世界中のほぼすべてのGISソフトで開けます。
    *   最大の注意点は、ファイルが「.shp（形状）」「.shx（インデックス）」「.dbf（属性情報）」など、**最低3つ以上の異なるファイルが『全く同じフォルダに、全く同じ名前』で揃っていないと絶対に動かない**という点です。どれか1つでも欠けたり、名前が変わったりするとエラーになります。
2.  **GeoJSON（ジオジェイソン：.geojson）**：
    *   Webやプログラミングの世界における「現代の主役」。
    *   中身はただの「テキストファイル（JSON形式）」なので、Pythonで非常に扱いやすく、Webブラウザで地図を動かす際にも多用されます。ファイルも1個で完結するため共有がとても簡単です。
3.  **KML/KMZ（ケーエムエル：.kml）**：
    *   「Google Earth」や「Google Maps」のマイマップでおなじみの形式。一般の人でも扱いやすいのが特徴です。

### 7.3.2 GeoPandas（ジオパンダス）とは？
これまでの授業で、私たちは表形式データを扱う **Pandas** を学んできました。
**GeoPandas（ジオパンダス）**は、Pandasをさらにパワーアップさせ、表の中に**「形状・位置情報（geometry列）」**を追加した最強の地図分析ライブラリです。

**【通常のPandas vs GeoPandasのデータフレーム構造】**
```text
▼ Pandasの DataFrame（ただの表）
  ┌────┬──────────┬──────────┬──────────┐
  │ ID │ 店舗名   │ 売上(円) │ 客数(人) │
  ├────┼──────────┼──────────┼──────────┤
  │ 01 │ 江古田店 │ 150,000  │ 300      │
  └────┴──────────┴──────────┴──────────┘

▼ GeoPandasの GeoDataFrame（地図にプロットできる表）
  ┌────┬──────────┬──────────┬──────────┬────────────────────────────┐
  │ ID │ 店舗名   │ 売上(円) │ 客数(人) │ geometry（形状列：最重要） │
  ├────┼──────────┼──────────┼──────────┼────────────────────────────┤
  │ 01 │ 江古田店 │ 150,000  │ 300      │ POINT (139.6732 35.7371)   │ 👈 緯度経度の位置が入っている！
  └────┴──────────┴──────────┴──────────┴────────────────────────────┘
```

通常のPandasの表に、位置情報（Point, LineString, Polygonなどの形状オブジェクト）が詰まった **`geometry`** という名前の特別な列が1列追加されただけです。
そのため、これまでに学んだPandasの操作（条件抽出、ソート、グループ集計など）が**100%そのまま同じ文法で使えます！**

### 【実践1】世界地図のデータを読み込んで描画する
GeoPandasには、最初から練習用の「世界地図データ（世界各国の境界線ポリゴン）」が内蔵されています。これを読み込んでみましょう！
※将来のGeoPandasバージョンで内蔵データが非推奨になる可能性があるため、Web上からも取得できるようにセーフティネット（フォールバック）を敷いたプロ仕様のコードです。

```python
# 世界地図データの読み込み
try:
    # 従来の読み込み方法
    world_path = gpd.datasets.get_path('naturalearth_lowres')
    world = gpd.read_file(world_path)
except:
    # get_pathが非推奨/削除された場合のWebからのバックアップ読み込み

print("--- 世界地図データのGeoDataFrameの先頭3行を表示 ---")
display(world.head(3))
```

一番右端に **`geometry`** という列があり、ここに `MULTIPOLYGON` や `POLYGON`（多角形：国境線で囲まれた面）の位置データがぎっしり詰まっているのが確認できたでしょうか？

```python
# 世界地図のプロット
fig, ax = plt.subplots(figsize=(12, 6))
world.plot(ax=ax, color='lightgreen', edgecolor='white')

# グラフの装飾
plt.title("GeoPandasで描く最初の世界地図 🗺️")
plt.xlabel("経度 (Longitude)")
plt.ylabel("緯度 (Latitude)")
plt.grid(True, linestyle='--', alpha=0.5)
plt.show()
```

### 練習問題 1: ベクタデータとラスタデータの違い（理論）
「川の氾濫危険エリアを表す市区町村ごとの境界線データ」と、「人工衛星から撮影された雲の画像データ」があります。
これらをGISで扱う際、それぞれ「ベクタデータ」「ラスタデータ」のどちらに分類されるか、理由と合わせて答えてください。

<details>
<summary>👉 練習問題 1 の解答と解説を見る</summary>

*   **正解**:
    *   **市区町村の境界線データ** ➡ **ベクタデータ**（さらに細かく言うと、閉じられた多角形なので **Polygon（面）**）
        *   *理由*: 境界線は「座標（点）」を繋いだ明確な幾何学的データであり、どれだけ拡大してもぼやけないくっきりした地図データだからです。
    *   **人工衛星の雲の画像データ** ➡ **ラスタデータ**
        *   *理由*: 写真データは細かな「ピクセル（格子・マス目）」の集まりであり、それぞれのマス目の色や強度の数値を記録しているためです。拡大するとギザギザになります。

</details>

### 練習問題 2: 地図データの「長老」Shapefileの罠（理論）
データ分析の仕事で、社外のパートナーから「店舗の位置データ」をShapefileでもらいました。
あなたのパソコンのフォルダには、`shop_location.shp` というファイルだけが保存されています。
このファイルをGeoPandasの `gpd.read_file()` で読み込もうとしたところ、エラーが発生して読み込めませんでした。
このエラーが発生した**「原因」**と、解決するためにパートナーに頼んで送ってもらうべき**「ファイル（拡張子）」**について説明してください。

<details>
<summary>👉 練習問題 2 の解答と解説を見る</summary>

*   **正解**:
    *   **原因**: Shapefileは、`.shp` ファイル単体では絶対に動作しないファイル形式だから。
    *   **解決のために送ってもらうべきファイル**: 少なくとも **`.dbf`**（属性データが入ったファイル）と **`.shx`**（インデックス情報が入ったファイル）の2つ。できれば座標系情報が入った **`.prj`** も。
*   **解説**:
    *   Shapefileは「3つのファイル（.shp, .shx, .dbf）で1つの地図データ」として機能する特別なセット商品です。どれか1つでもフォルダから欠けていると、エラーになって開くことができません。
    *   実務では「.shp」だけをメールで送られてきてパニックになるトラブルが非常に多いため、必ずこのルールを覚えておきましょう！

</details>

### 練習問題 3: 緯度・経度の「指定順」の罠（コード）
あなたが、店舗のGPS位置データをPython内に定義するために、経度 139.6732、緯度 35.7371 の Pointオブジェクトを作成しようとして、以下のコードを書きました。

`from shapely.geometry import Point`
`my_shop = Point(35.7371, 139.6732)`

1. このコードの書き方には、GISプログラミング上、**致命的な誤り**があります。どこが間違っているでしょうか？
2. このまま地図にプロットしようとすると、店舗はどこに飛んでいってしまいますか？

<details>
<summary>👉 練習問題 3 の解答と解説を見る</summary>

*   **正解**:
    1.  **間違い**: `Point(緯度, 経度)` の順番で指定してしまっている。正しくは **`Point(経度, 緯度)`** の順で書くべき。
    2.  **プロットした結果**: 日本（東経139度、北緯35度付近）ではなく、**「東経35度、北緯139度（そんな緯度は存在しないため、通常はエラーになるか、あるいは宇宙・北極点の彼方）」**に飛んでいってしまいます。
*   **解説**:
    *   日常会話や住所表記では「緯度・経度」と呼びますが、数学のグラフを思い出してください。
    *   横軸（X軸）＝経度（東経139度など）、縦軸（Y軸）＝緯度（北緯35度など）です。
    *   コンピュータやGeoPandasの内部は `(X, Y)` で座標を処理するため、**必ず `Point(経度, 緯度)` という X, Y の順序で指定する**のが鉄の掟です。全人類が必ず一度は通る罠ですので、強く意識しておきましょう！

</details>

### 練習問題 4: 角度とメートルの決定的な不整合（理論）
世界測地系（WGS84：経緯度、単位は「度」）で定義されている避難所データのGeoDataFrameがあります。
これに対し、座標系を何も変換しないまま、

`df_shelter["geometry"] = df_shelter.buffer(500)`

を実行して、避難所から「半径500メートル」の商圏円（バッファポリゴン）を作ろうとしました。
このとき、エラーは出ませんが、画面に地図をプロットしたときに発生する**「恐ろしい不具合」**について、単位の違い（度 vs メートル）に触れながら説明してください。

<details>
<summary>👉 練習問題 4 の解答と解説を見る</summary>

*   **正解**:
    *   単位が「メートル」ではなく「度」として処理されるため、**地球のサイズ（地球1周は360度）を遥かに超える、半径500度の超巨大な円**が作成され、地図が真っ青（巨大な円で画面全体が埋まる）になってしまう。
*   **解説**:
    *   GeoPandasの `.buffer()` や距離計算といった空間計算は、**「そのデータフレームが今持っている座標系の単位」**を使ってそのまま計算を行います。
    *   世界測地系 WGS84 (EPSG:4326) の単位は「度（Degree）」です。したがって、このまま 500 を指定すると「半径500度」の円を作ろうとしてしまいます。
    *   正しい500メートルの円を描くためには、計算する前に必ず **`df.to_crs(epsg=6677)`**（メートル単位の平面座標系）に投影変換するステップが必要です。これは第8回で詳しく学びます！

</details>

GeoPandasで、世界地図のGeoDataFrame `world` から「アジア大陸の国（`continent == "Asia"`）」だけを条件抽出して、`asia` という新しいデータフレームを作成しました。
