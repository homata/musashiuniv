## 8.1 座標参照系（CRS）の高度な変換 (約30分)

### 全人類が必ず一度ははまる「単位の罠（度 vs メートル）」

前回の授業で、GeoPandasに読み込んだデータの座標系が **「EPSG:4326」** という世界共通の座標系（世界測地系WGS84）であることを学びました。
これは地球を「丸い球体」として捉え、位置を **「経緯度（角度：Degree）」** で表す、GPSでおなじみの非常に便利な座標系です。

しかし、この **「経緯度（EPSG:4326）」のデータが入ったデータフレームに対して、いきなり「ここから半径500メートル以内の円を描いて！」と指示を出すと、プログラムは恐ろしい大暴走を起こします。**

```python
# 🚨 失敗するコード（実行しないでください）
# 世界測地系（経緯度：度）のデータのまま、500mのバッファサークルを作ろうとすると...
gdf_shops.buffer(500) 
```

**【何が起きてしまうのか？】**
GeoPandasは、指示された「500」という数値を、**「今データが持っている座標系の単位」**で解釈します。
*   `EPSG:4326`（世界測地系）の単位は **「度（Degree）」** です。
*   そのため、プログラムは「500メートル」ではなく、**「半径500度」**という、地球（1周360度）を遥かに超えて包み込む、宇宙スケールの超巨大な円ポリゴンを生成しようとします。
*   その結果、地図全体が真っ青なポリゴン（円の残骸）で埋め尽くされ、エラーを吐き出すか、描画が完全にバグってしまいます。

**【解決策（投影変換）】**
距離（メートル）や面積（平方メートル）を計算する、あるいはバッファ円を描く前には、角度である「経緯度」から、**「メートル単位の平面座標系」に変換（投影変換）するステップが絶対必要**です！

```text
  [ 📍 世界測地系: EPSG:4326 ] 角度(度)で表す球体データ（GPS等）
         │
         ▼  to_crs(epsg=6677)  【投影変換（プロジェクション）】
         │
  [ 🗺️ 平面直角座標系: EPSG:6677 ] メートル(m)で表す平面データ（日本国内・関東エリア）
         │
         ▼  .buffer(500)  ※ここで初めて「メートル」での正しい計算が可能になる！
         │
  [ 🟢 半径500mの正しい円ポリゴンの完成 ]
```

### 平面直角座標系（JGD2011）とEPSGコード

日本国内のデータをメートル単位で正確に計算したい場合は、国土地理院が定めた **「平面直角座標系（JGD2011）」** を使います。
狭い日本であっても、丸い球体を平らな紙に投影すると端の方が歪んでしまうため、日本全国を **「19の地域（ゾーン）」** に細かく分割し、それぞれの地域ごとに歪みが最小限になる基準点が設けられています。

| 対象エリア | 座標系名 | 代表的なEPSGコード | 単位 |
| :--- | :--- | :---: | :---: |
| **世界共通（GPS等）** | WGS 84（経緯度） | **`EPSG:4326`** | **度 (Degree)** |
| **関東地方（東京・神奈川等）** | 平面直角座標 第9系 | **`EPSG:6677`** | **メートル (Meter)** |
| **近畿地方（大阪・京都等）** | 平面直角座標 第6系 | **`EPSG:6674`** | **メートル (Meter)** |
| **北海道（中央部）** | 平面直角座標 第12系 | **`EPSG:6680`** | **メートル (Meter)** |

### 💻 ハンズオン①：GeoPandasでの座標参照系（CRS）の変換

実際に、Google Colab上で緯度経度のデータを「メートル単位（EPSG:6677：関東エリア）」に変換してみましょう。

まずは必要なライブラリのインポートと、環境を日本語化する準備を行います。

```python
# ------------------------------------------------------------------
# 準備：日本地図描画に必要なjapanize-matplotlibのインストール
# ------------------------------------------------------------------
!pip install -q japanize-matplotlib geopandas shapely

import pandas as pd
import geopandas as gpd
import matplotlib.pyplot as plt
import japanize_matplotlib
from shapely.geometry import Point

print("準備完了！")
```

次に、武蔵大学（江古田キャンパス）と白山駅の2箇所の緯度経度から地理データフレーム（GeoDataFrame）を作成し、座標参照系（CRS）をメートル単位に変換します。

```python
# 1. 2箇所の緯度・経度データ（通常の辞書データ）
# ※経度（Lng：東経）がX軸、緯度（Lat：北緯）がY軸になるため、Point(経度, 緯度)の順で定義します！
data = {
    "拠点名": ["武蔵大学（江古田）", "白山駅"],
    "経度(Lng)": [139.6732, 139.7523],
    "緯度(Lat)": [35.7371, 35.7215]
}

# Point オブジェクトのリストを作成して geometry に指定します
geometry = [Point(xy) for xy in zip(data["経度(Lng)"], data["緯度(Lat)"])]

# 2. 最初は「世界測地系（経緯度：EPSG:4326）」で地理データフレームを作成
gdf_places = gpd.GeoDataFrame(data, geometry=geometry, crs="EPSG:4326")

print("--- 【変換前】世界測地系 (EPSG:4326) ---")
print("現在の座標系の単位:", gdf_places.crs.axis_info[0].unit_name) # 度(degree)
display(gdf_places)

# 3. .to_crs() を使い、メートル単位の平面直角座標系「第9系（EPSG:6677）」に変換！
gdf_places_meter = gdf_places.to_crs(epsg=6677)

print("\n--- 【変換後】平面直角座標系 (EPSG:6677) ---")
print("現在の座標系の単位:", gdf_places_meter.crs.axis_info[0].unit_name) # メートル(metre)
# geometry 列の値が、度（139.6...）から、超巨大なメートル数値（X: -36715.4... Y: -121303...）に変わったのを確認してください！
display(gdf_places_meter)
```

見事に、経度139.67...という「角度（度）」から、日本の基準点から何メートル離れているかを表す「メートル値（X: -36715.4..., Y: -121303...）」に座標データが変換されました！これで、正確な距離の計算を行う準備が整いました。

## 8.2 商圏バッファ（`.buffer()`）と重心 (約25分)

### スポットの周りに「見えない安全・商業サークル」を描く：`.buffer()`

メートル単位の座標系に変換したデータがあれば、特定のスポットの周りに指定した半径（メートル）の「円（ポリゴン）」を一瞬で描くことができます。これをGISの世界では **「バッファ（Buffer）」** または **「商圏分析（Trade Area Analysis）」** と呼びます。

*   **ビジネスでの用途**：「自社店舗から『半径500m以内』のエリアを赤く塗り、競合店舗と商圏が被っていないか調べる」
*   **防災での用途**：「川（線データ）から『半径100m以内』のエリアを避難勧告の優先対象にする」

バッファを作成するには、GeoDataFrameに対して **`.buffer(半径メートル)`** を実行します。

### 💻 ハンズオン②：500mバッファの作成と地図プロット

先ほど作成した「武蔵大学」と「白山駅」のメートルデータ（`gdf_places_meter`）から、それぞれの「半径500mの円ポリゴン」を作って、地図に重ね合わせてプロットしてみましょう！

```python
# 1. 500mのバッファ（円ポリゴン）を生成！
# ※ CRSがメートル単位（EPSG:6677）なので、引数の「500」は「500メートル」として正しく処理されます。
gdf_places_meter["500m商圏"] = gdf_places_meter.geometry.buffer(500)

print("--- バッファ追加後のデータフレーム ---")
# 「500m商圏」列の中身が「POLYGON（多角形）」に変わっているのを確認してください
display(gdf_places_meter)

# 2. 地図上での描画（Matplotlib）
fig, ax = plt.subplots(figsize=(8, 8))

# 500mバッファ円（ポリゴン）を薄い赤色で描画
# ※GeoDataFrameの「geometry（位置情報列）」をバッファ列に一時的に指定してプロットします
gdf_places_meter.set_geometry("500m商圏").plot(ax=ax, color="red", alpha=0.3, edgecolor="darkred", label="500m商圏")

# 中心点（店舗のピン）を黒い点で重ねて描画
gdf_places_meter.plot(ax=ax, color="black", marker="*", markersize=150, label="店舗位置")

# グラフの装飾
plt.title("武蔵大学と白山駅の半径500m商圏バッファ")
plt.xlabel("X座標 (東方向へのメートル距離)")
plt.ylabel("Y座標 (北方向へのメートル距離)")
plt.grid(True, linestyle=":", alpha=0.6)
plt.show()
```

### ポリゴンの中心を暴き出す：重心（`.centroid`）

広い「公園の敷地ポリゴン」や、複雑な形をした「行政区画（練馬区など）のポリゴン」があります。
これらを「1つのピン（点データ：Point）」として地図にマッピングしたり、代表値として使いたいときは、ポリゴンの **「重心（Centroid：セントロイド）」** を計算します。

GeoPandasでは、**`.centroid`** 属性を呼び出すだけで、複雑な多角形の幾何学的な重心（中心）を全自動で計算して Point データとして返してくれます。

```python
# （体験コード）
# バッファ円（ポリゴン）の重心（中心点）を逆算して確認してみます
gdf_places_meter["重心ポイント"] = gdf_places_meter["500m商圏"].centroid

print("--- 重心ポイントのデータ ---")
print(gdf_places_meter["重心ポイント"]) # 元々の店舗位置Pointと一致する位置がPointとして返されます
```

## 8.3 空間結合（Spatial Join: `.sjoin()`）の魔法 (約25分)

### GPSデータを「行政区画」というバケツに投げ入れる

皆さんがスマートフォンから取得した「GPSの位置情報（緯度経度：Point）」が手元に1万件あるとします。
これを使って、「どのGPSが、何区（豊島区、練馬区、文京区など）の境界線ポリゴンの中に物理的に入っているか」を分類したいとき、どうすればよいでしょうか？

もし手書きでプログラムを書く場合、「各店舗が区のポリゴンの中に含まれているか（`within`）」を、二重のforループで1つずつ交差判定する必要があり、計算に膨大な時間と複雑なコードが必要になります。

これを一瞬で解決するのが、GeoPandasの **「空間結合（Spatial Join：`.sjoin()`）」** という魔法のメソッドです！

**【空間結合（sjoin）のビジュアルイメージ】**
```text
  [ 店舗 Point ] （緯度経度ピン）      [ 区画 Polygon ] （境界線の面）
  📍 店舗A (139.673, 35.737)           ▱ 練馬区
  📍 店舗B (139.752, 35.721)           ▱ 文京区
         │                               │
         ╰────────── gpd.sjoin() ────────╯
                      │
                      ▼ 【全自動で物理的に重なっているエリアを合体！】
  📍 店舗A ──▶ [物理的に内側にある！] ──▶  🏠 練馬区に所属！
  📍 店舗B ──▶ [物理的に内側にある！] ──▶  🏠 文京区に所属！
```

通常のPandasの `pd.merge()` は、共通の「商品ID」や「店舗名」といった**文字列や数値の『テキストキー』**を一致させて合体させました。
一方、GeoPandasの `gpd.sjoin()` は、共通のキーは一切不要で、**「物理的に重なっているかどうか（交差している、内側にあるなど）の『空間キー』」**を基準にして、お互いのデータをガッチャンコします！

### 💻 ハンズオン③：空間結合の実践

実際に、2つの店舗が「豊島区」と「文京区」のどちらのエリアに入っているかを、空間結合を使って判定させてみましょう！

※テスト用に、コードをコピペするだけで即座に動く「簡易的な行政区ポリゴン（ダミー）」をプログラム内で作成して実行します。

```python
import geopandas as gpd
from shapely.geometry import Point, Polygon

# ------------------------------------------------------------------
# 1. 簡易的な「行政区（区画）」のポリゴンデータを作成します（ダミー境界線）
# ------------------------------------------------------------------
# 豊島区簡易エリア（四角形のポリゴン）
poly_toshima = Polygon([
    (139.70, 35.72), (139.73, 35.72), (139.73, 35.74), (139.70, 35.74)
])
# 文京区簡易エリア（四角形のポリゴン）
poly_bunkyo  = Polygon([
    (139.73, 35.71), (139.76, 35.71), (139.76, 35.73), (139.73, 35.73)
])

gdf_districts = gpd.GeoDataFrame({
    "区名": ["豊島区", "文京区"],
    "行政コード": ["13116", "13105"]
}, geometry=[poly_toshima, poly_bunkyo], crs="EPSG:4326")

print("--- 区画（多角形：Polygon）データ ---")
display(gdf_districts)

# ------------------------------------------------------------------
# 2. 店舗の位置（点：Point）データを作成します
# ------------------------------------------------------------------
# 豊島区エリア付近の店舗と、文京区エリア付近の店舗
shop_points = [Point(139.7111, 35.7292), Point(139.7523, 35.7215)]
gdf_shops = gpd.GeoDataFrame({
    "店舗名": ["池袋サンシャイン店", "白山駅前店"]
}, geometry=shop_points, crs="EPSG:4326")

print("\n--- 店舗（点：Point）データ ---")
display(gdf_shops)

# ------------------------------------------------------------------
# 3. 運命の合体！ 空間結合（gpd.sjoin）を実行する！
# ------------------------------------------------------------------
# gpd.sjoin(左のデータ, 右のデータ, how="結合方法", predicate="空間関係の条件")
# predicate="intersects" は、「物理的に一部でも重なっている（交差している）もの」を結合します。
joined_result = gpd.sjoin(gdf_shops, gdf_districts, how="left", predicate="intersects")

print("\n--- 空間結合（自動位置判定）の完了！ ---")
# 各店舗に、共通キーがないにもかかわらず、自動的に正しい「区名」と「行政コード」がマージされているのを確認してください！
display(joined_result[["店舗名", "区名", "行政コード", "geometry"]])
```

共通キーがどこにもないのに、店舗のGPS座標から物理的に重なっているポリゴンを探し出し、見事に「池袋サンシャイン店 ＝ 豊島区」「白山駅前店 ＝ 文京区」と判定されました！

これが、マーケティングで店舗ごとの所属区画を自動分類したり、気象の雨雲ポリゴンとユーザーの位置GPSを合体させて「今、雨が降っているエリアにいるユーザーにだけアプリ通知を送る」といったシステム構築の裏側で使われている技術です。

*   **正解**: **2**
*   **解説**:
    日常会話では「緯度（Y）、経度（X）」の順で言うことが多いため、1番を選びたくなりますが、プログラミングや幾何学の世界では必ず **`(X, Y)`（横軸、縦軸）** の順で座標を扱います。
    *   **X軸（横軸）＝ 経度（Longitude）** ➡ 東西の移動（東京は東経約139度）
    *   **Y軸（縦軸）＝ 緯度（Latitude）** ➡ 南北の移動（東京は北緯約35度）
    
    そのため、必ず **`Point(経度, 緯度)`** の順で記述しなければなりません。逆の `Point(緯度, 経度)` で書いてしまうと、東経35度、北緯139度（北極点の近くの寒冷な海の上）にスカイツリーが吹き飛んでしまいます。

</details>

### 練習問題 2: 座標系の単位のミスマッチ
ある避難所から「半径100m」の避難可能範囲ポリゴンを作ろうと思い、世界測地系（`EPSG:4326`）のデータのまま `gdf.geometry.buffer(100)` を実行したところ、エラーは出ませんでしたが、画面いっぱいに巨大なポリゴンが描画されてしまい失敗しました。この原因として最も適切なものはどれでしょうか？

1.  バッファ関数に渡した「100」という数値が「100マイル」として解釈されたため。
2.  `EPSG:4326` の単位が「度（角度）」であるため、「半径100度（地球1周360度の約3分の1）」という地球規模の巨大な円が作られてしまったから。
3.  GeoPandasの内部でバグが発生し、一時的にメモリが壊れたため。

<details>
<summary>👉 練習問題 2 の解答と解説を見る</summary>

*   **正解**: **2**
*   **解説**:
    GeoPandasの空間演算は、常に「そのデータが今持っている座標系の単位」をそのまま数値に適用します。
    *   `EPSG:4326`（経緯度）の単位は **「度」** です。
    *   そのため、そのままバッファを実行すると「半径100度（地球の直系を網羅するレベル）」の円になり、画面が埋め尽くされます。
    *   これを防ぐには、事前に `.to_crs(epsg=6677)` などでメートル単位の座標系に変換するステップが絶対必要です。

</details>

### 練習問題 3: 空間結合（Spatial Join）の特徴
Pandasでのテーブルの結合（`pd.merge`）と、GeoPandasでの空間結合（`gpd.sjoin`）の決定的な違いについて、説明として正しいものを1つ選んでください。

1.  `pd.merge` はテーブルの大きさが同じでないと結合できないが、`gpd.sjoin` はどのようなテーブルサイズでも結合できる。
2.  `pd.merge` は「店舗ID」や「商品コード」といった共通の『文字キー（テキスト）』を一致させて結合するのに対し、`gpd.sjoin` は共通の文字キーは不要で、「物理的に重なっているか」という『空間の位置関係』をキーにして自動で結合する。
3.  `gpd.sjoin` は、一度結合すると元のデータフレームの列をすべて上書きして消去してしまう特性がある。

<details>
<summary>👉 練習問題 3 の解答と解説を見る</summary>

*   **正解**: **2**
*   **解説**:
    空間結合（Spatial Join）の最大の強みは、**「共通するキーワードの列（マスタのIDなど）がなくても、位置情報さえあれば合体できる」**という点です。
    GPSピンを境界線というバケツに投げ入れるだけで、物理的な重なりを自動判定してマージしてくれます。

</details>

### 練習問題 5: 座標系変換の順番
ある位置データ（`EPSG:4326`）に対して、①メートル単位の平面座標系（`EPSG:6677`）に変換し、②そこから300mのバッファを作成し、③再度Google Mapsなどの背景と重ねるために世界測地系（`EPSG:4326`）に戻す、という一連の処理を行いたいです。
このとき使用する、メソッドの正しい適用順序はどれでしょうか？

1.  `gdf.to_crs(epsg=6677)` ➡ `gdf.geometry.buffer(300)` ➡ `gdf.to_crs(epsg=4326)`
2.  `gdf.geometry.buffer(300)` ➡ `gdf.to_crs(epsg=6677)` ➡ `gdf.to_crs(epsg=4326)`
3.  `gdf.to_crs(epsg=4326)` ➡ `gdf.geometry.buffer(300)` ➡ `gdf.to_crs(epsg=6677)`

<details>
<summary>👉 練習問題 5 の解答と解説を見る</summary>

*   **正解**: **1**
*   **解説**:
    *   まず、最初のデータ（経緯度）をメートル座標系に変換するために **`gdf.to_crs(epsg=6677)`** を実行します（これで単位がメートルになります）。

    *   最後に、この300m円が含まれた地図データを、経緯度で動く他のWeb地図アプリ（次回のfoliumなど）と重ね合わせるために、**`gdf.to_crs(epsg=4326)`** で元の世界測地系に戻してあげます。この「変換 ➡ 処理 ➡ 逆変換」のサンドイッチ構造は、プロのGIS分析における基本のテンプレートです！
