### 練習問題 1: データの尺度と統計指標
「コーヒー(100円), 紅茶(120円), ジュース(150円)」という商品別の「価格」は **( A ) 尺度**であり、その代表値として平均値を計算することに意味があります。一方、「1:非常に満足, 2:満足, 3:普通, 4:不満」というアンケートの評価値は **( B ) 尺度**であり、代表値としては「中央値」や「最頻値」が適しています。
空欄(A)と(B)に入る尺度の名称の組み合わせを答えてください。

<details>
<summary>👉 練習問題 1 の解答と解説を見る</summary>

*   **正解**: **( A ) = 比例（比率）尺度、( B ) = 順序尺度**
*   **解説**:
    *   価格は、0円が「無（お金が存在しない）」を意味し、100円の2倍は200円という「掛け算・割り算（比率）」に意味があるため**比例尺度**です。平均値を計算できます。
    *   満足度アンケートは、1から4の数字に「順序（大小関係）」はありますが、「満足(2)と満足(1)の差が、不満(4)と普通(3)の差と全く等しい」とは言えず、割り算もできないため**順序尺度**です。アンケート結果を単純に「平均2.3」と出すのは厳密には不適切で、中央値（真ん中の人）や最頻値（最も多い回答）で見るのが基本です。

</details>

### 練習問題 2: Pandasの結合（merge）とデータ消失
Pandasで売上履歴データフレーム `df_sales`（1万行）と、商品マスタデータフレーム `df_products`（50件）を、共通の「商品ID」を使って `pd.merge()` で結合しようとしています。
しかし、結合オプションを何も指定せずにマージしたところ、売上履歴が8000行に減ってしまいました。この原因として最も適切なものはどれでしょうか？

1.  結合方式が標準で「外部結合(outer)」になっており、商品マスタに存在しない商品IDの売上が消去されたから。
2.  結合方式が標準で「内部結合(inner)」になっており、商品マスタに登録されていない商品IDの売上が、合致しないため消去されたから。
3.  売上履歴に「重複」があったため、結合時にPandasが自動的に重複をクレンジング（削除）したから。

<details>
<summary>👉 練習問題 2 の解答と解説を見る</summary>

*   **正解**: **2**
*   **解説**: `pd.merge()` のデフォルト（標準）の結合方式は **`how="inner"`（内部結合）** です。これは「両方のデータフレームに共通して存在するキー（商品ID）のみを残す」というお約束です。そのため、売上履歴の中に「まだ商品マスタに登録されていない、お試し新商品のID」などが混ざっていると、合致するものがマスタ側にないため、売上データ自体が丸ごと消去されてしまいます。売上を1行も消したくない場合は、**`how="left"`（左結合＝売上履歴をすべて残し、マスタにない部分はNaNにする）**を指定する必要があります。

</details>

### 練習問題 3: GISの座標系と単位の罠
GeoPandasで、ある店舗から「半径500m」の商圏ポリゴンを `.buffer(500)` で作成しようとしています。
しかし、店舗データのGeoDataFrameの座標系（CRS）が「EPSG:4326（世界測地系・経緯度）」のままで `.buffer(500)` を実行してしまいました。このとき発生する不具合として正しいものはどれでしょうか？

1.  エラーが発生して、プログラムがその場で強制終了する。
2.  エラーは出ないが、単位が「メートル」ではなく「度」として処理されるため、日本（地球）のサイズを遥かに超える巨大な（半径500度の）ポリゴンが生成されてしまう。
3.  プログラムが自動でメートルに変換して処理してくれるため、何の問題もなく正しい500mの円が作られる。

<details>
<summary>👉 練習問題 3 の解答と解説を見る</summary>

*   **正解**: **2**
*   **解説**: これもGIS分析で初心者が最も犯しやすい恐ろしい罠です。GeoPandasの空間演算（`.buffer()` や距離計算など）は、**「そのデータフレームが今持っている座標系の単位」**をそのまま使います。
    *   `EPSG:4326` の単位は **「度（Degree）」** です。
    *   そのため、この状態のまま `.buffer(500)` を実行すると、システムは「半径500度（地球は1周360度なので、地球を何周も包む巨大な円）」を作ろうとしてしまい、地図上が真っ青（巨大ポリゴンで埋まる）になります。
    *   空間演算を行う前には、必ず **`.to_crs(epsg=6677)`**（平面直角座標系などのメートル単位の平面座標系）に変換するステップが絶対必要です！

</details>

### 練習問題 4: 機械学習の「過学習（Overfitting）」
機械学習において、用意したデータすべてをAIの学習用（`.fit`）に使ってモデルを構築し、同じデータを使ってモデルの精度（決定係数など）を測定したところ、100%（完璧）の精度が出ました。
しかし、このAIモデルを実務に導入して「新しくやってきた明日のお客様の売上」を予測させたところ、全く当たらないひどい予測になってしまいました。この現象を何と呼ぶでしょうか？また、これを防ぐための機械学習の黄金のルールは何でしょうか？

<details>
<summary>👉 練習問題 4 の解答と解説を見る</summary>

*   **正解**:
    *   現象名：**過学習（オーバーフィッティング）**
    *   黄金のルール：**学習データ（訓練データ）と、テストデータ（評価データ）の分割（ホールドアウト法）**
*   **解説**:
    *   過去のデータを丸暗記（過学習）したAIは、過去の「たまたま起きたノイズ（その日だけ天気が大荒れだったなど）」まで完璧なルールとして記憶してしまいます。そのため、まだ見ぬ未来（未知のデータ）に対する予測力が極端に低下します（学校のテスト問題と答えを丸暗記したため、応用問題が解けない生徒と同じ状態です）。
    *   これを防ぐため、データをあらかじめ **「学習用（7割〜8割）」** と **「テスト用（2割〜3割）」** に分割し（`train_test_split`）、学習にはテストデータを見せず、評価の時にだけ「実力テスト」として解かせることで、本当の予測実力を測定します。

</details>

### 課題 2: applyとラムダ式による条件付き計算（第3回テーマ）
カフェの営業時間において、**「22時以降（22:00〜）の売上には深夜割増料金として10%（1.1倍）のサービス料を価格に上乗せする」**というルールを自動計算する列を追加したいです。
`apply()` と `lambda`、そして if-else 文を組み合わせて、新しい列「深夜対応価格」を作成してください。
※ヒント：行全体に処理を適用するため、必ず `axis=1` を指定してください。

```python
import pandas as pd

sales_history = pd.DataFrame({
    "商品名": ["コーヒー", "夜カフェラテ", "深夜パフェ", "紅茶"],
    "注文時": [15, 18, 23, 21], # 24時間表記の「時」
    "基本価格": [400, 500, 800, 450]
})

# TODO: apply と lambda を使い、注文時が 22 以上の場合は 基本価格*1.1、そうでない場合は 基本価格 を適用する
# ※ lambda row: row["基本価格"] * 1.1 if row["注文時"] >= 22 else row["基本価格"] の形を使います。
sales_history["深夜対応価格"] = sales_history.apply(
    lambda row: row["基本価格"] * 1.1 if row["注文時"] >= 22 else row["基本価格"],
    axis=1
)

print("--- 深夜料金適用後の売上履歴 ---")
display(sales_history)
```

### 課題 3: 時系列データからの月・曜日抽出とグループ集計（第3回テーマ）
売上の「日付」を表す列がありますが、現在はただの「文字列」になっています。
1.  日付列を `pd.to_datetime()` を使って日付型（datetime）に変換してください。
2.  日付データから、売上があった**「曜日名（日本語：月、火、水…）」**を抽出して「曜日」列を作成してください。
3.  作成した「曜日」列を使ってグループ化（`groupby`）し、曜日ごとの「売上合計」を計算して表示してください。

```python
import pandas as pd

sales_data = pd.DataFrame({
    "日付": ["2026-08-01", "2026-08-02", "2026-08-03", "2026-08-04", "2026-08-05"], # 8/1=土, 8/2=日, 8/3=月, 8/4=火, 8/5=水
    "売上": [12000, 15000, 8000, 9500, 8800]
})

# TODO: 1. 「日付」列をdatetime型に変換する
sales_data["日付"] = pd.to_datetime(sales_data["日付"])

# TODO: 2. .dt.day_name() や、日本語用の曜日名配列へのマッピングを使って曜日名（月〜日）を抽出する
# ※簡単な方法として、.dt.weekday を使うと 0=月, 1=火... 6=日 という数値が得られます。
#   これに日本語曜日の配列をマッピングします。
weekday_names = ["月", "火", "水", "木", "金", "土", "日"]
sales_data["曜日"] = sales_data["日付"].dt.weekday.apply(lambda x: weekday_names[x])

# TODO: 3. 「曜日」列でグループ化し、売上の合計を出す
weekday_sum = sales_data.groupby("曜日")["売上"].sum()

print("曜日変換後のデータ:")
display(sales_data)
print("\n曜日ごとの売上合計:")
print(weekday_sum)
```

### 課題 4: 記述統計（中央値・標準偏差・外れ値の抽出）（第4回テーマ）
カフェの15日間の客数データに、入力ミスで「2000人」というあり得ない巨大な異常値（外れ値）が1件混ざってしまっています。
1.  平均値(`.mean()`)と中央値(`.median()`)の両方を計算し、平均値が外れ値によってどれだけ跳ね上がっているか（中央値の方がいかに実態を表しているか）を確認してください。

3.  「中央値の3倍を超える客数」の日を、Pandasの条件抽出で「外れ値の日」として抜き出してください。

```python
import pandas as pd

visitors = pd.Series([120, 135, 110, 140, 125, 130, 115, 128, 142, 138, 2000, 122, 118, 127, 131]) # 11番目が異常値

# TODO: 1. 平均値と中央値を計算する

med_val = visitors.median()

# TODO: 2. 標準偏差を計算する
```

### 課題 6: GeoDataFrameの作成と座標系(CRS)変換（第7〜8回テーマ）
3つの店舗の「緯度・経度」データがあります。
1.  `geopandas` と `shapely.geometry.Point` を使って、この緯度経度から地理空間データフレーム（GeoDataFrame）を作成してください。
2.  作成したGeoDataFrameの座標系が、最初は「世界測地系（経緯度：EPSG:4326）」であることを定義し、それをメートル単位の平面座標系「JGD2011/9系（関東地域：EPSG:6677）」に `.to_crs()` で変換してください。

```python
import pandas as pd
import geopandas as gpd
from shapely.geometry import Point

# 店舗データ（経度 Lng, 緯度 Lat の順番に注意！）
shop_data = pd.DataFrame({
    "店舗名": ["江古田店", "白山店", "池袋店"],
    "経度(Lng)": [139.6732, 139.7523, 139.7111],
    "緯度(Lat)": [35.7371, 35.7215, 35.7292]
})

# TODO: 1. 経度・緯度から Point オブジェクトのリストを作成し、geometry列にする
# ※ Point(経度, 緯度) の順（X, Yの順）で渡すのが鉄則です！
geometry = [Point(xy) for xy in zip(shop_data["経度(Lng)"], shop_data["緯度(Lat)"])]

# GeoDataFrameの作成 (最初のCRSは EPSG:4326 経緯度)
gdf_shops = gpd.GeoDataFrame(shop_data, geometry=geometry, crs="EPSG:4326")

print("【変換前：世界測地系 (EPSG:4326)】単位は『度』")
print("現在のCRS:", gdf_shops.crs)
display(gdf_shops)

# TODO: 2. メートル単位の座標系「EPSG:6677」に変換する
gdf_shops_meter = gdf_shops.to_crs(epsg=6677)

print("\n【変換後：平面直角座標系 (EPSG:6677)】単位は『メートル』")
print("現在のCRS:", gdf_shops_meter.crs)
# geometryが [Point (X座標, Y座標)] という大きなメートル単位の数値に変わっているのを確認してください！
```

### 課題 7: 空間結合（Spatial Join）による位置判定（第8回テーマ）
空間結合（`gpd.sjoin`）を使うと、「店舗のGPSピン（Point）」が「どの市区町村の境界線（Polygon）」の中に物理的に含まれているかを、プログラムが全自動で交差判定して合体してくれます。
池袋店などの「店舗GeoDataFrame」と、豊島区や文京区の境界線を表す「行政区画GeoDataFrame」を空間結合し、各店舗が何区にあるかを自動判定させてください。

```python
import geopandas as gpd
from shapely.geometry import Point, Polygon

# 1. 簡易的な「行政区（区画）」のポリゴンデータを作成します（ダミー）
# 本来は国土数値情報などのShapefileを読み込みますが、ここではコードだけで完結するダミーです。
poly_toshima = Polygon([(139.70, 35.72), (139.73, 35.72), (139.73, 35.74), (139.70, 35.74)]) # 豊島区簡易エリア
poly_bunkyo  = Polygon([(139.73, 35.71), (139.76, 35.71), (139.76, 35.73), (139.73, 35.73)]) # 文京区簡易エリア

gdf_districts = gpd.GeoDataFrame({
    "区名": ["豊島区", "文京区"]
}, geometry=[poly_toshima, poly_bunkyo], crs="EPSG:4326")

# 2. 店舗Pointデータ
shop_points = [Point(139.7111, 35.7292), Point(139.7523, 35.7215)] # 池袋店（豊島区）、白山店（文京区）
gdf_shops = gpd.GeoDataFrame({
    "店舗名": ["池袋店", "白山店"]
}, geometry=shop_points, crs="EPSG:4326")

print("--- 区画（Polygon）データ ---")
display(gdf_districts)
print("--- 店舗（Point）データ ---")
display(gdf_shops)

# TODO: gpd.sjoin を使って、店舗データ(gdf_shops)に区画データ(gdf_districts)を空間結合してください。
# 引数: left_df=gdf_shops, right_df=gdf_districts, how="left", predicate="within" (あるいはintersects)
joined_result = gpd.sjoin(gdf_shops, gdf_districts, how="left", predicate="intersects")

print("\n--- 空間結合（自動位置判定）の結果 ---")
# 各店舗名に、自動的に正しい「区名」がマージされているのを確認してください！
display(joined_result[["店舗名", "区名", "geometry"]])
```

### 課題 8: scikit-learnによる売上予測（線形回帰AI）（第10回テーマ）
過去のカフェの「客数（説明変数X）」と「売上高（目的変数Y）」のデータがあります。
1.  データを学習用（75%）とテスト用（25%）に分割してください。
2.  `scikit-learn` の `LinearRegression` を定義し、学習用データを使ってAIに学習（`.fit`）させてください。
3.  テストデータを用いて予測（`.predict`）を行い、モデルの賢さを表す「決定係数 \\(R^2\\)」を算出してください。

```python
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LinearRegression
from sklearn.metrics import r2_score

# 過去の客数と売上データ（ダミー）
np.random.seed(42)
X = np.random.randint(50, 200, (100, 1)) # 客数（説明変数：2次元配列にする必要があります）
y = X * 2500 + np.random.normal(0, 30000, 100) # 売上（目的変数：単価約2500円＋ノイズ）

# TODO: 1. データを学習用（train）とテスト用（test）に 75:25 で分割する
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=42)

# TODO: 2. 線形回帰モデルを定義し、学習用データで学習させる
model = LinearRegression()
model.fit(X_train, y_train)

# TODO: 3. テストデータを使って予測値を計算し、決定係数(R2)を算出する
y_pred = model.predict(X_test)
r2 = r2_score(y_test, y_pred)

print(f"モデルの学習が完了しました。")
print(f"客数に対する売上予測式: 売上 ＝ {model.coef_[0]:.1f} × 客数 ＋ {model.intercept_:.1f}")
print(f"テストデータに対する決定係数(R2): {r2:.4f} (1.0に近づくほど超優秀！)")
```

### 課題 9: K-meansによる顧客自動クラスタリング（第11回テーマ）
カフェの常連さん100人について、「年間購入額（X軸）」と「年間来店回数（Y軸）」のデータが記録されています。
`scikit-learn` の `KMeans` を使用して、この顧客たちを特徴に応じて自動的に**「3つのグループ」**にクラスタリング（分類）し、AIが決定した各グループの中心点（重心：セントロイド）の座標を表示してください。

```python
import numpy as np
import pandas as pd
from sklearn.cluster import KMeans

# 顧客データ（年間購入額(千円)と来店回数：ダミー）
np.random.seed(0)
customer_features = np.random.randint(10, 100, (100, 2)) # 100人分

# TODO: K-meansモデルを定義。クラスタ数を「3」に設定する
kmeans = KMeans(n_clusters=3, random_state=42, n_init=10)

# TODO: データをAIに学習させ、各顧客がどのグループ(0,1,2)に属するかを予測（ラベル取得）する
# ※ .fit_predict(データ) メソッドを使うと、学習と予測を同時に行えます。
labels = kmeans.fit_predict(customer_features)

# TODO: AIが決定した3つのグループの「中心点（重心）」の座標を取得する
# ※モデルの .cluster_centers_ 属性に格納されています。
centroids = kmeans.cluster_centers_

print("最初の5人のお客様の自動分類グループ:", labels[:5])
print("\n--- AIが決定した3つのグループの中心点座標（[年間購入額, 来店回数]） ---")
for i, coord in enumerate(centroids):
    print(f"グループ {i} の中心: 購入額 {coord[0]:.1f} 千円 / 来店 {coord[1]:.1f} 回")
```
