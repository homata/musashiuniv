## 9.1 動的地図の革命：その仕組みとライブラリ比較 (約40分)

### 9.1.1 地図に「命（インタラクティブ）」を吹き込むとは？
これまで私たちが描画していたのは、MatplotlibやSeabornによる地図でした。これは「画像ファイル（PNGやJPEG）」です。
論文に印刷して載せるのには最適ですが、Webサイトで一般のユーザーが操作するには不向きです。

現代のWeb地図に求められるのは、以下のような**「対話（インタラクティブ）性」**です。

1.  **直感的なスクロールとズーム**（見たいところへ飛び、拡大する）。
2.  **動的なトッピング（レイヤー）のオン・オフ**（ハザードマップを重ねたり消したりする）。
3.  **クリック時のイベント**（ピンをクリックすると、そこに登録された詳細情報が表示される）。

実は、このような動的地図は、裏側では **「JavaScript（ジャバスクリプト）」** という、Webブラウザを動かすための全く別のプログラミング言語で書かれています。代表的なオープンソースライブラリが **「Leaflet.js（リーフレット・ジェイエス）」** です。

通常、Webで動く地図を開発するには、HTMLを書き、CSSでデザインを整え、何十行ものJavaScriptで地図の初期化やピンの設置を書く必要があり、文系の学生さんにとっては極めて高いハードルでした。

### 9.1.2 PythonからWeb地図への「自動翻訳（コンパイル）」

本日私たちが学ぶ **`folium`** や **`leafmap`** は、この難しいJavaScriptの記述を**「Pythonのコードから自動翻訳（コンパイル）して、手元のブラウザに一瞬で出力してくれる」**という、夢のようなブリッジライブラリです。

**【動的地図自動翻訳のイメージ】**

```text

     <div id="map_xxx"></div>

     </script>
    </body>
   </html>
         │
         ▼ (Google Colabの実行画面にロード！)
  [ 🖥️ ブラウザ上でグリグリ動く本物のデジタルマップ誕生！ ]
```

### 9.2.1 経緯度指定の「鉄則」と、全人類が一度はやる大バグの復習

前回の授業でも学びましたが、大事なことなのでもう一度おさらいします。
日常の会話では「緯度（Latitude）・経度（Longitude）」という順番で口にしますが、プログラミングやGIS（幾何空間）の世界のグラフを思い出してください。

*   **横軸（X軸）** ＝ 経度（東経140度など、左右の動き）
*   **縦軸（Y軸）** ＝ 緯度（北緯35度など、上下の動き）

座標を `(X, Y)` で表す基本ルールがあるため、GeoPandasやShapelyのPointオブジェクトでは **`Point(経度, 緯度)`** の順（経度が先、緯度が後）で指定するのが鉄則でした。

しかし、**`folium` の `location` 引数では、歴史的な背景から `[緯度, 経度]` の順（緯度が先、経度が後）でリストを渡すお約束**になっています！

```text
  【 幾何・GISデータ（GeoPandas等） 】
   geometry = Point( 経度 , 緯度 )  <-- 横(X), 縦(Y) の数学の基本順

  【 Web可視化（folium / Google Maps API 等） 】
   location = [ 緯度 , 経度 ]      <-- 日常生活の「緯度経度」の口頭順
```

*   **デバッグのアドバイス**：「地図を動かしたら画面が真っ白になった、あるいはピンが南極の近くや宇宙空間に消えてしまった！」という時の原因の9割は、この**「経度と緯度の指定順が逆になっていること」**です。エラーは出ないのにピンが表示されないため、最も注意して確認すべきポイントです。

### 9.2.2 ループ処理（`iterrows()`）による全自動マッピング

手動で `folium.Marker` を何個も書くのはスマートではありません。
私たちの手元には、Pandasのデータフレームという強力な表データがあります。
これまでに学んだ、データフレームを1行ずつ上から順番に読み出す **`for idx, row in df.iterrows():`** のループ処理と合体させることで、1万件のデータであっても一瞬で全自動マッピングできます。

```python
# 1. Pandasデータフレームで3つの店舗データを用意（実務を想定したダミーデータ）
import pandas as pd
import folium

shop_df = pd.DataFrame({
    "店舗名": ["江古田コーヒー", "桜台ベーカリー", "練馬スイーツ"],
    "緯度": [35.7368, 35.7382, 35.7351],
    "経度": [139.6705, 139.6631, 139.6542],
    "今日のおすすめ": ["コロンビア浅煎り", "焼きたてクロワッサン", "とろけるプリン"],
    "評価スコア": [4.5, 3.8, 4.8]
})

# 2. 地図の土台を生成
m_shops = folium.Map(location=[35.736, 139.663], zoom_start=14)

# 3. 黄金のループ：iterrows() で1行ずつ位置を取り出してピンを立てる
for idx, row in shop_df.iterrows():
    # 各行の経緯度、店舗名、おすすめ商品を取り出す
    lat = row["緯度"]
    lng = row["経度"]
    name = row["店舗名"]
    recommend = row["今日のおすすめ"]
    
    # マーカーを作成して地図に追加
    folium.Marker(
        location=[lat, lng], # foliumは [緯度, 経度] の順！
        popup=f"{name} (おすすめ: {recommend})", # クリックした時のテキスト
        tooltip=name # マウスを乗せた時（ホバー）に出る簡易テキスト
    ).add_to(m_shops)

m_shops
```

### 9.2.3 HTMLポップアップでデザインされたリッチなUIを作る

`popup` 引数の中に渡す文字は、ただのテキストだけではありません。
実は、**HTMLのソースコードをそのまま文字列として流し込むことができます！**

「改行を入れたい」「太字にしたい」「文字の色を赤にしたい」「ホームページへのリンクを埋め込みたい」といった時、以下のような簡単なHTMLタグを記述することで、一気に実用的なWEBアプリの画面に変貌します。

*   **改行** ➡ `<br>`
*   **太字** ➡ `<b> 太字にしたい文字 </b>`
*   **赤色の文字** ➡ `<span style="color: red;"> 赤くしたい文字 </span>`
*   **ハイパーリンク** ➡ `<a href="URL" target="_blank"> リンクテキスト </a>` （`target="_blank"` をつけると別タブで綺麗に開きます）

実際に、HTMLを使ったリッチなポップアップを実装してみましょう。

```python
m_rich = folium.Map(location=[35.7368, 139.6705], zoom_start=15)

# HTMLコードを文字列として作成します
# Pythonの「トリプルクォーテーション（\"\"\"）」を使うと、改行を含んだ長い文字列を綺麗に書けます。
html_content = """
<div style="font-family: sans-serif; font-size: 13px; width: 220px;">
    <h4 style="margin: 0 0 5px 0; color: #8B4513;">☕ 江古田コーヒー 本店</h4>
    <hr style="margin: 5px 0; border: 0; border-top: 1px solid #ccc;">
    <b>本日のブレンド:</b> <span style="color: green;">キリマンジャロ</span><br>
    <b>本日の混雑状況:</b> <span style="background-color: #ffcccc; padding: 2px 5px; border-radius: 3px;">かなり混雑 🔥</span><br>
    <br>
    <a href="https://www.musashi.ac.jp/" target="_blank" style="color: #1E90FF; text-decoration: none; font-weight: bold;">
        👉 公式サイトをチェックする
    </a>
</div>
"""

# HTMLをfoliumのポップアップオブジェクトに変換（max_widthを指定すると改行が崩れません）
rich_popup = folium.Popup(html_content, max_width=250)

folium.Marker(
    location=[35.7368, 139.6705],
    popup=rich_popup,
    icon=folium.Icon(color="darkblue", icon="coffee", prefix="fa") # font-awesomeのコーヒーアイコンを使用
).add_to(m_rich)

m_rich
```

### 9.2.4 条件分岐によるピンの「自動色分け」と「カスタムアイコン」

「評価スコアが4.5以上の店舗は赤色ピン、それ未満は灰色ピンにする」といった処理を、if文をループに組み込むことで実装します。

また、`folium.Icon` には `color`（ピン自体の色）の他に、ピンの中央に描かれる小さなイラスト（アイコン）を指定できます。
標準で使えるアイコンの他に、**Font Awesome（フォント・アサム）** という世界共通の無料アイコン集のパーツを、`prefix="fa"` というお守りを添えるだけで呼び出せます。

*   `icon="home"` ➡ 家のマーク
*   `icon="shopping-cart"` ➡ カートのマーク
*   `icon="info-sign"` ➡ インフォメーション
*   `icon="coffee", prefix="fa"` ➡ コーヒーカップ
*   `icon="cutlery", prefix="fa"` ➡ フォークとナイフ（レストラン）

```python
# 評価によってピンの色を自動で分けるデモ
m_color_test = folium.Map(location=[35.736, 139.663], zoom_start=14)

for idx, row in shop_df.iterrows():
    lat = row["緯度"]
    lng = row["経度"]
    name = row["店舗名"]
    score = row["評価スコア"]
    
    # 🌟 if-else で条件分岐
    if score >= 4.5:
        pin_color = "red"    # 高評価は赤
        pin_icon = "star"    # 星マーク
    else:
        pin_color = "gray"   # それ以外はグレー
        pin_icon = "thumbs-up" # グッドマーク
        
    folium.Marker(
        location=[lat, lng],
        popup=f"<b>{name}</b><br>スコア: {score}",
```

## 9.3 階級区分図（Choropleth Map）のデータ構築パイプライン (約40分)

### 9.3.1 「形（境界ポリゴン）」と「数字（Pandas）」を合体させる理論
ビジネスのマーケティングや自治体の地域分析で、「どのエリアで売上が高いか」「どこで高齢化が進んでいるか」を一目で把握するために、地域を色の濃淡で塗り分ける手法を**階級区分図（コーロプレス図：Choropleth Map）**と呼びます。

これを作成するには、絶対に**2つの別々のデータ**が必要です。

1.  **境界ポリゴン（地図の形データ：GeoJSON形式など）**
    *   「〇〇区の境界線は、この緯度経度の点々を繋いだ多角形（Polygon）です」という、ただの「形」の情報。
2.  **統計データ（属性情報：PandasのDataFrameなど）**
    *   「〇〇区の今年の売上高は500万円です」「高齢化率は28%です」という、ただの「数字」の表。

この2つを、共通のキーワード（例えば「区名」や「市区町村コード」）を接着剤（キー）にして合体させることで、初めて色分けされた地図が完成します。

**【階級区分図の接着（マージ）構造】**

```text
  [ GeoJSON（地図の形） ]                       [ Pandas DataFrame（統計数字） ]
   feature 1:                                    行 1:
     name: "杉並区"                               店舗: "杉並区"
     geometry: POLYGON((139.6 35.7...))            売上額: 1,200,000 円
   feature 2:                                    行 2:
     name: "練馬区"                               店舗: "練馬区"
     geometry: POLYGON((139.6 35.7...))            売上額:  850,000 円
            │                                              │
            ╰───────  Choropleth( key_on="feature.properties.name" ) ╯
                                      │
                                      ▼ (合体完了！)
  [ 🗺️ 杉並区は「濃い赤」、練馬区は「薄いオレンジ」に自動塗り分けされた動的地図！ ]
```

### 9.3.2 `folium.Choropleth` クラスのパラメータ徹底解読

foliumでこれを行うためのコードは、非常に設定項目（引数）が多く、初心者が最もエラーを起こしやすい難所です。
1行ずつのパラメータの意味を、ここで完全にマスターしましょう。

```python
# （概念コード：授業内で解説します）
# folium.Choropleth(
#     geo_data=geojson_data,               # 1. 地図の「形」データ（GeoJSONファイルなど）
#     data=pandas_df,                     # 2. 塗り分ける「数字」データ（PandasのDataFrame）
#     columns=["区名", "売上額"],           # 3. Pandas側の [接着キーにする列, 色に変換する数字の列]
#     key_on="feature.properties.name",   # 4. GeoJSON（形）側の [接着キーにする項目パス] （※超重要）
#     fill_color="YlOrRd",                # 5. グラデーションの色のパターンを指定（例: 黄色→橙→赤）
#     fill_opacity=0.7,                   # 6. 塗りつぶしの不透明度（0.0=透明 〜 1.0=完全不透明）
#     line_opacity=0.2,                   # 7. 境界線の不透明度
#     legend_name="店舗別売上高（円）"      # 8. 凡例（色の説明バー）のタイトル
# ).add_to(m)
```

### 【超重要】最大の難関 `key_on` の書き方

なぜ `key_on="feature.properties.name"` のように、ドット（`.`）で繋がれた長い文字列を指定するのでしょうか？
それは、GeoJSONという地図ファイルの内部構造（ネストされた辞書型）から、接着剤となる「地域名」を取り出すための**住所（パス）**を指定しているからです。

GeoJSONのファイルの中身は、以下のような構造をしています。

```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "properties": {
        "name": "杉並区",
        "code": "13115"
      },
      "geometry": { "type": "Polygon", "coordinates": [...] }
    }
  ]
}
```

この中から、接着剤として使いたい `"杉並区"`（`"name"`）を取り出すためには、
1.  まず全員に共通する親要素である **`feature`** から出発し、
2.  その中にある **`properties`**（属性グループ）の中に入り、
3.  目的の **`name`** という引き出しを開ける、

というルートを伝える必要があります。これをドットで繋いで **`feature.properties.name`** と書くのが、foliumにおける絶対のルールです。

*   **指導のアドバイス**：「Choroplethを実行したら、地図は出るのに全部黒（またはグレー）に塗りつぶされて、グラデーションにならない！」というエラーの100%は、この `key_on` の指定パスが、GeoJSONファイルの中身とズレていることが原因です。GeoJSONを一度Pandasで読むなどして、propertiesの中にどんなキー名（`"name"` なのか、`"name_local"` なのか、`"N03_004"` なのか）が入っているかを事前に確認する習慣を身につけさせます。

### 9.3.3 色のグラデーション（Color Brewer 2.0 規格）の選び方

`fill_color` に指定する文字列は、何でも良いわけではありません。
統計地図の世界標準カラー規格である **「ColorBrewer 2.0」** に定められたカラーコード（3文字の略称を繋いだもの）を指定します。

*   **`YlOrRd`**：Yellow (黄) ➡ Orange (橙) ➡ Red (赤)。売上高や危険度など、「数字が大きいほど警戒・活発」なデータの可視化に最適。
*   **`YlGnBu`**：Yellow (黄) ➡ Green (緑) ➡ Blue (青)。雨量や水分量、森林率など、自然・環境データの可視化に最適。
*   **`BuPu`**：Blue (青) ➡ Purple (紫)。高級感や、少し落ち着いた分布を示すのに最適。
*   **`RdYlGn`**：Red (赤：悪い/多い) ➡ Yellow (中間) ➡ Green (緑：良い/少ない)。「安全度」や「顧客満足度」など、両極端な評価を表すのに適したカラー。

### 練習問題 4: 「メートル座標系」での空間結合（sjoin）と距離計算（復習）
第8回で、商圏バッファ（`.buffer()`）や距離計算（`.distance()`）を行う前には、GeoDataFrameを世界測地系 `EPSG:4326`（経緯度）から、平面直角座標系 `EPSG:6677`（メートル）などの投影座標系に変換するステップが絶対に必要だと学びました。
では、本日学んだ `folium` や `leafmap` を使って、**「動的地図の上にピンを配置したり、階級区分図を描画する」直前のデータ**は、投影変換した `EPSG:6677` のままで渡してよいでしょうか？ それとも、元の `EPSG:4326` に戻す（あるいは最初から変換しない）必要があるでしょうか？

<details>
<summary>👉 練習問題 4 の解答と解説を見る</summary>

*   **正解**: **元の世界測地系 `EPSG:4326`（経緯度・角度単位）に戻す（あるいは経緯度データのままで渡す）必要がある。**
*   **解説**:
    *   ここが、GeoPandas（加工）とfolium（描画）を組み合わせる際の、最大の頭の整理ポイントです！
    *   `folium` や `leafmap` のWeb地図は、世界基準のGPS座標である **「緯度と経度（角度：WGS84 / EPSG:4326）」でピンの位置や境界線を認識・表示する仕組み** になっています。
    *   そのため、もしメートル平面座標系（`EPSG:6677`）のままで `folium.Marker(location=[X座標(メートル), Y座標(メートル)])` のように巨大な数値（例: -35000, -12000 など）を渡してしまうと、システムは「そんな緯度経度は地球上に存在しない！」とパニックを起こしてエラーになります。
    *   **「計算（バッファや距離）をする時はメートル平面（6677）に変換し、最終的に地図に塗る・撒く（folium可視化）時は、経緯度（4326）に戻す」**という、華麗な往復のパスワーク（データパイプライン）を理解できれば、あなたはもう完全に一人前のGISアナリストです！

</details>

#### Q. 地図上のピンに日本語を表示しようとしたら、文字化け（□□□ のようなトーフ現象）が発生しました。
*   **A.** とても鋭い観察です！これは、Matplotlibなどのグラフ描画時にも発生した「フォントの日本語対応問題」です。
    folium自体は標準でUTF-8に対応しているため、通常のポップアップテキストで文字化けすることはほぼありませんが、もしMatplotlibで描いた日本語の入ったグラフ画像をfoliumのポップアップに埋め込むなどの高度なことをした場合、文字化けすることがあります。
    その場合は、第7回で学んだ **`import japanize_matplotlib`** をコードの最上部で読み込み、グラフを日本語フォント対応にしてから画像出力して地図に埋め込むことで、綺麗に解決できます。

#### Q. CSVファイルから1万件の緯度経度を読み込んで folium でピンを立てたら、ブラウザの動作が極端に重くなり、固まってしまいました。
*   **A.** これは、実務のビッグデータ処理で必ず直面する問題です！
    `folium` は1つずつのピン（Marker）を個別のWeb要素（HTML要素）としてブラウザのメモリ上に展開するため、ピンの数が1000件、1万件と増えるにつれて、ブラウザが処理しきれなくなって悲鳴を上げます（フリーズします）。
    これを解決するためのアプローチは2つあります。
    1.  **ピンをグループにまとめる（クラスタリング）**:
        foliumの拡張モジュールである `MarkerCluster`（`from folium.plugins import MarkerCluster`）を使うと、地図を引いた時は「ここに150件あります」と数字の円でまとめて表示し、ズームインした時だけ個別のピンに自動でばらけるため、劇的に動作が軽くなります。
    2.  **`leafmap` に切り替える**:
        後半で紹介した `leafmap` は、大量の点を描画するための「WebGL」というグラフィック高速化技術と連動しているため、1万件〜10万件のデータであっても、嘘のようにサクサクと一瞬で描画・操作できます。大量データを扱う卒論や実務では、ぜひ `leafmap` に切り替えてみてください。

### 課題 4: leafmapを用いた「ループ処理なし」の高速一括マーカープロット（配点: 20点）

GeoPandasやPandasで大量の位置情報（緯度経度）を扱う際、`folium` の `for` ループで1点ずつマッピングする手法はコードが長く、件数が多いと低速になります。

1.  以下の観光スポットデータフレーム `df_spots` があります。
2.  `leafmap.Map` クラスを使って、東京スカイツリー周辺を中心としたズームレベル **13** の動的地図オブジェクト `leaf_m` を作成してください。

*   **[20点満点]**：コードエラーなく実行でき、東京の城西エリア（杉並区、中野区、練馬区）の3つの巨大な多角形ポリゴンが表示され、混雑度が最も高い「杉並区」が最も濃い赤色、次いで「中野区」が薄いオレンジ、「練馬区」が黄色としてグラデーション色分けされ、上部に凡例バーが表示されれば満点。

*   **[-3点減点]**：`fill_color` のグラデーションカラーの文字列に、指定不可能な綴り（`"RedOrange"` など）を書いてしまい、表示されなかった場合。
